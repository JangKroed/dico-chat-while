# Dico While · 교대 공지

여러 Discord 서버 채널의 웹 입력창에 문구 A와 B를 번갈아 넣어 전송하는 Chrome 확장 프로그램 개발본입니다. Webhook이나 서버 관리자 권한을 사용하지 않습니다. 본인 계정의 해당 채널 메시지 전송 권한은 필요합니다.

**A 전송이 확인된 뒤 중지하면, 다음에 시작할 때 B부터 이어집니다.** 문구와 주기를 수정하거나 팝업을 닫아도 다음 순서는 유지됩니다.

## 0.2.3: 전송용 창 재사용 및 제목·목록 확인

같은 채팅방을 일반 탭에서 다시 연결해도 기존 전송용 창 정보를 보존합니다. 메모리 절약으로 중지된 전송용 탭은 새 창을 만드는 대신 기존 탭을 새로고침합니다. 닫혔거나 다른 채팅방으로 이동한 경우에는 새 전송용 창이 필요합니다. 이전 버전에서 이미 잃어버린 창 연결은 자동 복구하지 않으므로 업데이트 후 최초 한 번은 창이 추가될 수 있습니다.

메시지 원문과 화면 텍스트를 비교할 때 `#`, `##`, `###` 제목과 `-`, `+` 목록의 서식 차이를 처리합니다. 새 메시지 여부·작성자·전송 완료 확인은 계속 적용합니다. 복잡한 Markdown은 여전히 확인 대기로 멈출 수 있습니다. 작성자를 자동으로 알아내지 못하는 경우 설정의 **내 Discord 사용자 ID**를 입력하세요.

이미 발송된 미확인 메시지는 실제 채팅 기록을 확인한 뒤 **전송됨**을 선택하세요. 그러면 다음 A/B 차례로 넘어갑니다. 업데이트는 미확인 결과를 임의로 성공 처리하지 않습니다. 실제 Discord 발송을 통한 수정 확인은 아직 수행하지 않았습니다.

## 0.2.2: 오류 알림

Chrome의 공식 `chrome.notifications`로 이 기기에 오류 알림을 표시합니다. Telegram 토큰이나 Chat ID는 필요하지 않습니다. 팝업을 닫아도 Chrome이 실행 중이면 알림을 요청합니다. 알림에는 채널 설정 이름과 오류 원인만 표시하고 공지 문구는 포함하지 않습니다.

1. 기존 설치 폴더에 새 파일을 덮어쓰고 `chrome://extensions`에서 확장 프로그램을 새로고침합니다. 알림 권한 승인 안내가 나오면 허용합니다.
2. 팝업 또는 설정 페이지를 다시 열고 **모든 채널의 오류 알림 받기**를 켭니다(기본 켜짐, 두 화면에 동기화).
3. **테스트 알림**을 누릅니다. 테스트 버튼은 알림 스위치가 꺼져 있어도 테스트 알림을 요청합니다.
4. 알림이 안 보이면 운영체제의 알림 설정에서 Google Chrome 알림을 허용하고 방해금지·집중 모드를 확인합니다.
5. 오류 알림을 누르면 확장 프로그램 설정 페이지가 열립니다. 해당 채널의 오류와 기록을 확인한 후 재개하세요.

전송 오류·전송 결과 불확실·실행 중 대상 탭 소실 등 저장된 채널 오류가 새로 발생하거나 달라질 때 알립니다. 같은 오류 상태를 계속 저장하거나 확장 프로그램을 재시작해도 반복 알리지 않습니다. 기존 오류가 해제된 뒤 다시 발생하면 다시 알립니다. 단순 설정 입력 오류는 화면에서 안내합니다. 알림 실패는 일정과 A/B 순서를 변경하지 않습니다.

Chrome 종료·기기 절전 중에는 즉시 알림을 보장하지 않습니다. 운영체제의 실제 알림 표시와 실제 Discord 발송은 이번 자동 검사에서 검증하지 않았습니다. [Chrome 공식 알림 API](https://developer.chrome.com/docs/extensions/reference/api/notifications)

## 0.2.1: 채팅방 구분과 입력창 준비 대기

- 같은 서버의 다른 채팅방은 같은 Chrome 탭에서 이동하며 각각 연결할 수 있습니다. 실제 서버 ID와 채팅방 ID가 모두 같은 대상만 중복 차단합니다.
- 시작 시 채널마다 별도 전송용 창을 포커스 전환 없이 엽니다. 기존 전송용 탭은 별도 창으로 옮겨 재사용합니다. 전송용 창은 최소화하지 마세요.
- 페이지 로딩 뒤에도 입력창이 늦게 나타나면 제한된 횟수로 준비 상태를 다시 확인합니다. 입력창이 여러 개이거나 초안이 있으면 중지합니다. 실제 전송은 자동 재시도하지 않습니다.
- 업데이트 시 이전 방식으로 실행 중이던 일정은 중지됩니다. 다시 시작하면 새 창 방식으로 준비하며 A/B 차례와 미확인 전송 상태는 유지합니다.
- Chrome은 비활성 탭의 렌더링과 타이머를 제한합니다. 별도 창은 그 영향을 줄이기 위한 개선이며, 가려지거나 최소화된 창·절전 상태에서 실제 입력까지 보장하지는 않습니다. [Chrome 백그라운드 탭 안내](https://developer.chrome.com/blog/background_tabs/)
- 실제 Discord에서 입력창 DOM이 정상적으로 하나인 것은 읽기 전용으로 확인했습니다. 실제 메시지 발송 성공은 아직 검증하지 않았습니다.

## 0.2.0: 채널별 설정과 화면 동기화

- 초기 채널 설정은 1개이며 **채널 추가**로 늘립니다. 마지막 한 개는 삭제할 수 없습니다.
- 각 설정은 이름, Discord 대상 탭, 문구 A/B, 간격, 다음 순서, 실행 상태, 기록을 독립적으로 저장합니다.
- 팝업과 설정 페이지의 **열린 Discord 탭** 목록에서 대상을 선택해 연결합니다. 팝업에서는 현재 Discord 탭을 바로 연결할 수도 있습니다.
- 대상을 지정하고 시작하면 확장 프로그램이 **채널별 전송용 창을 포커스 전환 없이 자동 생성**합니다. 일반 웹 Discord 탭에서 대화하거나 채널을 이동해도 전송용 탭과 분리됩니다. 재시작 시 전송용 탭을 재사용하며, 닫혔다면 다시 생성합니다. 같은 Discord 채널을 설정 두 개에 중복 연결할 수 없습니다.
- 시작하면 다음 차례의 문구를 바로 입력·전송하고, 성공 확인 시점부터 다음 간격을 계산합니다. 전송용 탭의 로딩 시간은 필요합니다. 각 채널을 개별 시작·중지하거나 **모두 시작 / 모두 종료**할 수 있습니다. 모두 시작은 설정과 연결이 정상인 채널을 시작하고, 시작할 수 없는 채널에는 오류를 표시합니다. 한 채널의 오류로 다른 채널을 중단하지 않습니다.
- 한 채널에서 A를 발송하고 중지하면 그 채널은 다음에 B부터 시작합니다. 다른 채널의 순서에는 영향을 주지 않습니다.
- **설정 저장**을 누르면 다른 화면에도 반영됩니다. 아직 저장하지 않은 입력은 해당 화면의 초안입니다. 같은 채널을 양쪽에서 수정하면 충돌을 표시하며, **최신 설정 불러오기**로 최신 저장값을 확인한 뒤 다시 편집합니다. 오래된 초안으로 새 저장값을 덮어쓸 수 없습니다.
- 기존 단일 채널 설정은 첫 번째 채널로 자동 이전하며 문구·간격·A/B 순서·미확인 전송을 보존합니다. 이전 버전에서 일반 탭으로 실행 중이던 일정은 업데이트 시 중지합니다. 다시 시작하면 새 전송용 탭에서 이어집니다.

업데이트는 **기존 설치 폴더에 파일을 덮어쓴 후** 확장 프로그램과 열린 설정 페이지·Discord 탭을 새로고침하세요. 다른 폴더에 별도로 설치한 확장 프로그램끼리는 저장소가 달라 동기화되지 않습니다. 기존 확장 프로그램을 삭제하면 설정이 사라질 수 있으므로 삭제하지 마세요.

## 0.1.1 업데이트: 입력창에만 문구가 남는 문제

화면 텍스트를 직접 삽입한 직후 Enter를 보내던 방식을 편집기의 붙여넣기 이벤트 처리로 변경했습니다. 선택 영역과 입력 내용이 반영될 시간을 두고, 전송 직전 예약 취소·채널 변경·초안 변경을 다시 확인합니다. 운영체제 클립보드를 읽거나 변경하지 않습니다. [Slate의 공개 편집기 이벤트 구현](https://github.com/ianstormtaylor/slate/blob/main/packages/slate-react/src/components/editable.tsx)을 참고했습니다. Discord에서 사용하는 편집기 버전과 동작은 다를 수 있습니다.

기존 설치 폴더의 파일을 새 파일로 교체한 뒤 `chrome://extensions`에서 확장 프로그램의 새로고침 버튼을 누르고 **Discord 페이지도 새로고침**하세요. 확장 프로그램을 삭제할 필요는 없습니다. 기존 설치 경로를 유지하면 저장된 진행 순서도 유지됩니다.

이전 시도에서 문구가 입력창에만 남아 있다면 실제 채팅 기록에 발송되지 않았는지 먼저 확인하고 초안을 지운 뒤 **초안을 지웠고 전송 안 됨**을 선택합니다. 이후 시작하면 같은 문구부터 다시 시도합니다. 실제로 전송되었다면 **전송됨**을 선택합니다.

비동기 편집기 모의 검사에서 기존 실패와 수정 후 성공을 확인했으며, 실제 Discord에서의 해결 여부는 아직 검증하지 않았습니다.

## 설치

1. Chrome 주소창에서 `chrome://extensions`를 엽니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 눌러 이 프로젝트 폴더(`manifest.json`이 있는 폴더)를 선택합니다.
4. 확장 프로그램 목록에서 **Dico While · 교대 공지**를 고정합니다.
5. 이미 열어 둔 Discord 탭을 새로고침합니다.

빌드나 npm 패키지 설치는 필요하지 않습니다. Chrome 120 이상, `https://discord.com`의 서버 채널을 대상으로 합니다. Discord 데스크톱 앱·DM·다른 Discord 도메인은 지원하지 않습니다.

## 사용

1. Chrome에서 공지를 보낼 Discord 서버 채널을 엽니다.
2. 확장 프로그램 팝업의 **현재 탭 선택**을 누릅니다.
3. 문구 A, 문구 B, 전송 간격을 입력하고 **설정 저장**을 누릅니다.
4. **시작**을 누릅니다. 전송용 탭이 준비되면 다음 문구를 바로 전송하며, 성공을 확인한 뒤부터 설정한 간격을 적용합니다.
5. **중지** 후 다시 **시작**하면 다음 문구부터 이어집니다. 중지 시 이미 입력·발송 처리에 들어간 한 건은 완료될 수 있으며, 성공하면 그 다음 문구가 저장됩니다.
6. 팝업 위 **설정** 또는 Chrome 확장 프로그램의 옵션에서 설정 페이지를 엽니다. 넓은 화면에서 설정·온오프·기록·불확실 전송 확인을 처리할 수 있습니다.

문구는 각각 공백만으로 구성되지 않은 1~2,000자, 간격은 30~86,400초 사이의 정수입니다. 초안 덮어쓰기를 막기 위해 작성 중인 메시지나 첨부파일·답장이 있으면 자동 중지합니다. 전체·역할 멘션(`@everyone`, `@here`, `<@&...>`)은 차단합니다.

대상 채널을 지정하면 실행은 **별도 전송용 탭**에서 진행됩니다. 사용자가 일반 Discord 탭에서 이동하는 것은 실행에 영향을 주지 않습니다. 전송용 탭 자체를 다른 채널로 이동하거나 닫으면 해당 채널만 중지합니다. 닫힌 전송용 탭은 다음 시작 시 다시 생성합니다. 다시 선택해도 A/B 차례는 유지됩니다. 각 설정마다 연결된 탭·채널을 독립적으로 관리합니다.

## 비활성 탭과 복구

- 예약은 페이지 타이머 대신 확장 프로그램의 `chrome.alarms`로 처리합니다. 탭이 일반적인 비활성 상태여도 예약이 동작합니다.
- **Chrome이 완전히 종료되거나 기기가 절전 중일 때는 전송하지 못합니다.** 알람은 정확한 시각을 보장하지 않으며 OS·Chrome 상태에 따라 지연될 수 있습니다.
- 메모리 절약으로 탭이 폐기·동결되거나 로그아웃·채널 권한 변경·입력창 변경이 감지되면 중지합니다. 해당 탭을 다시 열고 상태를 확인한 뒤 재개하세요.
- 절전 뒤 밀린 횟수만큼 몰아서 보내지 않습니다. 다음 예약부터 정상 간격으로 진행합니다.
- Chrome 재시작 시 같은 전송용 탭을 확인할 수 있으면 예약 복구를 시도합니다. 탭 ID가 바뀌거나 페이지가 아직 준비되지 않았으면 중지하며, 시작을 누르면 전송용 탭을 다시 준비합니다. A/B 순서는 계속 보존됩니다.

## 전송 결과가 불확실할 때

전송 직전에 처리 중 상태를 저장합니다. 페이지가 반응하지 않거나 전송 응답이 유실되면 자동 재시도하지 않고 멈춥니다. 재시작 전에 실제 Discord 채널을 확인하세요.

- **전송됨**: 다음 문구로 넘어갑니다. A였다면 B입니다.
- **초안을 지웠고 전송 안 됨**: 남은 입력창 초안을 직접 지운 뒤 선택합니다. 같은 문구 순서를 유지합니다.

확인 버튼 자체는 전송하지 않습니다. 확인 뒤 별도로 시작해야 합니다. 잘못된 수동 확인은 중복이나 누락을 일으킬 수 있습니다.

화면에 새 메시지가 생겼다는 사실만으로 성공 처리하지 않습니다. 최근 메시지인지, 본인 작성자로 식별되는지 또는 로컬 전송 중 상태에서 완료 상태로 바뀌었는지를 확인합니다. 본인 사용자 ID를 선택적으로 입력할 수 있습니다. Discord 사용자 설정 → 고급 → 개발자 모드에서 본인 프로필의 사용자 ID를 복사할 수 있으며 관리자 권한은 필요 없습니다. 기본 프로필 이미지 등으로 작성자 ID를 읽을 수 없고 전송 상태 변화도 확인하지 못하면 보수적으로 멈춥니다.

## 현재 한계와 검증 범위

- **실제 Discord 채널에 메시지를 발송하는 검증은 하지 않았습니다.** 실제 Chrome의 로컬 모의 DOM에서 입력·성공 확인·차단과 UI를 검사했습니다.
- Discord의 공개 전송 API가 아니라 웹 화면과 편집기 이벤트에 의존합니다. Discord가 합성 키 이벤트를 무시하거나 DOM 구조를 바꾸면 전송되지 않거나 확인 대기로 멈출 수 있습니다. 이를 우회하는 토큰 추출·비공개 API 호출은 하지 않습니다.
- v0.1은 일반 텍스트와 일반 URL을 기준으로 합니다. Markdown 서식, 커스텀 이모지, 메시지 렌더링 차이가 있으면 실제 전송되었어도 확인 대기로 멈출 수 있습니다. 명령어·스레드 동시 입력·파일 전송은 대상으로 하지 않습니다.
- 화면 기반 확인은 서버 승인이나 정확히 한 번 전송을 완전히 보장하지 않습니다. 전송 결과가 불명확한 경우 위 수동 확인 절차를 사용합니다.
- 개인 계정 자동화는 Discord의 self-bot 금지 규정에 해당하며 계정 제재 위험이 있습니다. 공지 자동화의 공식적인 대안은 봇 또는 Webhook입니다. [Discord 공식 안내](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots)
- [Chrome 알람 API의 실행·절전 관련 제한](https://developer.chrome.com/docs/extensions/reference/api/alarms)

## 저장과 권한

문구·다음 순서·대상·채널별 최근 30개 기록을 해당 Chrome 프로필의 `chrome.storage.local`에 저장합니다. 외부 서버나 Chrome 동기화에 보내지 않습니다. 확장 프로그램 삭제·데이터 초기화 시 설정과 순서도 삭제됩니다. 로그인 토큰·비밀번호를 읽거나 저장하지 않습니다.

- `notifications`: 오류 및 테스트 알림 표시
- `storage`: 설정과 진행 상태 저장
- `alarms`: 백그라운드 예약
- `activeTab`: 팝업에서 사용자가 선택한 현재 탭 확인
- `scripting`: 설치 전부터 열려 있던 Discord 탭에 입력창 연결 코드 추가
- `https://discord.com/*`: 선택한 Discord 탭의 경로·입력창·전송 결과 확인

## 개발 검증

Node.js 20 이상에서 추가 의존성 없이 실행합니다.

```sh
npm test
npm run check
```

실제 Chrome DOM/UI 검증용 `scripts/browser-check.mjs`는 별도의 임시 프로필과 `127.0.0.1:9333` 디버깅 포트가 필요합니다. 개인 Chrome 프로필로 실행하지 마세요. 검사 탭의 모든 요청을 로컬 응답으로 대체하여 Discord로 발송하지 않습니다.

```sh
node scripts/browser-check.mjs
node scripts/browser-check.mjs --ui
```

파일 구성: `channel-manager.js`(채널별 상태·이전·저장 충돌 관리), `controller.js`(개별 채널 상태·예약), `background.js`(Chrome API 연결), `content.js`(Discord 입력창), `popup.html`·`options.html`·`ui.js`·`styles.css`(설정 화면).

# Dico While · 교대 공지

여러 Discord 서버 채널의 웹 입력창에 문구 A와 B를 번갈아 넣어 전송하는 Chrome 확장 프로그램 개발본입니다. Webhook이나 서버 관리자 권한을 사용하지 않습니다. 본인 계정의 해당 채널 메시지 전송 권한은 필요합니다.

**A 전송이 확인된 뒤 중지하면, 다음에 시작할 때 B부터 이어집니다.** 문구와 주기를 수정하거나 팝업을 닫아도 다음 순서는 유지됩니다.

## 0.2.17: 게시 기록과 남은 A/B 초안을 함께 비교

재확인 시 입력창이 비어 있어야 한다는 조건을 완화했습니다. 본인의 이번 게시가 하나로 확인되면, 남은 초안이 방금 게시된 문구인 경우 다음 예약에서 다음 문구로 교체하고, 이미 다음 차례 문구인 경우 보존해 재사용합니다. 재확인 단계에서는 초안을 삭제하거나 Enter를 누르지 않습니다. 다른 글·A/B가 섞인 초안·첨부·답장 상태는 자동 진행하지 않습니다.

각 전송 직전에도 마지막 전송 확인 이후 본인이 예정 문구를 이미 게시했는지 확인합니다. 확인되면 다시 입력하거나 보내지 않고 차례를 넘깁니다. 초안 재시도 중 뒤늦은 게시를 찾은 경우에도 원래 시도의 문구·시간·본인 작성자와 비교해 자동 복구합니다. 같은 공지가 여러 번 게시됐거나 다음 문구까지 게시되어 순서를 확정할 수 없으면 중지합니다.

비교 대상은 화면에서 읽을 수 있는 게시 기록입니다. 본인 ID 미확인·화면 밖 기록·통신 장애에서는 전체 기록을 완전히 비교할 수 없으므로 중복 방지를 절대 보장하지 않으며, 근거가 불충분한 재확인은 중지를 유지합니다. 기존의 확정 초안 재시도 정책은 유지됩니다.

## 0.2.16: 불확실한 전송의 게시 기록 재확인

전송 응답이 유실되거나 결과가 불확실하면 같은 전송을 반복하지 않고 게시 기록을 최대 3회(2초 간격, 요청별 최대 2초) 읽습니다. 현재 채널에서 본인 작성자 ID·문구·이번 전송 이후 시각이 일치하는 확정 게시가 정확히 하나이고 입력창이 비어 있을 때만 A/B 차례를 넘기고 다음 주기를 예약합니다. 기록 확인 중에는 입력·Enter·새로고침을 하지 않습니다.

본인 ID가 자동 감지되지 않으면 팝업의 내 Discord 사용자 ID를 설정하세요. 작성자 불명·남은 초안·여러 후보·과거 메시지·전송 실패·게시 기록 미로딩은 성공으로 간주하지 않습니다. 근거가 부족하면 기존 미확인 전송을 유지하고 중지합니다. 이미 수동 확인 대기로 중지된 채널은 자동 재개하지 않습니다. 실행 중 확장 프로그램이 중단된 경우에도 저장된 전송 기록으로 읽기 전용 재확인을 수행합니다. 채널별 독립 실행은 유지합니다.

모의 테스트로 검증했으며 상대방 Discord 환경에서의 실제 복구 성공은 별도 확인이 필요합니다.

## 0.2.15: 표시된 슬로우 모드 잔여 시간 대기

입력창 주변에서 지원하는 슬로우 모드 카운트다운(`MM:SS`/`HH:MM:SS`)을 읽으면 입력 전 전송을 미룹니다. Enter 직전에도 다시 확인하며 제한이 남으면 Enter를 보내지 않습니다. 남은 시간에 1.5초 여유를 더해 예약하고, Chrome 알람의 최소 간격을 고려해 최소 30초 뒤 다시 확인합니다. A/B 차례와 채널별 독립 실행은 유지됩니다.

팝업에는 **슬로우 모드 대기**를 표시하고 로그에는 탐지 여부·잔여 시간·다음 예약을 기록합니다. 대기 중 수동으로 게시한 초안은 기존 게시 흔적 확인으로 중복 전송을 막습니다. Discord 화면 구조나 시간 표기가 다르면 자동 감지되지 않을 수 있습니다. 상대방 실환경에서의 감지 및 Enter 문제 해결은 아직 검증하지 못했으며, 슬로우 모드가 꺼지거나 시간이 0이면 기존 전송 경로를 사용합니다.

## 0.2.14: 여러 채널 독립 실행

전체 시작·예약 전송·로딩 복구를 채널별로 독립 실행합니다. 한 채널의 전송 확인이 늦어져도 다른 채널을 기다리게 하지 않습니다. 같은 채널의 작업은 순서를 지키고, 여러 채널의 저장은 짧게 직렬 처리해 설정과 A/B 순서가 덮어써지지 않도록 합니다.

주기는 각 채널의 전송 **확인 완료 시점**부터 다시 계산합니다. 창 준비·Discord 응답·Chrome 예약 지연까지 없어지는 것은 아니며, 여러 채널이 정확히 같은 순간에 게시되는 것을 보장하지 않습니다. Enter 미처리는 별도 문제이므로 남은 문구 확인·재시도·미확인 중지 기준은 유지합니다.

## 0.2.13: 남은 공지를 차례에 맞춰 자동 처리

예약 시점의 초안이 저장된 A/B와 일치하면 자동 처리합니다. 현재 차례의 공지는 다시 붙여넣지 않고 커서를 끝으로 옮겨 Enter를 보내며, 다른 차례 공지는 선택한 내용을 현재 차례로 교체합니다. A/B 이외의 개인 초안과 첨부·답장 상태는 보존하고 중지합니다. 다음 차례는 게시 성공 확인 뒤에만 변경합니다.

전송 관찰 중 새 메시지가 하나도 나타나지 않고 입력창에 현재 공지가 그대로 남았다면, 설정한 간격 후 같은 차례로 최대 3회 추가 시도합니다. 시도 횟수는 저장되어 worker 재시작으로 초기화되지 않습니다. 재시도 전에 이전 시도 이후의 동일 공지 게시 흔적이 보이면 원래 전송의 수동 확인으로 전환합니다. 화면 관찰에는 한계가 있어 중복 가능성을 완전히 배제할 수는 없습니다. 새 게시·전송 중·실패 흔적, 응답 유실, 재시도 한도 초과는 자동 재전송하지 않습니다. 진단에는 `draft-reused`, `draft-replaced`, `draft-retry-scheduled`가 남습니다.

이미 이전 버전에서 중지된 미확인 전송은 이 업데이트로 자동 해제하지 않습니다. 실제 게시 여부를 한 번 확인한 뒤 다시 시작해야 합니다. 현재 공지 유지·다른 공지 교체·개인 초안 보존·차례 유지·재시도 한도·늦은 게시 차단을 모의 환경에서 검증했습니다. 실제 Discord 발송 검증은 아직 수행하지 않았습니다. 확장과 기존 전송용 Discord 페이지를 모두 새로고침하세요.

## 0.2.12: 전송 단계별 진단과 처리 중 표시

예약 시간이 된 뒤 입력하는 기존 동작을 유지합니다. 팝업은 전송 처리 중에 이전 타이머 대신 **입력·전송 확인 중**을 표시합니다. 자동 확인과 사용자 수동 확인은 각각 `delivery-confirmed`, `manual-confirmed`로 구분하며, 미발송 선택은 `manual-not-sent`입니다.

`delivery-trace`는 같은 전송 ID로 수신, 붙여넣기 전후, Enter 직전·직후, 게시 관찰, 완료 단계를 연결합니다. 입력 스크립트 버전, 예약 대비 시작 지연, 단계별 경과 시간, 페이지 숨김·포커스, 입력창 개수·교체·문구 일치 여부, 선택 영역·조합 입력 상태, 이벤트 `defaultPrevented`, 새 메시지·전송 중·실패·작성자·시각 판정 정보를 기록합니다. `defaultPrevented`는 이벤트의 기본 동작 차단 여부이며 서버 전송 성공이나 Discord 처리 성공을 단독으로 증명하지 않습니다. 수신 시 전송 ID와 발신 탭을 확인하고 허용된 숫자·참/거짓 값만 보관합니다. 메시지 원문·채널 주소·사용자 ID·토큰·임의 예외 문자열은 단계별 기록에 포함하지 않습니다.

모의 입력창에서 붙여넣기 성공 후 Enter 무시를 재현하고 잔류·새 게시 없음이 로그에 남는 것을 확인했습니다. 실제 상대방 환경의 원인 확정이나 전송 오류 해결을 의미하지 않습니다. Enter 자동 재시도는 추가하지 않았습니다.

업데이트 후 확장과 **기존 전송용 Discord 페이지도 새로고침**하세요. 이미 남은 초안과 불확실한 발송은 실제 게시 여부를 먼저 확인해야 합니다. 문제 기기에서 오류 직후 진단 로그를 다운로드하면 새 단계별 기록이 포함됩니다. 진단 실패는 전송을 중지하거나 추가 발송하지 않으며, 페이지 종료·통신 단절 시 일부 단계가 누락될 수 있습니다.

## 0.2.11: 설정 웹페이지를 사용 가이드로 전환

팝업 상단의 **사용법** 또는 Chrome 확장 프로그램의 옵션을 열면 첫 채널 연결, 문구·주기 저장, 시작·중지, 채널 추가, 오류 대처, 백업·업데이트, 알림·이메일 안내가 나옵니다. 안내 페이지는 상태 조회나 설정 스크립트 없이 열리며 기존 설정을 변경하지 않습니다. 실제 설정과 실행·로그 다운로드·백업은 팝업에서 진행합니다. 이메일 연결 설정은 팝업 하단의 접힌 **오류 로그 이메일 자동 발송**으로 이동했습니다.

로컬 Chrome 미리보기에서 안내 표시와 도움말 펼치기를 확인했습니다. 설치된 확장 팝업에서 이메일 저장·실제 발송은 수행하지 않았습니다.

## 0.2.10: 닫은 전용 창을 다시 시작할 때 로딩 오인 수정

새 전용 창의 주소가 아직 확정되지 않았을 때 빈 주소를 다른 채널 이동으로 오인하던 문제를 수정했습니다. `pendingUrl`이 지정한 채널이면 준비를 기다리고, 실제 주소와 로딩 완료를 확인한 뒤 입력창 검사를 진행합니다. 로딩 중인 전용 창은 다시 시작해도 재사용합니다. 지연된 탭 변경 이벤트는 현재 탭 상태를 다시 확인하므로, 이미 준비된 창을 오래된 빈 주소·절전 이벤트로 중지하지 않습니다. 실제 다른 채널 이동이나 로그인 화면은 계속 차단합니다.

재현 검사에서 기존 코드의 동일 오류를 확인하고, 수정 후 창 재생성·로딩 대기·창 재사용·오래된 이벤트·실제 이동 차단을 검증했습니다. 이는 Chrome API 상태를 모의한 통합 테스트이며, 수정 버전의 실제 Chrome 창 재생성 및 Discord 발송 검증은 아직 하지 않았습니다. 기존 폴더에 덮어쓰고 확장 프로그램을 새로고침하세요. 설정과 A/B 차례는 유지됩니다.

## 0.2.9: 실제 Discord 제목·목록 텍스트 비교 수정

실제 게시된 메시지 DOM에서 제목과 목록 끝에 `hiddenVisually` 보조 쉼표가 삽입되는 것을 확인했습니다. 메시지 내용 추출 시 이 보조 텍스트를 제외하고 실제 문장 부호와 줄바꿈은 보존합니다. `35~43` 같은 일반 물결표를 지원하지 않는 Markdown으로 오인하던 조건도 수정했습니다. 취소선 `~~` 등 미지원 서식은 여전히 보수적으로 처리합니다.

다른 채널의 시작 작업 때문에 수동 확인 버튼이 잠긴 동안은 대기 이유를 버튼에 표시합니다. 작업이 끝나면 확인 버튼을 사용할 수 있습니다. 기존 미확인 건은 실제 채팅 기록을 확인한 뒤 전송됨을 선택하세요. 실제 DOM 읽기와 회귀 테스트로 텍스트 추출을 확인했으며, 새 자동 발송을 수행하는 검증은 하지 않았습니다.

## 0.2.8: 전송 후 성공 확인 개선

연속 메시지의 작성자를 찾을 때 본문의 제목(h3)을 작성자 헤더로 오인하던 조건을 수정했습니다. 편집기에 문구가 아직 남아 있는 동안에도 새 메시지의 전송 중 상태를 관찰하며, 임시 메시지 ID가 같은 DOM 요소에서 최종 ID로 바뀌어도 연결합니다. 실제 작성자가 다른 것으로 확인되면 성공 처리하지 않습니다.

전송 완료 관찰은 10초에서 25초로 늘렸고, DOM 변경 관찰과 0.5초 간격 읽기 전용 점검을 함께 사용합니다. 오래된 입력창이 교체되면 현재 입력창을 확인합니다. 새 메시지·문구 일치·생성 시각·작성자 또는 로컬 전송 상태·입력창 비움 조건을 유지하며, 기존 메시지나 전송 실패 표시는 성공으로 인정하지 않습니다. 확인 실패 메시지는 내용 불일치·작성자 불명·전송 중·시각 확인 실패 등으로 구분합니다.

전송을 다시 시도하거나 새로고침하지 않습니다. 끝내 확인되지 않으면 실제 게시 여부를 확인해야 합니다. 기존 미확인 건은 자동으로 해제하지 않습니다. 수정 후 기존 설치 폴더에 덮어쓰고 확장 프로그램뿐 아니라 전송용 Discord 탭도 새로고침하세요. 모의 DOM 테스트를 통과했으며 실제 사용자 환경의 발송 확인 성공은 아직 검증하지 않았습니다.

## 0.2.7: 로딩 자동 복구 최대 10회

전송 전 전용 탭의 페이지·입력창·채팅 기록이 준비되지 않으면 기존 탭을 새로고침해 최대 10회 복구를 시도합니다. 각 시도에서 준비 상태를 여러 번 확인하고 성공하면 다음 A/B 차례로 이어갑니다. 팝업에 복구 횟수를 표시하며 진단 로그에는 `loading-recovery`와 단계 코드를 저장합니다. 횟수는 로컬에 저장되어 worker 재시작 때도 이어집니다. 사용자가 다시 시작하면 새 복구 횟수로 시작합니다.

10회 모두 실패하면 최종 오류로 중지하고 기존 오류 알림·연결된 이메일 보고에 반영합니다. 복구 도중 중지할 수 있습니다. 0.2.14부터 전체 시작과 복구는 채널별로 독립 실행하며 한 채널의 복구가 다른 채널을 막지 않습니다.

초안·첨부·복수 입력창·다른 채널 이동·닫힌 탭은 무조건 새로고침하지 않습니다. 특히 입력 후 전송 결과가 불확실한 메시지는 중복을 막기 위해 자동 복구나 재발송하지 않습니다. 실제 전송 결과를 먼저 확인하세요. 실제 Discord 로딩 장애를 일으켜 수행한 검증은 아직 하지 않았습니다.

## 0.2.6: 설정 유지와 백업·복원

업데이트마다 다시 설정할 필요가 없습니다. Chrome의 확장 프로그램 저장소는 설치 ID별로 분리되어 있으므로 ZIP을 새 폴더에 풀어 별도로 등록하면 이전 설정이 보이지 않을 수 있습니다.

1. 기존 확장 프로그램을 삭제하지 마세요.
2. 새 ZIP의 파일을 **기존에 로드한 폴더에 덮어씁니다**. 버전별 폴더를 새로 등록하지 않습니다.
3. `chrome://extensions`에서 해당 확장 프로그램의 새로고침 버튼을 누릅니다.
4. 팝업을 다시 열고 전송용 Discord 페이지도 새로고침합니다. 같은 설치를 유지하면 문구·주기·메일 설정이 그대로 남습니다.

폴더나 PC를 옮길 때는 팝업에서 **설정 백업**으로 JSON을 저장한 뒤 새 설치의 **백업에서 복원**에 넣으세요. 모든 채널의 이름·문구·간격·대상 주소·내 Discord 사용자 ID·다음 A/B 차례를 옮깁니다. 백업에는 공지 문구와 채널 주소가 포함되므로 공개하지 마세요. 메일 URL·연결 키·알림 설정·활동 기록·기존 탭 ID는 포함하지 않습니다. 새 설치의 메일 연결은 따로 등록해야 합니다.

백업·복원 전에 모두 중지하고 미확인 전송을 확인하세요. 복원은 현재 채널 설정 전체를 교체하며 확인창을 표시합니다. 파일 검증에 실패하면 기존 설정을 유지합니다. 복원 후 자동으로 발송하지 않으며, 시작하면 새 전송용 창을 준비합니다. 아직 설정하지 않은 초기 채널도 백업 가능합니다.

## 0.2.5: 이메일 연결과 작업별 오류 진단

팝업 하단의 **오류 로그 이메일 자동 발송**에서 Google Apps Script 웹 앱 URL과 연결 키를 등록합니다. 수신 주소는 `didlsdydgh@gmail.com`으로 고정되어 있습니다. Gmail 비밀번호는 사용하지 않습니다. 팝업 이메일 영역의 **메일 연결 튜토리얼 열기** 또는 `mail-relay/SETUP.html`을 따라 Google 계정에서 최초 배포·권한 승인을 진행하세요. 배포 전에는 자동 메일이 전송되지 않습니다.

사용자가 각 기기에서 동의하고 활성화한 뒤 발생하는 새 오류부터 최근 100개 진단 로그를 약 1분 뒤 모아 발송합니다. 연속 오류는 하나로 합칩니다. 로그는 기기 번호 대신 채널 설정 순번으로 구분하며 공지 문구·채널 주소·사용자 ID는 제외합니다. 연결 키는 로컬 저장소에 저장하며 진단 로그나 ZIP에 넣지 않습니다. 공유 키를 아는 사람은 고정 수신 주소로 메일을 요청할 수 있으므로 안전하게 전달하세요. 서버 전체 하루 20회 한도와 보고서당 1회 시도로 반복 발송을 제한합니다. 실패·응답 유실 시 자동 재시도하지 않고 설정 화면에 표시합니다. 실제 Gmail 배포·메일 수신은 아직 검증하지 않았습니다.

`background.js`의 `queue = next.catch(...)`는 공통 오류 처리 지점입니다. 해당 줄 표시만으로 자동 중지 원인을 판단할 수 없습니다. 이제 작업명과 오류 원문(URL 제외)을 `runtime-error` 진단으로 보관합니다. 설정 저장 충돌처럼 화면에서 안내한 오류도 포함될 수 있습니다. 사용자에게 보이는 오류 안내와 전송 중지 보호는 유지합니다.

## 0.2.4: 자동 중지 진단 로그

팝업의 **진단 로그 다운로드**에서 JSON 파일을 저장합니다. 문제가 발생한 사람의 기기에서 오류 직후 내려받으세요. 최근 500개 기록에 실행 상태 변경, 자동 중지와 오류 원인, 전송 시작·확인, 미확인 전송 존재 여부, 주기·다음 예약·전용 창 여부를 담습니다. 내보낸 파일에는 확장 프로그램 버전과 브라우저 정보도 포함됩니다. 공지 문구, 채널 이름·주소, Discord 사용자 ID, 인증 정보는 수집하지 않습니다.

진단 로그는 해당 기기에만 보관합니다. **이메일 자동 발송은 아직 연결되지 않았습니다.** 요청된 수신 주소는 `didlsdydgh@gmail.com`이며, 발송 서버 또는 메일 발송 서비스 설정이 필요합니다. 현재 버전에서는 다운로드한 로그를 직접 전달해야 합니다. 업데이트 전 발생한 중지 과정은 소급 기록할 수 없습니다.

## 0.2.3: 전송용 창 재사용 및 제목·목록 확인

같은 채팅방을 일반 탭에서 다시 연결해도 기존 전송용 창 정보를 보존합니다. 메모리 절약으로 중지된 전송용 탭은 새 창을 만드는 대신 기존 탭을 새로고침합니다. 닫혔거나 다른 채팅방으로 이동한 경우에는 새 전송용 창이 필요합니다. 이전 버전에서 이미 잃어버린 창 연결은 자동 복구하지 않으므로 업데이트 후 최초 한 번은 창이 추가될 수 있습니다.

메시지 원문과 화면 텍스트를 비교할 때 `#`, `##`, `###` 제목과 `-`, `+` 목록의 서식 차이를 처리합니다. 새 메시지 여부·작성자·전송 완료 확인은 계속 적용합니다. 복잡한 Markdown은 여전히 확인 대기로 멈출 수 있습니다. 작성자를 자동으로 알아내지 못하는 경우 설정의 **내 Discord 사용자 ID**를 입력하세요.

이미 발송된 미확인 메시지는 실제 채팅 기록을 확인한 뒤 **전송됨**을 선택하세요. 그러면 다음 A/B 차례로 넘어갑니다. 업데이트는 미확인 결과를 임의로 성공 처리하지 않습니다. 실제 Discord 발송을 통한 수정 확인은 아직 수행하지 않았습니다.

## 0.2.2: 오류 알림

Chrome의 공식 `chrome.notifications`로 이 기기에 오류 알림을 표시합니다. Telegram 토큰이나 Chat ID는 필요하지 않습니다. 팝업을 닫아도 Chrome이 실행 중이면 알림을 요청합니다. 알림에는 채널 설정 이름과 오류 원인만 표시하고 공지 문구는 포함하지 않습니다.

1. 기존 설치 폴더에 새 파일을 덮어쓰고 `chrome://extensions`에서 확장 프로그램을 새로고침합니다. 알림 권한 승인 안내가 나오면 허용합니다.
2. 팝업을 다시 열고 **모든 채널의 오류 알림 받기**를 켭니다(기본 켜짐).
3. **테스트 알림**을 누릅니다. 테스트 버튼은 알림 스위치가 꺼져 있어도 테스트 알림을 요청합니다.
4. 알림이 안 보이면 운영체제의 알림 설정에서 Google Chrome 알림을 허용하고 방해금지·집중 모드를 확인합니다.
5. 오류 알림을 누르면 사용 가이드가 열립니다. 팝업에서 해당 채널의 오류와 기록을 확인한 후 재개하세요.

전송 오류·전송 결과 불확실·실행 중 대상 탭 소실 등 저장된 채널 오류가 새로 발생하거나 달라질 때 알립니다. 같은 오류 상태를 계속 저장하거나 확장 프로그램을 재시작해도 반복 알리지 않습니다. 기존 오류가 해제된 뒤 다시 발생하면 다시 알립니다. 단순 설정 입력 오류는 화면에서 안내합니다. 알림 실패는 일정과 A/B 순서를 변경하지 않습니다.

Chrome 종료·기기 절전 중에는 즉시 알림을 보장하지 않습니다. 운영체제의 실제 알림 표시와 실제 Discord 발송은 이번 자동 검사에서 검증하지 않았습니다. [Chrome 공식 알림 API](https://developer.chrome.com/docs/extensions/reference/api/notifications)

## 0.2.1: 채팅방 구분과 입력창 준비 대기

- 같은 서버의 다른 채팅방은 같은 Chrome 탭에서 이동하며 각각 연결할 수 있습니다. 실제 서버 ID와 채팅방 ID가 모두 같은 대상만 중복 차단합니다.
- 시작 시 채널마다 별도 전송용 창을 포커스 전환 없이 엽니다. 기존 전송용 탭은 별도 창으로 옮겨 재사용합니다. 전송용 창은 최소화하지 마세요.
- 페이지 로딩 뒤에도 입력창이 늦게 나타나면 제한된 횟수로 준비 상태를 다시 확인합니다. 입력창이 여러 개이거나 초안이 있으면 중지합니다. 실제 전송은 자동 재시도하지 않습니다.
- 업데이트 시 이전 방식으로 실행 중이던 일정은 중지됩니다. 다시 시작하면 새 창 방식으로 준비하며 A/B 차례와 미확인 전송 상태는 유지합니다.
- Chrome은 비활성 탭의 렌더링과 타이머를 제한합니다. 별도 창은 그 영향을 줄이기 위한 개선이며, 가려지거나 최소화된 창·절전 상태에서 실제 입력까지 보장하지는 않습니다. [Chrome 백그라운드 탭 안내](https://developer.chrome.com/blog/background_tabs/)
- 실제 Discord에서 입력창 DOM이 정상적으로 하나인 것은 읽기 전용으로 확인했습니다. 실제 메시지 발송 성공은 아직 검증하지 않았습니다.

## 0.2.0: 채널별 설정과 화면 동기화

- 초기 채널 설정은 1개이며 **채널 추가**로 늘립니다. 마지막 한 개는 삭제할 수 없습니다.
- 각 설정은 이름, Discord 대상 탭, 문구 A/B, 간격, 다음 순서, 실행 상태, 기록을 독립적으로 저장합니다.
- 팝업의 **열린 Discord 탭** 목록에서 대상을 선택해 연결합니다. 팝업에서는 현재 Discord 탭을 바로 연결할 수도 있습니다.
- 대상을 지정하고 시작하면 확장 프로그램이 **채널별 전송용 창을 포커스 전환 없이 자동 생성**합니다. 일반 웹 Discord 탭에서 대화하거나 채널을 이동해도 전송용 탭과 분리됩니다. 재시작 시 전송용 탭을 재사용하며, 닫혔다면 다시 생성합니다. 같은 Discord 채널을 설정 두 개에 중복 연결할 수 없습니다.
- 시작하면 다음 차례의 문구를 바로 입력·전송하고, 성공 확인 시점부터 다음 간격을 계산합니다. 전송용 탭의 로딩 시간은 필요합니다. 각 채널을 개별 시작·중지하거나 **모두 시작 / 모두 종료**할 수 있습니다. 모두 시작은 설정과 연결이 정상인 채널을 시작하고, 시작할 수 없는 채널에는 오류를 표시합니다. 한 채널의 오류로 다른 채널을 중단하지 않습니다.
- 한 채널에서 A를 발송하고 중지하면 그 채널은 다음에 B부터 시작합니다. 다른 채널의 순서에는 영향을 주지 않습니다.
- **설정 저장**을 누르면 다른 화면에도 반영됩니다. 아직 저장하지 않은 입력은 해당 화면의 초안입니다. 같은 채널을 양쪽에서 수정하면 충돌을 표시하며, **최신 설정 불러오기**로 최신 저장값을 확인한 뒤 다시 편집합니다. 오래된 초안으로 새 저장값을 덮어쓸 수 없습니다.
- 기존 단일 채널 설정은 첫 번째 채널로 자동 이전하며 문구·간격·A/B 순서·미확인 전송을 보존합니다. 이전 버전에서 일반 탭으로 실행 중이던 일정은 업데이트 시 중지합니다. 다시 시작하면 새 전송용 탭에서 이어집니다.

업데이트는 **기존 설치 폴더에 파일을 덮어쓴 후** 확장 프로그램과 열린 설정 페이지·Discord 탭을 새로고침하세요. 다른 폴더에 별도로 설치한 확장 프로그램끼리는 저장소가 달라 동기화되지 않습니다. 기존 확장 프로그램을 삭제하면 설정이 사라질 수 있으므로 삭제하지 마세요.

## 0.1.1 업데이트: 입력창에만 문구가 남는 문제

화면 텍스트를 직접 삽입한 직후 Enter를 보내던 방식을 편집기의 붙여넣기 이벤트 처리로 변경했습니다. 선택 영역과 입력 내용이 반영될 시간을 두고, 전송 직전 예약 취소·채널 변경·초안 변경을 다시 확인합니다. 운영체제 클립보드를 읽거나 변경하지 않습니다. [Slate의 공개 편집기 이벤트 구현](https://github.com/ianstormtaylor/slate/blob/main/packages/slate-react/src/components/editable.tsx)을 참고했습니다. Discord에서 사용하는 편집기 버전과 동작은 다를 수 있습니다.

기존 설치 폴더의 파일을 새 파일로 교체한 뒤 `chrome://extensions`에서 확장 프로그램의 새로고침 버튼을 누르고 **Discord 페이지도 새로고침**하세요. 확장 프로그램을 삭제할 필요는 없습니다. 기존 설치 경로를 유지하면 저장된 진행 순서도 유지됩니다.

이전 시도에서 문구가 입력창에만 남아 있다면 실제 채팅 기록에 발송되지 않았는지 먼저 확인하고 초안을 지운 뒤 **초안을 지웠고 전송 안 됨**을 선택합니다. 이후 시작하면 같은 문구부터 다시 시도합니다. 실제로 전송되었다면 **전송됨**을 선택합니다.

비동기 편집기 모의 검사에서 기존 실패와 수정 후 성공을 확인했으며, 실제 Discord에서의 해결 여부는 아직 검증하지 않았습니다.

## 설치

1. Chrome 주소창에서 `chrome://extensions`를 엽니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 눌러 이 프로젝트 폴더(`manifest.json`이 있는 폴더)를 선택합니다.
4. 확장 프로그램 목록에서 **Dico While · 교대 공지**를 고정합니다.
5. 이미 열어 둔 Discord 탭을 새로고침합니다.

빌드나 npm 패키지 설치는 필요하지 않습니다. Chrome 120 이상, `https://discord.com`의 서버 채널을 대상으로 합니다. Discord 데스크톱 앱·DM·다른 Discord 도메인은 지원하지 않습니다.

## 사용

1. Chrome에서 공지를 보낼 Discord 서버 채널을 엽니다.
2. 확장 프로그램 팝업의 **현재 탭 선택**을 누릅니다.
3. 문구 A, 문구 B, 전송 간격을 입력하고 **설정 저장**을 누릅니다.
4. **시작**을 누릅니다. 전송용 탭이 준비되면 다음 문구를 바로 전송하며, 성공을 확인한 뒤부터 설정한 간격을 적용합니다.
5. **중지** 후 다시 **시작**하면 다음 문구부터 이어집니다. 중지 시 이미 입력·발송 처리에 들어간 한 건은 완료될 수 있으며, 성공하면 그 다음 문구가 저장됩니다.
6. 팝업 위 **사용법** 또는 Chrome 확장 프로그램의 옵션에서 튜토리얼을 엽니다. 설정·온오프·기록·불확실 전송 확인은 팝업에서 처리합니다.

문구는 각각 공백만으로 구성되지 않은 1~2,000자, 간격은 30~86,400초 사이의 정수입니다. 초안 덮어쓰기를 막기 위해 작성 중인 메시지나 첨부파일·답장이 있으면 자동 중지합니다. 전체·역할 멘션(`@everyone`, `@here`, `<@&...>`)은 차단합니다.

대상 채널을 지정하면 실행은 **별도 전송용 탭**에서 진행됩니다. 사용자가 일반 Discord 탭에서 이동하는 것은 실행에 영향을 주지 않습니다. 전송용 탭 자체를 다른 채널로 이동하거나 닫으면 해당 채널만 중지합니다. 닫힌 전송용 탭은 다음 시작 시 다시 생성합니다. 다시 선택해도 A/B 차례는 유지됩니다. 각 설정마다 연결된 탭·채널을 독립적으로 관리합니다.

## 비활성 탭과 복구

- 예약은 페이지 타이머 대신 확장 프로그램의 `chrome.alarms`로 처리합니다. 탭이 일반적인 비활성 상태여도 예약이 동작합니다.
- **Chrome이 완전히 종료되거나 기기가 절전 중일 때는 전송하지 못합니다.** 알람은 정확한 시각을 보장하지 않으며 OS·Chrome 상태에 따라 지연될 수 있습니다.
- 메모리 절약으로 탭이 폐기·동결되거나 로그아웃·채널 권한 변경·입력창 변경이 감지되면 중지합니다. 해당 탭을 다시 열고 상태를 확인한 뒤 재개하세요.
- 절전 뒤 밀린 횟수만큼 몰아서 보내지 않습니다. 다음 예약부터 정상 간격으로 진행합니다.
- Chrome 재시작 시 같은 전송용 탭을 확인할 수 있으면 예약 복구를 시도합니다. 탭 ID가 바뀌거나 페이지가 아직 준비되지 않았으면 중지하며, 시작을 누르면 전송용 탭을 다시 준비합니다. A/B 순서는 계속 보존됩니다.

## 전송 결과가 불확실할 때

전송 직전에 처리 중 상태를 저장합니다. 페이지가 반응하지 않거나 전송 응답이 유실되면 자동 재시도하지 않고 멈춥니다. 재시작 전에 실제 Discord 채널을 확인하세요.

- **전송됨**: 다음 문구로 넘어갑니다. A였다면 B입니다.
- **초안을 지웠고 전송 안 됨**: 남은 입력창 초안을 직접 지운 뒤 선택합니다. 같은 문구 순서를 유지합니다.

확인 버튼 자체는 전송하지 않습니다. 확인 뒤 별도로 시작해야 합니다. 잘못된 수동 확인은 중복이나 누락을 일으킬 수 있습니다.

화면에 새 메시지가 생겼다는 사실만으로 성공 처리하지 않습니다. 최근 메시지인지, 본인 작성자로 식별되는지 또는 로컬 전송 중 상태에서 완료 상태로 바뀌었는지를 확인합니다. 본인 사용자 ID를 선택적으로 입력할 수 있습니다. Discord 사용자 설정 → 고급 → 개발자 모드에서 본인 프로필의 사용자 ID를 복사할 수 있으며 관리자 권한은 필요 없습니다. 기본 프로필 이미지 등으로 작성자 ID를 읽을 수 없고 전송 상태 변화도 확인하지 못하면 보수적으로 멈춥니다.

## 현재 한계와 검증 범위

- **실제 Discord 채널에 메시지를 발송하는 검증은 하지 않았습니다.** 실제 Chrome의 로컬 모의 DOM에서 입력·성공 확인·차단과 UI를 검사했습니다.
- Discord의 공개 전송 API가 아니라 웹 화면과 편집기 이벤트에 의존합니다. Discord가 합성 키 이벤트를 무시하거나 DOM 구조를 바꾸면 전송되지 않거나 확인 대기로 멈출 수 있습니다. 이를 우회하는 토큰 추출·비공개 API 호출은 하지 않습니다.
- v0.1은 일반 텍스트와 일반 URL을 기준으로 합니다. Markdown 서식, 커스텀 이모지, 메시지 렌더링 차이가 있으면 실제 전송되었어도 확인 대기로 멈출 수 있습니다. 명령어·스레드 동시 입력·파일 전송은 대상으로 하지 않습니다.
- 화면 기반 확인은 서버 승인이나 정확히 한 번 전송을 완전히 보장하지 않습니다. 전송 결과가 불명확한 경우 위 수동 확인 절차를 사용합니다.
- 개인 계정 자동화는 Discord의 self-bot 금지 규정에 해당하며 계정 제재 위험이 있습니다. 공지 자동화의 공식적인 대안은 봇 또는 Webhook입니다. [Discord 공식 안내](https://support.discord.com/hc/en-us/articles/115002192352-Automated-User-Accounts-Self-Bots)
- [Chrome 알람 API의 실행·절전 관련 제한](https://developer.chrome.com/docs/extensions/reference/api/alarms)

## 저장과 권한

문구·다음 순서·대상·채널별 최근 30개 기록을 해당 Chrome 프로필의 `chrome.storage.local`에 저장합니다. 외부 서버나 Chrome 동기화에 보내지 않습니다. 확장 프로그램 삭제·데이터 초기화 시 설정과 순서도 삭제됩니다. 로그인 토큰·비밀번호를 읽거나 저장하지 않습니다.

- `notifications`: 오류 및 테스트 알림 표시
- `storage`: 설정과 진행 상태 저장
- `alarms`: 백그라운드 예약
- `activeTab`: 팝업에서 사용자가 선택한 현재 탭 확인
- `scripting`: 설치 전부터 열려 있던 Discord 탭에 입력창 연결 코드 추가
- `https://discord.com/*`: 선택한 Discord 탭의 경로·입력창·전송 결과 확인

## 개발 검증

Node.js 20 이상에서 추가 의존성 없이 실행합니다.

```sh
npm test
npm run check
```

실제 Chrome DOM/UI 검증용 `scripts/browser-check.mjs`는 별도의 임시 프로필과 `127.0.0.1:9333` 디버깅 포트가 필요합니다. 개인 Chrome 프로필로 실행하지 마세요. 검사 탭의 모든 요청을 로컬 응답으로 대체하여 Discord로 발송하지 않습니다.

```sh
node scripts/browser-check.mjs
node scripts/browser-check.mjs --ui
```

파일 구성: `channel-manager.js`(채널별 상태·이전·저장 충돌 관리), `controller.js`(개별 채널 상태·예약), `background.js`(Chrome API 연결), `content.js`(Discord 입력창), `popup.html`·`options.html`·`ui.js`·`styles.css`(설정 화면).

# 업데이트 롤백 구현 계획

사용자 요청: 업데이트한 프로그램을 기존 설정 화면에서 이전 정상 버전으로 되돌린다. 사용자가 파일을 다운로드하거나 폴더를 직접 교체하지 않는다.

## 설계 선택

최근 정상 버전 한 개의 프로그램/확장 파일을 로컬에 보관한다. 임의 버전 다운로드 방식은 네트워크와 과거 데이터 호환성에 의존하므로 사용하지 않는다. 데이터베이스를 과거 시점으로 복구하면 설정과 실행 기록이 사라질 수 있으므로 코드만 복원하고 현재 데이터는 유지한다. 대상 코드가 현재 데이터와 호환되는지 검증할 수 없는 경우 실행하지 않는다.

## 구현 순서

1. 업데이트 성공 후 이전 코드 보관 및 무결성/확장 ID 검증을 추가한다.
2. 기존 독립 작업자, 단일 업데이트 잠금, 최종 중단 확인, 종료 확인, 재시작 검증을 재사용한다. 롤백 실패 시 현재 버전 복원을 시도하되 살아 있는 프로세스의 파일은 바꾸지 않는다.
3. 인증된 UI+CSRF POST /api/updates/rollback을 추가한다. 사용자 경로/버전 입력을 받지 않는다.
4. 상태 응답에 복원 가능 여부·버전·불가 이유를 노출하고 실제 파일 경로나 토큰은 숨긴다.
5. 설정 화면에 복원 대상과 버튼을 추가하며 중복 요청과 진행 중 작업을 막는다. 같은 탭으로 재연결하며 그룹을 자동 재개하지 않는다.
6. 정상 복원, 파일 손상/경로 변조, 미보관, 동시 요청, 상태 경합, 부분 교체 실패, 재시작 실패, 데이터 보존을 회귀 검증한다.
7. 전체 테스트·빌드·실제 브라우저 확인 후 기존 main 기반 업데이트 경로에 반영한다.

## 최초 도입 제한

이전 버전 작업자는 새 프로그램의 HTTP 준비 확인 이후 백업을 삭제한다. 새 프로그램은 HTTP 준비 응답 이전에 인증된 진행 작업의 직전 파일을 제한된 시간·크기 안에서 검증해 보관한다. 이 전환 보관에 실패하거나 이미 삭제된 과거 파일은 복원 가능으로 표시하지 않는다. 지원 버전의 업데이트 과정에서 안전하게 보관된 복원본만 노출한다. 사용자 기기의 실제 롤백이나 Discord 발송은 이번 구현 검증에 포함하지 않는다.

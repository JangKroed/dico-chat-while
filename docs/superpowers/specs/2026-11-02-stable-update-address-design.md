# 업데이트 주소와 기존 탭 유지 0.4.4

## 요구

업데이트마다 임의 포트가 바뀌고 새 관리 창이 열리는 불편을 제거한다. 설치별 주소를 유지하고 기존 인증 탭이 같은 주소에서 다시 연결되어야 한다.

## 선택한 방법

고정 기본 포트와 설치별 포트 기록을 사용한다. 새 설치 기본은43127이고 기존 설치는 현재 포트를 기록해 재사용한다. 임의 포트 재배정·매번 새 브라우저 열기는 제거한다. 별도 프록시/고정 리다이렉트 서버는 프로세스·설치를 추가하므로 사용하지 않는다. 포트 충돌 시 다른 주소로 조용히 이동하지 않고 실패 원인을 안내한다. 테스트의 명시 port:0은 임시 포트로 격리한다.

업데이트 worker는 일반 재시작에서 --open을 사용하지 않는다. 기존 UI 세션은 동일 origin의 현재12시간 정책 안에서만 개인 저장 파일에 보존한다. 세션ID·CSRF·만료시각의 형태와 개수/크기, 파일0600·UID·심볼릭 링크를 검사하고 만료·다른origin을 재사용하지 않는다. 기존 Origin/Host/CSRF·브리지 인증은 유지한다. close의 메모리 정리가 저장본을 지우지 않도록 한다.

UI는 서버 중지 후 순차적·제한적 재시도로 세션과 새 CSRF를 확인하고 snapshot/SSE를 복구한다. 새 앱 버전은 /api/session appVersion으로 확인한다. 업데이트를 실행한 설정 화면은 같은 탭에서 새 UI를 반영하고, 다른 편집 화면은 초안을 보존하며 같은탭 갱신 안내를 제공한다. 인증 만료는 자동 우회하지 않는다.

구버전0.4.3 이전은 세션을 저장하지 않았으므로 최초 전환 시 기존 메모리 인증을 되살릴 수 없다. 이 한 번의 이전은 명확히 안내하고 이후 업데이트를 같은 탭으로 유지한다. 실제 사용자 서비스·OS설정은 개발 중 변경하지 않는다. 확장0.4.2의 파일은 바꾸지 않는다.

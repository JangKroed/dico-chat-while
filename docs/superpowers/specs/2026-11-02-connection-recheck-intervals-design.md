# 연결 재검사와 발송 주기 0.4.3

## 사용자 요구

실제 연결이 복구됐어도 OPEN_CHANNEL 거절 알림을 재검사로 해결하지 못하는 문제를 고친다. 현재 저장 설정에 따른 실제 순서를 설명한다. 계정·채널별 기본 주기는 감지된 슬로우 모드+3초로 자동 고정하고 직접 설정은 그 이상만 허용한다.

## 설계

OPEN_CHANNEL 재검사는 원 명령의 브라우저·계정·서버·채널 전체가 같은 연결만 인정한다. 현재 세션의 verified 증거, 최신 heartbeat, 실패 이후 observedAt을 모두 요구한다. 계정 등록만 있거나 다른 채널·다른 브라우저, 오래된 증거면 남겨 둔다. 성공하면 connection_reverified로 과거 알림만 해결하며 발송 결과나 그룹 상태를 바꾸지 않는다.

주기는 auto/custom 모드로 구분한다. 최소값은 마지막으로 알려진 슬로우 모드+3000ms, 미감지는 기준 3000ms이되 UI에 감지 대기로 표시한다. 자동은 최소값을 따르고, 사용자 설정값은 customIntervalMs에 보존한다. 실제 intervalMs는 max(사용자값,최소값)이다. 새 custom 설정이 최소 미만이면 거부한다. 슬로우 모드 변화에 따른 실제 주기 변경은 CONFIG_SYNC하며 진행·미확인 시도가 있으면 터미널 이후로 구성 동기화를 미룬다.

기존 주기가 최소값 이하이면 자동으로 이전하고, 그보다 길면 기존 의도를 custom으로 유지한다. 실제 운영 설치·DB·설정은 개발 과정에서 변경하지 않는다. 새 그룹 UI 기본값은 20초 대신1초이며 기존그룹값은 그대로다. 앱0.4.3만 변경하고 확장0.4.2는 유지한다.

대안으로 알림 강제 숨기기와 UI에서만 최소값 제한을 고려했으나, 현재 증거 검증 및 서버 저장 검증을 선택한다. 중복·오발송 방지와 기존 설정 의도를 보존하기 위해서다.

# 중앙 업데이트 자동화

목표는 이미 승인된 설정 자동화 범위에서 중앙 페이지 한 번의 업데이트 실행으로 준비·검사·적용·재시작을 처리하는 것이다. 스토어 비용·전역 설정 변경 없이 현재 macOS/Windows 구조를 유지한다.

대안: 기존 클론 git pull은 작업 파일 충돌과 반복 명령이 남는다. 스토어 배포는 현재 비용 조건과 맞지 않는다. 선택은 고정 저장소의 별도 체크아웃에서 준비하는 로컬 업데이트다.

인증된 중앙 페이지가 업데이트를 요청하면 고정 GitHub 저장소 main을 격리된 작업 폴더로 받고 빌드·검사를 완료한다. 실행·미확인·제어 대기 상태에서는 적용하지 않는다. 관리 설치 위치만 갱신하고 사용자 DB·기존 클론·브라우저 프로필을 보존한다. Windows의 실행 파일 잠금 때문에 기존 Node·런처 바이너리는 교체하지 않고 JS 디렉터리만 교체한다. 바이너리 업그레이드가 필요한 릴리스는 명시적인 전체 설치 대상이다.

확장은 빌드 시 고정된 build ID를 실행 증거로 사용한다. 네이티브 호스트가 설치된 확장 파일의 실제 해시와 비교하고, 중앙과 로컬이 모두 안전한 상태에서만 chrome.runtime.reload()를 수행한다. 같은 목표에 대한 재시도는 제한하여 잘못된 로드 경로에서 무한 재시작을 방지한다. 동일 빌드라면 재로드하지 않는다. 관리 확장 경로는 기존 문서의 app/extension을 유지한다. 다른 폴더를 로드한 경우 최초 한 번 관리 경로를 선택해야 한다.

콘텐츠 스크립트는 교체 가능한 수명 관리와 버전 응답을 추가하고 안전한 탭에서만 다시 주입한다. 작성 중 초안을 삭제하거나 실제 Discord 메시지를 보내지 않는다. 구버전 콘텐츠는 최초 한 번 페이지 새로고침이 필요할 수 있다. 업데이트 후 그룹을 자동 재개하지 않는다.

실패 시 원인과 다음 단계를 표시한다. 새 프로그램의 정상 확인 전 이전 프로그램 파일을 보존한다. 외부 updater와 사설 작업 토큰으로 UI 세션 종료를 넘겨 처리하며 공개 다운로드 URL·임의 셸 명령을 UI 입력으로 받지 않는다.

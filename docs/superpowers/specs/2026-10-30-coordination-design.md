# 브라우저 간 순환 발송

사용자가 선택한 중앙 조정기 방식으로 A → B → C 순서를 공유한다. 브라우저별 오프셋은 장기 순서를 보장하지 못하므로 사용하지 않는다. 기존 비연동 채널의 동작은 유지한다.

조정기는 Node.js 20 이상 내장 HTTP/fs 모듈로 실행한다. 설치 부담을 줄이기 위해 SQLite 대신 원자적 파일 교체와 fsync로 상태를 보관한다(Windows는 디렉터리 fsync를 지원하지 않아 파일 fsync만 수행). 단일 프로세스만 상태 폴더를 사용하며 잠금 파일로 중복 실행을 막는다. 기본 주소는 127.0.0.1:43127이다. 기본 상태 폴더는 자동 업데이트 교체 대상이 아닌 홈 폴더의 .dico-coordinator이다. 네트워크 배포/자동 시작 설치는 이번 로컬 구현 범위에 포함하지 않는다.

그룹은 서버 설정에서 순서가 있는 Discord 사용자 ID 목록, 동일한 대상 채널, 게시 확인 이후의 간격을 지정한다. 각 멤버는 최초 연결한 브라우저·채널 설정의 고유 clientId에 바인딩된다. 확장에서는 조정기 URL, 토큰, 그룹, 사용자 ID를 저장한다. 토큰은 진단/설정 백업에서 제외한다. 선택한 서버 origin만 브라우저 권한을 요청한다.

발송 intent를 로컬에 저장한 뒤 현재 차례의 멤버만 일회용 허가를 받는다. 서버는 허가를 디스크에 저장한 후 응답한다. 게시 확인 후 완료 보고를 저장해야 차례가 넘어간다. 허가 자동 만료/재발급/구성원 건너뛰기는 없다. 재시작해도 진행 중 허가는 유지된다. 요청 또는 발송 응답 유실은 pending을 보존하고 중지한다. 동일 ID의 완료 보고는 멱등 처리한다. 미발송 수동 확인은 차례를 유지하며 허가를 닫는다. 사용자 수동 확인 전에는 기존 브라우저의 지연 발송이 끝났는지 확인해야 한다.

연동 채널은 게시 확인을 생략할 수 없고 Discord 사용자 ID가 필요하다. 각 계정의 최소 주기·슬로우 모드와 그룹 간격을 모두 존중한다. 늦어진 멤버 때문에 그룹이 멈추거나 간격이 길어질 수 있다. 다른 멤버의 준비/네트워크 지연이 순서를 추월하게 해서는 안 된다.

검증: 순환, 간격, 중복/동시 요청, 허가 응답 유실, 완료 응답 유실, 재시작, 손상 파일/저장 실패, 다른 브라우저의 같은 멤버 점유, 다른 채널, 권한/인증, 설정 수정/백업, 기존 전체 테스트와 배포 ZIP 포함 검사. 실제 Discord 발송은 실행하지 않는다.

# 관리 프로그램 이전 버전으로 되돌리기 (0.4.35)

## 기존 문제

기존 worker는 업데이트한 프로그램의 재시작을 확인한 뒤 작업 폴더의 `previous`를 삭제했다. 실패 직후의 자동 복원만 지원했으며 성공한 업데이트를 나중에 되돌릴 코드가 남지 않았다.

## 보관과 공개 계약

정상 시작이 확인되면 직전 코드의 `central`과 `extension`만 설치별 고정 `updates/rollback` 슬롯에 보관한다. 전체 파일 경로·길이·내용의 SHA-256과 관리 프로그램 버전·확장 고정 키를 함께 기록하며, 읽기 및 교체 전에 다시 검증한다. 심볼릭 링크·특수 파일·지나치게 큰 트리는 거절한다. 임의 복원 경로는 API로 받지 않는다. 같은 버전 재업데이트는 기존의 다른 버전 슬롯을 덮어쓰지 않는다. 새 슬롯은 staging에 준비한 뒤 교체한다. 보관 실패 시 작업 폴더의 이전본을 지우지 않고 unavailable 상태로 표시한다.

`createUpdateController().rollback()`은 이전 코드로 되돌리는 작업을 시작한다. `status()`에는 `mode: update | rollback`과 `rollback: {available, version?, reason?}`이 포함된다. 이유 코드는 `NO_BACKUP`, `BACKUP_INVALID`, `ROLLBACK_INCOMPATIBLE`, `SAME_VERSION`이다. version은 보관된 대상 버전이며 로컬 경로·토큰·원시 오류는 공개하지 않는다. 성공적으로 되돌린 뒤에는 바로 전 코드가 다음 되돌리기 대상으로 보관된다.

## 데이터와 실행 안전성

되돌리기는 네트워크 다운로드·Git·npm 없이 보관된 코드만 사용한다. 관리 프로그램 업데이트와 동일하게 모든 그룹 중지/일시정지, 진행·미확인 시도 없음, 미완료 제어 의도 없음 조건을 검사한다. 준비 완료 후 전용 작업 토큰으로 다시 승인하고, 기존 프로세스 종료 확인 및 동일 OS 잠금 안에서 코드만 교체한다. 데이터베이스·설정·로그·전송함은 교체 대상이 아니다.

대상 구버전은 현재 SQLite의 일관된 임시 복제본에서 별도 Node 프로세스로 실제 시작하여 읽기 호환성을 검사한다. schemaVersion 숫자가 같다는 이유만으로 통과시키지 않는다. 재시작에 필요한 세션·연결 상태와 대기 명령 폐기 등 명시된 변화 외에 기존 설정·메시지·확정 결과·자원 잠금·과거 이벤트·대기 이력의 삭제나 변경을 거부한다. 임시 파일은 검사 후 제거하며 실제 DB에는 쓰지 않는다. 종료 후 최종 교체 직전에 파일 해시와 데이터 호환성을 다시 검사한다. 보수적인 검사이므로 구버전이 실행 가능하더라도 현재 자료를 보존하지 못하면 되돌리기는 중단된다.

구버전 시작에 실패했을 때 그 프로세스가 종료됐다는 증거가 있는 경우에만 현재 버전 코드로 자동 복원한다. 종료 여부를 확정하지 못하면 실행 중일 수 있는 파일을 다시 덮어쓰지 않고 양쪽 코드를 보존한다.

## 0.4.34에서 최초 진입

구 worker가 새 프로그램의 health 응답을 기다린 뒤 `previous`를 삭제한다는 순서를 이용한다. 새 프로그램은 HTTP를 열기 전에 활성 작업의 private job token, 작업 ID/정규 경로, 살아 있는 worker, applying 단계, 확장 신원을 확인한 다음 이전 코드를 새 슬롯에 캡처한다. 32MiB 상한과 파일 작업 사이의 8초 검사 예산으로 정상 시작 대기를 제한한다. 이미 제거된 과거 버전을 네트워크에서 추측 복원하지 않는다. 파일 접근 제한·시간 초과 등으로 캡처하지 못해도 프로그램 시작을 막지 않고 보관본 없음으로 표시한다. 따라서 이전본이 남아 정상 검증되는 0.4.34→0.4.35 앱 내 업데이트부터 보관할 수 있으며, 모든 기기에서의 캡처 성공을 보장하지는 않는다.

## 검증

기능 부재/기존 결함을 회귀 테스트로 먼저 실패시킨 뒤 구현했다. 코드 보관·동일 버전 보존·변조/심볼릭 링크 거부·오프라인 실행·토큰 계약·시작 실패 복원·종료 미확인 시 덮어쓰기 금지·구 worker의 삭제 전 캡처와 잘못된 토큰 거부를 검증했다. 별도 데이터 QA는 같은 schemaVersion에서도 메시지·설정·이벤트·확정 결과·잠금·닫힌 대기 이력을 변경하는 구버전을 거절하고, 실제 현재 core의 정상 시작은 허용함을 확인했다. 신규·독립 QA·기존 업데이트 관련 41개 테스트가 통과했다. 실제 사용자 설치에는 테스트용 롤백을 실행하지 않았다.

통합 검증: 전체 1,170개 테스트 통과(실패·건너뜀 0), TypeScript/Vite 빌드·구문/manifest/CSP·React SSR 검사 통과. 실제 격리 Chrome에서 롤백 요청·중복 클릭 차단·같은 탭 유지 및 1440/1000/390px 화면을 확인했다. 실제 설치의 코드 교체는 임시 환경에서 검증하고 사용자 설치에는 실행하지 않았다.

사용 위치: 설정 · 도움말 → 프로그램 · 확장 업데이트 → 이전 버전으로 되돌리기. 보관된 버전과 불가 이유를 표시하며 실행 중에는 중복 실행을 막는다.

# 제보 용량과 이메일 미수신 조사 (0.4.27)

2026-11-03 상대방이 용량 제한으로 전체 제보를 만들지 못했고, 기간을 줄여 보냈으나 관리자 메일이 없다는 보고가 들어왔다. 스크린샷에는 Brave/Chrome 두 그룹의 발송 복구 대기가 보이며 버전·reasonCode·제보 ID는 보이지 않는다. 이 화면만으로 발송 중단 원인은 확정할 수 없다.

## 확인 사실

- Gmail 전체(스팸·휴지통 포함) 조회에서 상대방 제보를 찾지 못했다.
- 같은 공개 이메일 중계에 합성 제보 647345fd-f222-42d9-9441-d4b918d70566을 보내 접수 응답 및 Gmail INBOX의 JSON 첨부(1990바이트)를 확인했다. 실제 사용자 로그는 포함하지 않았다. 중계는 검사 시점에 동작했다.
- 기존 보고서는 16MiB 초과 시 오류였다. 기간을 좁혀도 오래된 미해결 시도 관련 로그를 수집하므로 크기가 계속 클 수 있다.
- 수동 전송 API는202대기열등록을 반환한다. 기존 창은 이후 실제 접수·실패 상태를 직접 갱신하지 않았다. 상대방 제보가 중계까지 도달했는지는 현재 자료로 확인할 수 없다.

## 수정

- 원본 로그를 삭제하지 않고 제보 사본만 자동으로 제한한다. DB이벤트는 일반 사건과 반복 trace에 별도 예산을 두어 반복 로그가 중요 사건을 전부 밀어내지 않게 한다.
- 보고서는 배열별 바이트/개수 예산과 최종4MiB미만·트리노드 제한을 적용한다. 미해결·진행중 시도와 그룹 activeAttemptId를 정상 완료 이력보다 우선 보존한다.
- selection.omittedCounts와 REPORT_COMPACTED 경고에 제외 건수를 명시하고, 검사·개인정보 필터링을 거쳐 이메일에 포함되어도 유지한다. 전체 로그가 전송됐다고 표시하지 않는다.
- 수신 주소/키가 없는 수동 전송은 바로 알린다. 제보 창에서2초간격으로 실제 큐 상태를 갱신하고 제보ID·접수번호·실패사유를 표시한다. 전송 대기를 접수 완료로 표시하지 않는다.
- 중계 UNAUTHORIZED·QUOTA·DELIVERY_UNCERTAIN·BUSY·INVALID를 구분한다. 성공 접수 검증과 동일ID재시도는 그대로 유지한다. Google 코드 재배포는 필요 없다.

## 검증

54MB급 발송 본문 데이터 및18MB이상 DB로그에서 기존코드 실패를 재현했다. 수정후 제한크기 보고서 생성·중요오류 보존·검사통과를 확인했다. 오래된unknown+2600confirmed에서unknown우선보존, 타임라인 제외건수 보존, 제보창실패/접수전환 테스트를 추가했다. 상대방 기기의 실제 전송상태와 장애원인은 아직 미확인이다.

기존 관리 화면 업데이트 경로로0.4.27을 제공한다. 상대방이 업데이트 후 제보 창에서 보이는 제보ID와 접수번호 또는 실패코드를 확인하면 실제 수신경로와 대조할 수 있다.

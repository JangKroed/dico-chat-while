## 검증과 한계

- 실제 loopback HTTP 세션·CSRF·정적 UI·SQLite 단일 실행·상태 복구·네이티브 stdio 브리지 통합 시험을 수행했다.
- 가상 Chrome 실행기 세 개와 실제 중앙 코어를 연결해 36회 A → B → C 순환과 중지를 검증했다. 별도 코어 시험은 300회 순환을 포함한다.
- 실제 Discord 계정에 메시지를 보내지 않았다. 기본 아바타 등 계정 식별 근거가 없는 경우 보수적으로 차단한다.
- 실제 GUI 자동 검증은 Chrome·Brave 헤드리스 프로세스가 SIGABRT로 종료돼 미완료다. HTTP UI 로드·명령 처리는 성공했으며 재실행 가능한 브라우저 시험 스크립트를 제공한다.
- Node24 내장 SQLite는 현재 런타임에서 experimental 경고를 낸다. 런타임을 번들하고 버전을 고정했지만 배포 OS별 회귀 검증이 필요하다.
- 대량 이력은 SQLite의 트랜잭션 상태 집계로 저장한다. 현재 규모의 회귀 시험 외에 대용량 성능 시험은 하지 않았다.

## 출시 전 남은 작업

Windows와 macOS Intel 실기기 패키징·설치·절전·제거 시험, 실제 브라우저 확장 연결/권한 UI 검증, 승인된 실제 채널 발송 시험, 앱 서명·공증 및 배포 경로 확정이 필요하다. 구형 확장과 새 실행기를 같은 계정·채널에서 병행 실행하지 않는다.

고급 알림 설정 UI(유형별/회복/방해금지), OS 알림 클릭 연동, 서비스 외부 감시기, CSV·본문 포함 선택 내보내기, 과거 대량 로그 페이지 탐색, 앱/확장 자동 업데이트의 새 관리 방식 통합은 후속 항목이다. 해당 항목을 이미 제공하는 것으로 표시하지 않는다.

## 2026-10-31 설치 편의 개선

- `setup.command` / `setup.ps1`: 지원 Node 자동 선택 또는 공식 아카이브와 SHA-256 확인 후 프로젝트 내부에 준비. Windows MSVC는 설치된 개발 환경을 탐색하며 도구 자체 설치는 안내합니다.
- `scripts/setup-central.mjs`: 도구 진단, 무변경 실행 계획, 의존성·빌드·검사·테스트·패키징의 순차 처리 및 선택 설치·실행. 실행 중 서비스는 생성 파일 변경 전에 차단합니다.
- 설정 화면의 설치·연결 진단: 인증된 읽기 전용 API로 실제 연결·등록·설정 적용을 구분합니다. 기존 실행기 중지를 자동 검증하지 않습니다.
- 여러 PC와 Android 컨트롤러는 `MULTI-DEVICE.md`의 설계 단계입니다. 현재 서버를 LAN에 노출하지 않습니다.
- Windows PowerShell/컴파일러와 신규 Node 다운로드 경로의 실제 OS 실행 검증은 남아 있습니다. 개발 중 도구·네이티브 호스트·방화벽·인증서 설치를 실행하지 않았습니다.

## 2026-11-01 · 0.4.1 연결 흐름과 문제 해결 UI

계정 등록과 논리 채널 카탈로그를 분리했습니다. 확장 팝업의 계정 등록은 친구 목록에서도 가능하고 전송용 창을 만들지 않습니다. 중앙의 채널 URL 추가 후 계정을 선택하면 검증용 전용 창 연결을 요청합니다. 기존 바인딩·메시지·그룹은 유지하며 새 카탈로그에 반영합니다. 계정 변경 시 기존 연결을 승계하지 않고 재검증합니다.

알림은 원인·대상·해결 단계와 관련 화면 이동을 제공하며 상세 원인이 없는 과거 기록은 미기록으로 표시합니다. 읽음과 실제 해결을 구분합니다. 현재 문제는 미해결만 기본 표시합니다.

자동 테스트와 빌드 외에 격리된 임시 데이터로 실제 브라우저에서 계정 화면, 채널 추가, 계정 선택과 연결 대기, 문제 해결 단계, 읽음 유지 및 좁은 화면(375px 가로 넘침 없음)을 확인했습니다. 실제 사용자 데이터·서비스·Discord 발송은 변경하지 않았습니다. 헤드리스 Chrome은 SIGABRT로 실행되지 않아 별도 브라우저 화면 검증으로 대체했습니다. 네이티브 확장의 실제 Discord 계정 등록·창 연결은 실사용 검증이 남아 있습니다.

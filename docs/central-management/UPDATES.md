## 0.4.23 입력창 재생성·완료 응답 유실 복구와 관리자 제보

Discord가 같은 입력 폼 안에서 유일한 입력창을 다시 만들었을 때, 계정·채널·전송한 문구와 기존 폼을 확인해 입력창을 다시 찾는다. 입력·쿨다운 대기·전송 직전 확인 중 발생한 교체도 처리한다. 빈 입력창은 추가 시간 대기 없이 완료하고 같은 초안이 남으면 현재 차례에서 재시도한다. 새 폼·계정·채널·다른 초안은 이 자동 복구 대상으로 추측하지 않는다.

전송 처리는 완료됐지만 브라우저 응답만 유실되면 같은 콘텐츠 실행 수명에 저장된 정확한 시도의 완료 영수증을 한 번 읽는다. 10분·최근100개의 메모리 영수증이며 전송을 다시 실행하지 않는다. 과거 미확인 결과나 재시작으로 사라진 증거를 빈 입력창만 보고 소급 확정하지 않는다. 전달받은 사용자의 당시 원인은 아직 해당 PC의 기록 없이 단정하지 않는다.

문제·실행 기록·로그 상세·설정에서 ‘관리자에게 제보’를 열어 증상과 관련 기록을 미리보고 JSON 파일로 저장한다. 메시지 원문과 표시 이름은 포함 여부를 고를 수 있다. 관리자는 같은 화면의 ‘관리자용 제보 파일 열기’로 버전·빌드, 계정/채널·그룹 순서, 슬로우 모드·보정·재시도, 사건 타임라인과 입력·전송 증거를 확인한다. 수신 서버가 지정되지 않았으므로 파일을 원하는 메신저·메일로 직접 전달하는 방식이다. 외부 자동 전송은 하지 않는다.

발송 시도 상세와 관련 로그에는 현재 수정된 보관 메시지 대신 그 시도에 저장된 실제 원문을 표시한다. 보관 기간 정리 등으로 원문이 없으면 누락으로 표시한다. 보고서는 인증·세션·쿠키·브리지 키·초안 백업을 제외하며 검사기는 파일의 스크립트·HTML·URL을 실행하지 않는다. 보고서 최대16MiB는 파일 처리 한도이며 기록 보관 건수 제한이 아니다.

기존에 버려지던 DICO_TRACE를 연결해 준비·입력·Enter 요청·재시도·종료의 안전한 스칼라 진단을 저장한다. 실제 본문은 시도 기록에만 보관하고 진단 로그에 임의 초안을 복사하지 않는다. 반복 진단은 표본화하고 오류·종료 단계는 남긴다. 단일 시도 보고서는 해당 시도의 모든 직접 관련 이벤트와 제한된 전후 문맥을 수집하며 전체 기록 제보는 선택 기간을 따른다.

## 0.4.22 SSH 없는 내부망 주소 접속

설정·도움말에서 내부망 접속을 켜면 자동 감지한 사설 IPv4 주소와 별도 저장 포트를 표시한다. 같은 내부망의 PC·Mac·스마트폰에서 그 주소를 열고 중앙 화면의 2분·1회용 연결 코드를 입력하면 관리 화면을 사용할 수 있다. SSH나 다른 기기의 DICO 설치는 필요 없다. 신뢰하는 내부망·VPN HTTP 접속이며 공인 포트 공개 기능은 아니다.

LAN 연결은 기존 로컬 주소와 네이티브 실행기 연결을 유지한다. 원격 브라우저의 세션·쿠키는 별도로 관리하며 로그인 전 데이터·실시간 로그 조회를 차단한다. 네이티브 브리지와 내부망 설정 API는 원격 접속에서 제공하지 않는다. 접속 끄기·주소 변경·프로그램 재시작은 원격 세션을 폐기하고, 모든 설정 초기화는 내부망 접속도 끈다. 중앙 PC에서 실제 방화벽·네트워크 설정을 개발 과정에서 변경하지 않았다.

사용 순서는 [주소로 중앙 관리 페이지 접속하기](REMOTE-ACCESS.md)를 따른다. 다른 PC의 Discord 실행기를 한 중앙 스케줄러에 연결하는 기능과는 구분한다.

## 0.4.21 즉시 발송 처리·재시도 직접 설정·기간 내 기록 조회·다른 PC 접속 안내

중앙 발송의 입력창 비움 판정에서 500ms 유지 시간을 없앴다. 실제 전송을 요청한 문구가 입력창에서 사라진 것을 확인하면 즉시 완료 처리한다. 입력창 자체가 없거나 계정·채널이 바뀐 상태를 빈 입력창으로 취급하지 않는다. 보내려던 같은 문구가 남아 있으면 같은 차례에서 실제 슬로우 제한과 전송 상태를 확인하고 재시도한다. 게시된 메시지를 기다리는 공용 시간 초과 사유 대신 입력창 누락·교체, 다른 문구, 계정·채널 변경, Discord 실패 표시 등 실제 확인한 사유를 기록한다. 전달받은 사용자의 당시 원인은 해당 PC 기록 없이 단정하지 않는다.

재시도 횟수는 5회 상한 대신 직접 입력한다. 0은 재시도 사용 안 함, 무제한은 횟수 제한 없이 계속한다. 무제한에서도 전체 중지·세션 변경·다른 초안·실제 전송 중/실패 상태 검사는 유지한다. 설정과 진단에도 무제한을 숫자 5로 잘못 표시하지 않는다.

기록은 건수가 아니라 기존 보관 기간(30·90·180일)을 따른다. 실행 기록과 전체 로그는 이전 기록을 나눠 불러와 보관된 기간 전체를 조회한다. 화면 한 번에 불러오는 수와 실제 보관 수를 구분한다. 진행 중·미확인 결과와 중복 방지 기록은 기존처럼 보호한다.

설정·도움말에 ‘다른 PC에서 관리 화면 열기’를 추가했다. 같은 내부망은 SSH 터널, 서로 다른 내부망은 VPN 연결 후 SSH 터널을 사용하며 양쪽 포트를 동일하게 유지한다. 인증된 중앙 화면에서 2분짜리 일회용 접속 링크를 발급한다. 기존 주소 복사만으로 새 PC에 로그인할 수 없으며 로컬 브리지 키를 전달하지 않는다. OS별 준비·설치 확인·명령 복사·접속 오류 안내는 [원격 접속 문서](REMOTE-ACCESS.md)를 따른다. 여러 PC의 Discord 실행기를 통합하는 기능은 별도 구현 대상이다.

## 0.4.20 입력창 비움 기준 발송 처리·연결 제거·브라우저 창 통합

새 중앙 발송은 요청한 문구를 제출한 뒤 같은 계정·채널의 입력창이 500ms 동안 비워지면 발송 처리하고 다음 차례로 진행한다. 실제 메시지 본문·작성자·Discord 메시지 ID를 찾는 작업은 필수 조건에서 제외한다. 처음부터 비어 있거나 입력창을 찾지 못한 경우, 페이지·계정 변경이나 명시적인 전송 실패는 이 기준으로 성공 처리하지 않는다. 기록에는 입력창 비움 기준과 실제 메시지 관측 기준을 구분하며 메시지 ID를 만들어 넣지 않는다. 이전 미확인 발송은 현재 입력창만 보고 소급 확정하거나 재발송하지 않는다. 그룹·계정 간격과 슬로우 모드 확인은 유지한다.

채널 개별 삭제, 채널의 계정 연결 해제, 등록 계정·브라우저 제거와 채널 이름 수정을 중앙 화면에서 제공한다. 진행 중인 발송과 미확인 결과가 있는 대상은 처리해야 할 항목을 안내한다. 삭제한 연결은 이전 확장 관측이나 재접속으로 다시 등록되지 않으며, 명시적인 재등록·재연결로 다시 추가한다. 기존 실행 기록은 보존한다.

채널에서 계정 연결을 해제하면 해당 계정·채널의 전송 탭을 닫는다. 브라우저가 꺼져 있으면 다음 연결에서 처리한다. 삭제 대상 탭이 다른 페이지로 이동했다면 그 페이지를 닫지 않고 저장 연결만 정리한다. 브라우저별 전송 창은 다시 하나로 통합하고 채널별 탭을 둔다. 전송용으로 등록한 탭만 옮기며 일반 창과 탭은 그대로 둔다. 마지막 전송 탭을 닫으면 해당 전송 창도 닫힌다.

## 0.4.19 초기화 연결 복원 방지·실제 채널 이름·확장 업데이트 확인

모든 설정 초기화는 중앙 목록뿐 아니라 확장에 저장된 계정·채널·적용 구성을 다음 연결에서 함께 정리한다. 영속 초기화 세대로 오래된 확장 관측과 초기화 직전 처리 중이던 응답을 차단한다. 꺼져 있던 브라우저도 다음 연결 때 이전 연결을 복원하지 않는다. 기존 버전에서 이미 초기화한 설치는 초기화 이력으로 이관한다. 열린 Discord 탭, 로그인, 작성 중 초안과 실행 이력은 유지한다. 빈 등록 상태에서는 열린 탭을 스캔해 계정을 임의로 재등록하지 않는다.

채널 URL만 추가하면 숫자 ID 대신 ‘채널 이름 확인 대기’으로 표시하고, 이미 열린 정확한 대상 탭에서 이름을 읽는 작업을 요청한다. 실제 채널 헤더·선택된 채널·정리된 페이지 제목으로 이름을 확인하며 새 탭을 열거나 메시지를 보내지 않는다. 검증된 관측으로 자동 이름을 갱신하고, 사용자가 직접 지정한 이름은 유지한다. 아직 로그인하거나 해당 채널을 열지 않아 이름을 읽을 수 없으면 확인 대기로 남는다. 기존 ID 이름도 이관한다.

확장 자동 재시작은 브라우저에 등록된 압축해제 폴더를 다시 읽는다. 따라서 설치된 관리 프로그램만 새 버전이고 브라우저는 예전에 받은 ZIP의 확장 폴더를 계속 읽으면 이전 버전으로 남을 수 있었다. 이제 안전한 업데이트 확인 시 Chrome·Brave의 각 프로필 등록 경로를 읽고, 같은 확장 키·허용 ID·DICO 패키지·런타임이 확인되는 배포 폴더의 확장만 최신 설치본으로 교체한다. 복사본을 먼저 검증하고 기존 폴더를 보관한 뒤 교체하며, 실패하면 기존 폴더를 복원한다. 브라우저 설정 파일과 사용자 데이터는 바꾸지 않는다. 이 확인은 0.4.13의 기존 업데이트 요청에도 적용된다.

개발 저장소·심볼릭 링크·출처를 확인하지 못한 폴더는 자동 교체하지 않는다. 이 경우 설정·도움말의 설치·연결 진단에서 표시하는 정확한 관리 확장 폴더로 한 번 전환해야 한다. 브라우저를 강제로 종료하거나 같은 빌드를 반복 재시작하지 않는다. 이전 확장이 이미 같은 대상 빌드의 자동 재시작을 한 번 시도한 기록이 있다면, 파일 복구 뒤에도 확장 관리 화면에서 한 번 새로고침해야 할 수 있다.

자동 처리할 수 없는 경로는 설정·도움말 → 설치·연결 진단의 ‘자동 업데이트용 확장 폴더’를 확인한다. Chrome/Brave 확장 관리에서 개발자 모드를 켜고 ‘압축해제된 확장 프로그램 로드’로 이 폴더를 한 번 선택한다. 기존 DICO를 삭제하지 않고 같은 ID의 관리 폴더를 등록해 설정을 보존한다.

업데이트 화면은 관리 프로그램과 각 확장의 보고 버전을 비교한다. 연결 응답이 오더라도 버전이 다르면 업데이트 필요로 표시한다. 관리 프로그램과 모든 사용하는 브라우저 확장에 같은 버전을 적용해야 한다.

## 0.4.18 계정 닉네임·기본 프로필 사진·그룹 간격과 표시 순서

검증된 현재 계정의 실제 Discord 닉네임과 사용자명을 계정 등록·지속 관측에서 저장한다. 숫자 ID만 있던 자동 이름은 닉네임으로 갱신한다. 사용자가 지정한 별칭은 유지하며 계정 카드에 실제 닉네임과 ID도 함께 표시한다. 백업·복원에서도 자동 이름과 별칭 구분을 보존한다.

기본 프로필 사진에는 계정 ID가 없는 이미지 인덱스만 있으므로 사진 번호를 ID로 추측하지 않는다. 현재 사용자 영역의 명시적 계정 정보와 그 영역에 연결된 제한된 UI 구성요소의 사용자 정보에서 ID·닉네임만 확인한다. 브라우저 MAIN 실행 영역에서 읽고, 발송 허가 응답 직전에도 현재 계정·대상·중지 상태를 다시 검증한다. 인증 토큰·저장소·비공개 API에 접근하지 않는다. 읽을 수 없거나 ID가 충돌하면 검증 실패로 남긴다. 기본 사진 지원은 계정 등록뿐 아니라 준비·실제 발송 전 검증에도 적용한다.

새 그룹의 기본 최소 간격은 20초다. 기존 저장값을 임의 변경하지 않는다. 이전의 일괄적인 5초 입력 선행으로 그룹20초가 입력 준비15초로 표시될 수 있었다. 이제 그룹 간격은 이전 게시 확인 후 온전히 기다린 뒤 입력 준비를 시작한다. 준비와 확인의 실제 지연은 다음 진행에 추가되고 차례는 유지된다. 예: 20초 대기+7초 준비 지연이면 최소27초 뒤 발송 허가. 계정별 슬로우 제한 대기는 별도로 최대5초 먼저 준비할 수 있다.

대시보드 계정 목록은 채널 등록 순서 대신 그룹에 설정된 실제 계정 순서를 사용한다. 순번과 현재 차례를 표시하고 그룹 상세와 같은 순서를 유지한다. 같은 채널의 여러 그룹은 구분하며 그룹 미지정 계정과 누락된 연결을 숨기지 않는다. group_interval 등 대기 원인도 한국어로 표시한다.

관리 프로그램과 사용하는 모든 브라우저 확장을 0.4.18로 업데이트한다. 현재 운영 설정·계정·발송 상태를 개발 과정에서 변경하거나 실제 메시지를 보내지 않았다. 기본 사진의 실제 Discord 화면을 직접 조작하는 검증은 수행하지 않았으며, 공개 UI 소스 분석·실행 영역/계정 전환/중지 경계 재현 시험으로 검증한다.

## 0.4.17 확장 업데이트 보류 후 빠른 재확인

실행 기록을 읽기 전용으로 관찰한 결과 중앙 프로그램과 Brave는 0.4.16이었으나 Chrome 두 프로필은 0.4.15로 남아 있었다. 업데이트 보류도 30초 재확인 제한에 포함되어, 그 사이 모두 실행을 누르면 이후 실행 중 보호 조건으로 업데이트가 계속 보류될 수 있었다. 최초 보류의 내부 사유 자체는 저장되지 않아 단정하지 않는다.

보류된 업데이트는 기존 5초 heartbeat에서 안전 상태를 다시 검사한다. 변경 없음·오류·수동 조치 상태에는 기존 간격을 유지한다. 새 polling이나 실행 중 강제 재시작을 추가하지 않는다. 확장의 선택적 빌드 ID는 64자리 해시 검증 후 연결 정보에 저장한다.

관찰 구간 23:22~23:26(KST)에는 추가 게시 14건, 그룹별 순서 위반 0건, 중단 0건이었다. Brave 일부 시도는 1~2회 재시도 후 게시되어 25~50초의 추가 지연이 있었다. 이 버전은 최초 Enter가 수락되지 않는 원인까지 해결했다고 주장하지 않는다. 화면 직접 관찰 도구가 없는 세션에서 DB·실행 결과를 대조한 기록이다. 실제 실행·중지·재발송·업데이트를 자동 조작하지 않았다.

## 0.4.16 재생성된 채널 탭의 대기 거절 수정과 중지 완료 분리

0.4.15 운영 기록에서 그룹3의 준비가 여섯 번 연속 MANAGED_DELAY_UNAVAILABLE로 거절됐다. 같은 세션·설정 버전에서 CONFIG_SYNC가 저장한 탭은 1093824113이고, 다시 열린 실제 PREPARE 탭은 1093824145였다. 워커 대기 검증이 이전 설정의 탭만 인정한 회귀다. 현재 세션의 준비·실행 시도와 일치하는 계정·채널·설정·실제 탭을 기준으로 대기를 허용하고, 워커 시작 시 저장 상태를 먼저 불러온다. 대기 응답은 입력·발송 허가를 대신하지 않는다.

같은 시각 그룹1의 재시도는 사용자 전체 중지 요청으로 취소됐으나 RETRY_CANCELLED가 일반 result_unknown으로 손실됐다. 취소·게시 변화 사유와 관찰한 초안·게시 증거를 보존한다. 중지 요청 뒤 모든 브라우저의 적용 응답과 해당 시도의 실행 차단이 확인되면 그룹의 중지·일시정지는 완료한다. 과거 미확인 결과·시도·중복 방지 잠금은 그대로 유지하며 결과 확정 전 다시 발송하지 않는다. 이전 버전에서 이미 응답을 받은 중지 대기도 같은 증거로 정리한다.

대시보드의 확인 필요 집계와 그룹의 이전 발송 결과 이동 버튼은 중지가 완료된 미확인 시도도 표시한다. 실제 결과 확정 시 잠금을 해제한다. 시간 이상 감지에는 벽시계 경과·단조시계 경과·차이·감지 조건을 기록한다. 시간 이상 감지 기준 자체를 해제하거나 실제 OS 잠자기로 단정하지 않는다.

서비스는 전체 중지·앱 재시작·업데이트·설정 복원 후 자동으로 준비된다. 별도 서비스 재개 버튼은 제거한다. 그룹과 실제 발송은 자동 시작하지 않으며 전체 중지는 각 그룹의 실행 허가를 차단한다. 시계 이상 감지도 서비스 조작 단계를 추가하지 않고 영향받은 그룹을 일시정지하며 시간 기준과 남은 간격을 다시 준비한다.

대시보드의 채널별 그룹 카드와 발송 그룹 목록에 그룹별 시작·재개·중지를 표시한다. 해당 그룹의 연결·메시지·미확인 결과만 검사하고 시작 불가 사유를 표시한다. 여섯 개 이후 그룹도 생략하지 않는다. 상태 수신이 지연돼도 중지 요청은 사용할 수 있다.

채널의 계정 연결 목록과 실행 기록 목록에 전체 선택·전체 해제를 추가한다. 계정 연결은 연결 가능 항목만 선택한다. 실행 기록의 현재 필터 밖 선택은 보존하고 일괄 처리 200건 제한을 지킨다. 알림 활성화 같은 단일 설정 체크박스는 목록 선택과 구분한다.

관리 프로그램과 각 브라우저 확장을 모두 0.4.16으로 업데이트한다. 운영 데이터의 미확인 결과를 임의로 미발송 처리하거나 그룹을 자동 재개하지 않는다.

## 0.4.15 준비 지연 자동 복구·채널별 창 분리

- 새 채널은 채널별로 최소화된 전송 창을 하나씩 엽니다. 여러 채널을 한 창의 비활성 탭으로 추가하지 않습니다.
- 계정·브라우저의 `채널별 창 분리`는 해당 브라우저의 그룹과 미확인 발송이 정리된 뒤 실행합니다. 기존 탭을 이동하므로 탭 ID와 작성 중인 초안을 유지하며 새로고침하지 않습니다. 일반 탭은 이동하거나 최소화하지 않습니다.
- 안전한 연결 복구 시 기존 채널 탭도 별도 창으로 분리합니다. 진행 중이거나 결과가 미확인인 발송이 있으면 이동을 미룹니다. 이미 단독 창인 채널은 이동하거나 포커스를 변경하지 않습니다.
- `전송 창 숨기기`는 해당 채널만 있는 전송 창을 최소화합니다. 여러 탭이 남아 있는 창은 먼저 분리해야 합니다.
- 창을 나누어도 OS 전경 포커스나 실제 게시 성공을 보장하지 않습니다. 입력·포커스·게시 확인 실패는 발송 결과로 계속 확인해야 합니다.

실제 운영 기록에서 문제 알림 두 건은 Enter 이후의 미확인 전송이 아니라 발송 허가 전 PREPARE 단계의 30초 시간 초과였다. 처리 중인 같은 명령이 다시 대기열에 들어가고 거절 결과가 재처리되어 수백 건의 오류와 중지 지연으로 이어졌다. 동일 명령의 실행을 합치고 거절 결과도 저장하며 같은 ACK가 반복돼도 오류를 다시 만들지 않는다.

숨겨진 Chromium 페이지는 연결된 페이지 타이머를 크게 지연시킬 수 있다. 관리 전송의 입력 안정화·제한 대기·게시 관찰·발송 후 보정 관측은 인증된 관리 탭만 요청할 수 있는 최대 1초의 확장 워커 대기로 변경했다. 실제 입력·Enter 권한은 별도로 재검증한다. 시간 지연 재현 시험으로 확인하며 당시 Chromium 내부 스케줄러 상태까지 운영 로그로 증명한 것은 아니다.

발송 허가가 발급되지 않은 준비 실패는 미발송으로 확정하고 설정된 재시도 횟수 안에서 5초 뒤 같은 차례를 준비한다. 같은 계정의 게시 확인 전 다음 계정이나 문구로 넘기지 않는다. 재시도 횟수 소진·계정 변경·다른 초안 등은 구체적인 준비 오류로 안내한다. Enter 이후의 불확실한 결과에 이 미발송 판정을 적용하지 않는다.

창 표시·숨김·분리 실패는 대상과 재시도 경로를 안내한다. 같은 계정·채널에 같은 창 작업이 성공한 뒤 ‘해결 상태 재검사’를 누르면 지난 경고가 정리된다. 다른 채널의 성공이나 읽음 표시는 해결 근거로 사용하지 않는다.

적용 순서: 그룹을 정상 중지하고 설정·도움말에서 업데이트한다. 관리 프로그램과 각 브라우저 확장이 0.4.15로 연결된 뒤, 계정·브라우저의 ‘채널별 창 분리’를 실행한다. 기존 초안과 탭 ID를 유지한다. 로그에서 지난 창 작업을 대상 채널에 다시 요청한 뒤 해결 상태를 재검사한다. 실제 그룹 재개는 사용자가 ‘모두 실행’으로 요청한다.

# 업데이트 사용 방법 (0.4.9)

## 평소에는 중앙 페이지에서 한 번

1. 실행 중인 그룹을 중지하거나 일시정지합니다. 진행·미확인 결과와 중지 응답 대기를 먼저 처리합니다.
2. 설정·도움말 → **업데이트 실행**을 누릅니다.
3. 새 소스 다운로드 → 의존성 준비 → 빌드·검사 → 안전 상태 재확인 → 프로그램 적용 순서가 표시됩니다. 기존 탭은 재연결을 기다립니다.
4. 같은 주소의 기존 탭이 다시 연결되면 완료 상태와 브라우저 연결을 확인합니다. 설정 화면에서 실행한 업데이트는 같은 탭에서 화면을 갱신합니다. 다른 편집 화면은 초안을 보존하도록 갱신 안내를 표시할 수 있습니다. 그룹은 자동 재개되지 않습니다.

기존 개발 폴더에서 git pull·빌드·설치 명령을 반복할 필요가 없습니다. 고정 저장소 `JangKroed/dico-chat-while`의 main을 별도 작업 폴더에 받습니다. 기존 클론, DB, 설정과 실행 기록은 보존합니다. Git과 npm은 최초 소스 설치 때 준비된 것을 재사용합니다. 도구가 없으면 어떤 도구가 필요한지 표시합니다.

## 확장을 매번 새로고침하지 않는 방식

실행 중인 확장 빌드 ID와 설치 폴더의 실제 파일 해시를 비교합니다. 확장 파일이 같으면 재로드하지 않습니다. 바뀌었으면 모든 그룹과 로컬 실행기가 유휴 상태일 때 각 브라우저가 `chrome.runtime.reload()`로 자체 재시작합니다. Chrome·Brave 프로필이 닫혀 있으면 다음 실행·연결 때 확인합니다.

콘텐츠 스크립트도 안전한 전송용 탭에서 버전을 검사해 다시 연결합니다. 초안을 삭제하거나 Discord 탭을 강제로 새로고침하지 않습니다. 구버전 콘텐츠 스크립트는 최초 한 번 직접 탭을 새로고침해야 할 수 있습니다. 새 버전이 확인되지 않으면 같은 목표 빌드에 대한 재로드를 반복하지 않고 로드 폴더 확인을 안내합니다.

## 0.4.0·0.4.1에서 최초 한 번 전환

기존 버전에는 업데이트 버튼과 자동 재로드 코드가 없으므로 이번 0.4.2 전환만은 기존 설치 절차가 필요합니다.

1. 현재 그룹을 중지하고 미확인 결과·중지 응답을 확인합니다.
2. 관리 프로그램을 정상 종료합니다. 관리 페이지의 ‘전체 중지’는 프로세스 종료와 다릅니다.
3. 최신 소스를 받은 폴더의 `setup.command`(macOS) 또는 `setup.ps1`(Windows)을 실행합니다. 자세한 도구 준비와 실행은 [클론 설치 문서](CLONE-SETUP.md)를 참고하세요.
4. 각 브라우저의 관리 확장 경로가 아래 **설치된 app/extension**인지 한 번 확인하고 확장을 새로고침합니다.
5. 필요한 초안을 따로 보관하고 기존 Discord 탭을 한 번 새로고침한 뒤 연결을 확인합니다.

| OS | 관리되는 확장 폴더 |
| --- | --- |
| macOS | `~/Library/Application Support/DICO/app/extension` |
| Windows | `%LOCALAPPDATA%\DICO\app\extension` |

클론의 `central/extension`이나 옛 패키지 폴더를 로드했다면 앱 업데이트가 그 폴더를 바꾸지는 않습니다. 기존 확장을 무작정 삭제하지 말고 현재 로드 경로를 먼저 확인하세요. 관리 경로 이전은 최초 한 번 필요하며, 이후 그 경로를 유지합니다. 브라우저가 새 권한 승인을 요구하거나 확장을 비활성화한 경우에는 브라우저에서 처리해야 합니다.

## 실패했을 때

다운로드·의존성·빌드·검사 실패 시 기존 설치를 바꾸지 않습니다. 적용 직전에 실행 상태가 바뀌어도 중단합니다. 교체 오류에서는 이전 JavaScript 파일을 복원하고, 시작 확인 실패 시 이전 파일을 보존하여 복구 가능한 상태를 남깁니다. 실패 원인과 다음 조치는 중앙 화면에 표시됩니다.

Windows 파일 잠금을 피하기 위해 Node와 네이티브 런처 실행 파일은 일반 업데이트에서 교체하지 않습니다. 더 높은 Node 버전이나 런처 변경이 필요한 릴리스는 전체 설치 도구를 사용합니다. 새 버전의 DB를 임의로 과거 DB로 덮어쓰지 않습니다.

## 검증 범위

자동 테스트는 임시 설치 폴더에서 안전 상태·출처 고정·CSRF/작업 인증·중복 실행·교체 복구·확장 재로드 제한을 검사합니다. 실제 사용자 프로그램 설치, 실제 Chrome/Brave 확장 재로드, Windows 실기기 업데이트와 Discord 발송은 별도 인수 검사가 필요합니다.

## 주소와 탭 유지 (0.4.4부터)

설치별 포트를 기록해 프로그램 재시작·업데이트 때 재사용합니다. 신규 설치 기본은 `http://127.0.0.1:43127`이고 기존 설치는 사용할 수 있는 기존 포트를 유지합니다. 포트가 다른 프로그램에 점유되면 임의 주소로 바꾸지 않고 오류를 안내합니다.

일반 업데이트는 브라우저를 새로 열지 않습니다. 유효한 UI 세션은 개인 저장 파일에 기존12시간 정책 안에서 보존되며 같은주소·같은탭에서 재연결합니다. 만료된 인증을 자동으로 우회하지 않습니다. 세션 파일은 백업이나 확장으로 내보내지 않습니다.

기존0.4.3 이하 worker는 새창을 여는 코드와 메모리 전용 세션을 사용하므로,0.4.4 최초 전환은 새 화면이나 최초 인증이 한 번 필요할 수 있습니다.0.4.4가 시작하는 다음 업데이트부터 기존탭 유지가 적용됩니다. 확장0.4.2 코드는 바뀌지 않습니다.

## 0.4.4 표시·진단 보강

대시보드에서 채널별·계정별 간격 충족까지 남은 시간을 매초 표시합니다. 이는 중앙에서 계산한 실행 조건의 예상 시각이며 실제 게시 완료 시각은 아닙니다. 연결이 끊기거나 미확인 발송이 있으면 숫자 대신 확인할 상태를 표시합니다.

직접 지정한 계정 표시 이름을 실행 기록 목록·상세와 대시보드·그룹·문제 안내에 공통 적용합니다. 같은 계정 ID라도 브라우저별로 등록한 이름을 구분합니다.

이번 버전은 발송 결과 진단 보강 때문에 확장도 변경됩니다. 관리 프로그램 업데이트 후 각 브라우저의 확장 업데이트 안내를 확인하세요. 미확인 시도는 먼저 실제 Discord 게시 내역과 실행 차단을 확인해 결과를 확정해야 합니다. 상세 절차는 `DELIVERY-TROUBLESHOOTING.md`를 참고하세요.

### 실제 Discord 제한 상태 확인

`early-prepare-v1`을 지원하는 최신 확장은 다음 예정 시각의 약 5초 전부터 문구를 준비합니다. 현재 차례만 준비하며 다른 계정의 차례를 앞당기지 않습니다. 준비 후에는 같은 초안과 계정·채널을 유지한 채 실제 Discord의 남은 제한 시간을 반복 확인합니다. 예정 시각과 제한 해제 모두 충족해야 전송 허가가 발급됩니다. Enter 직전에도 다시 검사합니다.

제한 표시를 읽을 수 없으면 0초로 간주하지 않습니다. 연결·초안이 바뀌거나 준비 대기가 2분을 넘으면 중단해 확인하도록 합니다. 허가 후 새 제한이 감지된 경우에는 Enter를 누르지 않고 그룹을 일시정지해 차례를 유지합니다. 초기 실행처럼 5초의 준비 여유가 없는 경우는 입력 준비가 끝난 뒤 확인 절차를 수행합니다.

## 0.4.5 대시보드 진행 문구 수정

중지된 그룹에서는 남아 있는 쿨다운과 무관하게 계정 행에 `중지됨`을 표시합니다. 일시정지 상태는 `일시정지됨`으로 표시합니다. 실행 중인 그룹의 현재 차례 계정만 `입력 준비까지 약 N초`를 표시하고 다른 계정은 `차례 대기`를 표시합니다. 입력 준비 시간은 해당 그룹의 다음 허가 예정 시각에서 최신 확장의 사전 입력 5초를 뺀 시각입니다. 다음 계정의 개인 쿨다운을 실제 입력 예정 시각으로 표시하지 않습니다.

입력 후에는 `입력 준비 완료 · 발송 대기`, `Discord 제한 해제 대기`, `발송 확인 중`을 표시합니다. 기존 미확인 발송은 중지 여부와 별개로 실제 게시 여부 확인이 필요하다는 표시를 유지합니다. 이번 변경은 중앙 화면에만 적용되며 확장 빌드는 0.4.4를 유지합니다.

## 0.4.6 브라우저마다 전송 창 하나로 관리

- Brave에 채널 3개를 연결하면 최소화된 전송용 창 1개에 탭 3개를 둡니다. Chrome과 다른 브라우저 프로필은 각각 별도로 관리합니다.
- 이미 여러 창으로 나뉘어 있다면 해당 브라우저의 모든 그룹을 중지하고 미확인 결과를 확인한 뒤, 계정·브라우저 화면의 `전송 창 모으기`를 누르세요. 기존 탭을 이동하며 페이지를 새로고침하거나 초안을 지우지 않습니다. 일반 탐색 탭은 옮기지 않습니다.
- 대시보드·채널 설정·실행 기록·문제 알림의 `전송 창 보기`는 연결된 기존 채널 탭을 선택해 창을 앞으로 가져옵니다. `전송 창 숨기기`는 해당 브라우저의 전송용 창 전체를 최소화합니다. 보기 동작은 메시지를 발송하지 않습니다.
- 전송용 창이나 브라우저를 종료하면 자동 실행할 수 없습니다. 최소화 상태로 유지하세요. 백그라운드 절전이나 Discord 화면 변경으로 검증하지 못할 때는 발송을 차단합니다.
- 여러 관측 요청을 직렬화·병합하고 채널별 읽기는 병렬화해 오래된 결과가 새 결과를 덮는 문제를 줄였습니다. 로딩·화면 읽기 실패·닫힌 탭·실제 계정 불일치를 구분합니다.
- 장애 이후 현재 세션에서 정상 계정·채널을 다시 확인하면 관련 연결 알림을 해결합니다. 게시 여부 미확인 시도와 수동 재개가 필요한 그룹은 자동 재개하지 않습니다.

관리 프로그램과 각 브라우저 확장을 0.4.6으로 업데이트한 뒤 사용합니다. 운영 중인 창을 자동으로 이동시키지 않으며 창 모으기는 사용자가 요청한 경우에만 수행합니다.

## 0.4.7 대기·초안·설정 보존과 화면 테마

- 상세창이 데스크톱 화면보다 길어지면 창 내부를 스크롤합니다. 키보드와 터치 스크롤도 지원합니다.
- 발송 직전 실제 Discord 쿨다운이 남으면 같은 발송 시도·계정·초안·그룹 순서를 유지하며 기다립니다. 제한 해제 뒤 입력 안정 상태와 최신 중앙 승인을 다시 확인한 후 Enter를 한 번 시도합니다. 실제 게시가 확인돼야 다음 계정으로 넘어갑니다. 기다리는 동안 중지·계정·초안 변경이나 연결 유실이 있으면 차단합니다.
- 정상 관측 중인 긴 쿨다운은 30초 결과 타임아웃으로 종료하지 않습니다. 최대 지원 관측 대기는 6시간 30초이며, 관측 유실과 절전·시계 변화는 기존 안전 검사로 중단합니다. 이미 Enter를 시도한 미확인 시도에는 Enter를 다시 보내지 않습니다.
- 입력창 문구가 예정 문구와 같으면 붙여넣지 않고 그대로 사용합니다. 다른 일반 텍스트 초안은 브라우저에 먼저 보관하고, 원문이 바뀌지 않은 경우에만 예정 문구로 교체합니다. 보관 실패·첨부·답장·해석할 수 없는 입력은 교체하지 않습니다. 보관 원문은 확장 사이드패널의 ‘교체 전에 보관한 초안’에서 볼 수 있습니다. 같은 발송 ID와 미확인 시도의 중복 전송을 막으며, 사용자가 지정한 반복 메시지 자체를 과거 본문과 같다는 이유로 금지하지 않습니다.
- 설정 초기 렌더링에 저장값을 사용하고, 알림·기록 보존의 편집값을 별도로 유지합니다. 한 항목 저장이나 업데이트 재연결이 다른 항목의 미저장 편집을 덮어쓰지 않습니다. 미저장 설정이 있으면 자동 화면 새로고침 대신 업데이트 안내를 표시합니다. 저장된 SQLite 설정이 재시작으로 초기화되는 현상은 재현되지 않았습니다.
- 저장된 계정과 닫힌 전송용 채널 탭을 재연결 시 자동 복구합니다. 실제 계정 확인과 기존 실행기 중지 확인이 필요하며, 미확인 발송이 있거나 기존 탭이 다른 채널이면 자동 교체하지 않습니다. 대시보드의 ‘자동 연결 진행 상황’에서 브라우저 연결 → 계정 확인 → 채널 확인 → 설정 적용을 확인합니다. 발송 시작은 별도 실행 요청이 필요합니다.
- 설정·도움말에서 시스템·라이트·다크 테마를 선택합니다. 기본은 시스템이며 OS 테마 변경을 반영합니다. 직접 고른 테마는 같은 브라우저에서 업데이트 뒤에도 유지합니다.

검증 범위: 자동 시험과 UI 빌드. 격리된 Chrome 실행 실패로 실제 브라우저 스크롤·다크 화면·Discord 게시의 최종 확인은 완료하지 못했습니다. 이번 이미지의 Enter 시도 후 초안 잔류는 쿨다운이 원인이라고 확정할 증거가 없으므로, 신규 대기 경로 개선과 기존 미확인 결과 처리를 구분합니다.

## 0.4.8 UI/UX와 두 테마 정리

- 대시보드는 현재 운영 요약과 문제를 먼저 표시한다. 정상 연결의 세부 절차는 접고, 브라우저별 요약과 계정 별칭으로 구분한다. 단계는 완료·진행 중·대기를 구분하며, 실행 차단 사유는 별도로 표시한다.
- 연결이 끊긴 브라우저에 자동 생성 이름인 ‘연결된 Chrome’이 남아 현재 연결 상태처럼 읽히지 않도록 표시 이름을 정리한다. 사용자가 지정한 이름은 보존한다.
- 화면별 다크 색상 덧칠을 공통 색상 토큰으로 교체했다. 본문·보조 문자·진단 안내·입력·표·상태·포커스·비활성 버튼을 두 테마에서 함께 관리한다. 보조 문자는 최소 12px, 일반 본문과 입력은 13px 이상을 기준으로 조정했다.
- 마지막 갱신은 실제 수신 시각을 사용한다. 선택 기간의 분석 조회 실패를 0건이나 다른 기간의 집계로 대체하지 않는다.
- 편집 중 페이지 이동·선택 변경에서 초안 보호를 보강하고, 모달 Tab 순환·Escape 닫기·포커스 복귀와 모바일 메뉴의 기본 키보드 처리를 추가했다.
- 이번 변경은 중앙 화면에 적용되며 확장 버전은 0.4.7을 유지한다. 관리 프로그램 업데이트로 적용한다.

리뷰와 검증 범위는 `UIUX-REVIEW-2026-11-02.md`에 기록했다. 자동 시험·React 서버 렌더 검사·색상 조합 검증은 실행했으나, 격리된 Chrome 시작 실패로 실제 브라우저의 반응형·키보드·시각 검증은 완료하지 못했다.

## 0.4.9 네이티브 통신 연결 회귀 수정

0.4.7에서 추가한 `CONNECTION_PROGRESS`, `RECOVERY_STATUS`, `DELIVERY_WAIT`를 네이티브 호스트의 통신 허용 목록에 누락했다. 중앙 코어는 처리할 수 있었지만 네이티브 호스트가 먼저 거절해, 최초 연결 성공 뒤 자동 복구 보고 단계에서 끊기는 문제가 발생했다. 이 수정은 세 메시지를 명시적으로 허용하며 등록 확장 출처·비밀 필드·프레임 크기·미지원 메시지 차단은 유지한다.

기존 코어·실행기 통합 시험은 이 네이티브 경계를 생략해 누락을 잡지 못했다. 모든 실제 확장 요청 타입의 통과 계약 검사와, 실제 네이티브 프레임 → 로컬 HTTP → 중앙 상태를 연결한 자동 복구·쿨다운 회귀 검사를 추가했다. 대기 중 같은 시도와 메시지 순서를 유지하고, 허가 차단·해제, 알 수 없는 메시지 거절 후 정상 세션 유지까지 검사한다. 실제 Discord 메시지는 보내지 않는다.

관리 프로그램만 0.4.9로 업데이트하면 된다. 확장 버전은 0.4.7 유지가 정상이다. 업데이트 뒤 기존 호스트 연결이 닫히고 새 호스트로 자동 재연결될 때까지 약 30초 기다리거나, 각 확장의 `연결 도움말 · 다시 확인 → 관리 프로그램 다시 연결`을 누른다. 계정·채널을 삭제하거나 다시 만들 필요는 없다. 이번 수정은 기존 그룹을 자동 실행하지 않는다.

진단 시 실제 DB를 읽기 전용으로 확인한 결과 계정 3개·채널 8개가 남아 있었고 최근 이벤트 90개에서 연결/해제가 각각 44번 반복됐다. 설치된 0.4.8 호스트에도 세 타입이 없는 것을 확인했다. 운영 DB와 실행 상태는 수정하지 않았다.


## 0.4.10 미발송 확인 후 현재 차례 이어가기

- 문제 알림과 실행 기록 상세에 **미발송 확인 · 같은 계정에서 계속**을 추가했다. 실제 미발송을 확인한 사용자의 요청으로 이전 시도를 미발송 처리하고 해당 그룹의 같은 계정·현재 메시지 차례를 다시 준비한다. 다른 그룹은 실행하지 않는다. 게시가 확인돼야 다음 계정과 다음 메시지로 넘어간다.
- 확장이 전송 처리를 마치고 최종 관측 결과를 반환한 경우에는 이전 실행의 추가 Enter가 차단됐음을 함께 보고한다. 응답 유실·통신 실패는 이에 포함하지 않는다. 입력창에 문구가 남았다는 사실만으로 과거 미발송을 자동 확정하지 않는다.
- 미발송 확인 뒤 새 입력 준비가 정기 하트비트보다 먼저 도착해도, 중앙의 확정 결과를 먼저 동기화한다. 이 순서 누락으로 이미 정리한 시도가 다시 미확인 초안으로 차단되는 문제를 방지한다.
- 현재 문구가 예정 메시지와 같으면 그대로 사용하며, 실제 Discord 제한이 남으면 해당 계정의 차례에서 기다린다. 사용자가 미발송을 확인하지 않은 기존 시도에 Enter를 반복하지 않는다.
- 이미 요청한 중지의 적용 응답이 남아 있으면 미발송 결과를 저장하고 대기 상태를 표시한다. 적용 완료 뒤 실행 기록에서 해당 시도를 다시 이어갈 수 있다. 이 대기에는 자동 재시작을 예약하지 않아 이후의 중지 요청을 덮지 않는다.

관리 프로그램과 각 브라우저의 확장을 모두 0.4.10으로 업데이트해야 전체 개선이 적용된다. 계정·채널·메시지를 삭제하거나 다시 등록할 필요는 없다. 업데이트 자체는 기존 미확인 시도를 미발송으로 바꾸거나 그룹을 실행하지 않는다.

검증은 가상 Discord 응답을 이용한 코어·실행기 시험과 UI 빌드를 포함한다. 실제 Discord에서 Enter가 처리되지 않는 원인은 아직 확정되지 않았으며, 이번 변경은 미발송을 확인한 사용자가 현재 차례를 이어가는 절차를 줄인다.


## 0.4.11 재실행 시 발송 주기 전체를 다시 기다리는 문제 수정

서비스 재개 및 전체 실행 경로에서, 이전 게시 확인 기록이 있는 모든 계정에 재개 시각부터 `슬로우 모드 + 3초` 또는 사용자 지정 주기 전체를 다시 부과하고 있었다. 그룹 간격도 같은 방식으로 초기화됐다. 재실행 직전에 실제 Discord 제한이 이미 풀렸어도 중앙 타이머가 입력 준비를 지연시킬 수 있었다.

명시적 재개 시 마지막 게시 확인 시각을 기준으로 이미 지난 시간을 제외하고 남은 간격만 복원한다. 해당 간격이 이미 지났거나 게시 확인 이력이 없으면 추가 대기 없이 현재 차례를 준비한다. 사용자 지정 간격이 남아 있으면 남은 부분만 유지한다. 실제 Discord 잔여 제한은 준비·발송 직전 기존 관측 경로에서 확인하며 남아 있으면 같은 차례에서 기다린다. 현재 게시 확인 전 다음 계정으로 넘어가지 않는다.

서버 재시작 이후 채널 연결 확인과 명시적 실행 요청은 유지한다. 시계 역행으로 마지막 게시 확인 시각이 미래가 된 경우 대기는 해당 간격 전체를 상한으로 제한한다. 운영 데이터나 실제 그룹은 이 수정 과정에서 변경·실행하지 않았다.

관리 프로그램만 0.4.11로 업데이트한다. 확장 버전은 0.4.10 유지가 정상이며 이번 수정 때문에 확장을 다시 새로고침할 필요는 없다.


## 0.4.12 같은 계정·초안의 제한된 전송 재시도

운영 DB를 읽기 전용으로 확인한 결과 첫 순환 8건은 게시 확인됐으나 이후 세 그룹에서 Enter 요청 후 초안 잔류가 발생했다. 세 건 모두 새 게시·일치 게시·전송 중 표시가 관측되지 않았다. 첫 입력과 다음 순환은 같은 content 함수를 사용하며 중앙 확장도 기존 확장의 합성 키 입력 경로를 재사용한다. 앞선 대기·타이머·수동 재개 수정은 이 경로 자체를 대체한 것이 아니다.

현재 공개 Discord 소스는 Slate `onKeyDown`에서 제출하며, 자동완성·내부 composition·submitting 상태 등에 의해 요청이 소비될 수 있다. 단순 keypress 누락을 원인으로 단정하지 않는다. 기존 가상 입력창 시험은 keydown 즉시 게시를 만들어 실제 Discord의 이벤트 수락을 검증하지 못했다. 실제 실패 당시 내부 상태 로그가 없어 세 건의 정확한 내부 차단 원인은 확정하지 않았다.

사용자의 요청에 따라 동일한 발송 시도 내에서 최대 5회 재시도한다. 각 요청 후 게시 관찰을 마친 다음 동일한 초안만 남고 게시·전송 흔적이 없을 때만 재시도한다. 재시도마다 실제 슬로우 제한과 현재 계정·채널·초안·중지 상태 및 새 중앙 승인을 다시 확인한다. 늦게 도착한 게시 증거나 불확실한 전송 흔적이 있으면 반복하지 않는다. 현재 시도의 게시가 확인돼야 다음 계정 및 메시지로 넘어가며 재시도 중 차례와 후속 진행을 유지한다.

설정·도움말의 **발송 재시도**에서 0~5회로 정한다. 기본은 5회(최초 요청 포함 최대 6회)이며 새로 준비하는 시도부터 적용한다. 기존 알림·기록 보존 설정과 독립적으로 저장하며 업데이트 뒤 유지한다.

Enter 이벤트의 취소 여부와 당시 문서 활성·숨김 상태를 결과 진단으로 전달한다. 이벤트가 취소됐다는 사실을 실제 게시 성공으로 표시하지 않는다. 관리 프로그램과 각 브라우저 확장을 모두 0.4.12로 업데이트한다. 기존 미확인 시도는 업데이트만으로 자동 재발송하지 않는다.


## 0.4.13 발송 후 실제 제한 관측과 다음 주기 보정

기존 content는 발송 후 제한 해제를 관측했지만 중앙 확장의 background는 `DICO_TIMING_SAMPLE`을 수신 확인만 하고 버리고 있었다. 실제 측정 결과가 중앙의 다음 발송 주기에 반영되지 않는 누락을 연결했다. 이미지의 Discord 잔여 제한 71초와 중앙 입력 준비 69초는 입력 준비 선행 5초와 여유 3초를 적용하면 정상인 2초 차이일 수 있으며, 그 이미지 자체를 시간 오차의 증거로 단정하지 않는다.

- 같은 계정·채널에서 게시가 확인된 시도만 보정한다. 첫 3개의 유효한 양수 잔여 제한 관측으로 전체 제한 주기를 추정해 5초 전 입력 준비 전에 반영하고, 가능한 경우 실제 제한 해제도 관찰한다. 절전·시계 변화·계정·입력창 변경·숫자 파싱 실패는 보정하지 않는다.
- 기본 주기는 `슬로우 모드 + 3초`이고, 보정된 기본값은 명목 기본값과 실측 해제 시각에 3초를 더한 값 중 큰 값이다. 사용자 지정 주기는 `보정된 기본값 + max(0, 사용자 설정값 - 명목 기본값)`이다. 예를 들어 명목 63초, 보정 기본 67초, 사용자 설정 70초이면 적용 주기는 74초다.
- 측정은 같은 content의 단조 경과 시간을 사용한다. 발송 확인을 기다린 시간을 주기에 다시 더하지 않도록 중앙의 확인 수신 시각에서 검증된 확인 지연을 제외한 기준으로 다음 기한을 계산한다. 전송 지연은 보수적으로 남겨 서로 다른 PC 시계를 직접 빼지 않는다.
- 보정값과 기준은 계정·채널별로 보관하고 재시작 시에도 지난 시간을 반영한다. 과거 세션·이전 게시·변경된 구성의 관측을 현재 주기에 적용하지 않는다. 보정이 새로운 발송을 시작하거나 게시 확인 전 차례를 넘기지는 않는다. 발송 직전 실제 제한 확인은 계속 수행한다.
- 대시보드 상세와 채널 설정에 기본·실측 보정·직접 추가·적용 주기를 표시하고, 입력 준비 시간이 실제 발송 제한과 다른 기준임을 설명한다.

관리 프로그램과 각 브라우저 확장을 모두 0.4.13으로 업데이트한다. 새 `COOLDOWN_SAMPLE` 네이티브 통신 타입을 호스트 허용 목록에 추가하고 실제 프레임 경계를 통과하는 회귀 검사를 포함한다. 실제 Discord 메시지를 추가로 보내거나 운영 DB를 변경하지 않고 가상 응답으로 검증한다.


## 0.4.14 비개발자 전달 패키지와 기존 설치 확인

- 새 컴퓨터의 OS·CPU 확인부터 기존 프로그램·확장 설치 확인, macOS 설치, Chrome·Brave별 확장 로드, 계정·채널·메시지·그룹 설정 및 첫 실행까지 안내하는 오프라인 HTML 문서를 추가했다.
- 배포본의 `check-installation.command` / `.cmd`는 설치·부분설치·데이터만 남은 경우를 읽기 전용으로 구분한다. 운영 DB를 열거나 서비스를 시작·종료하지 않는다. 브라우저 파일 존재와 네이티브 연결 등록은 실제 확장 연결과 구분한다.
- `open-manager.command` / `.cmd`는 설치된 프로그램을 실행하거나 실행 중인 프로그램의 관리 화면을 연다. 설치되지 않았다면 설치 안내를 표시한다.
- 런타임과 함께 npm을 포함하고 배포 메타데이터에서 개발자 PC의 npm 절대경로를 제거했다. Git은 별도 설치가 필요한 앱 내 업데이트 도구이며 최초 macOS 패키지 실행의 필수 조건은 아니다.
- 실제 제작 패키지는 macOS Apple Silicon용이다. Windows x64는 C++ Build Tools가 필요한 소스 준비 경로를 따로 안내하며, Mac 패키지를 Windows용 실행 파일로 안내하지 않는다.

관리 프로그램 0.4.14 / 확장 0.4.13. 개인 데이터·계정·메시지·세션은 전달 파일에 포함하지 않는다. 실제 사용자 설치·실제 Discord 추가 발송 없이 임시 환경의 검사 테스트 및 배포 구성 검증으로 확인한다.

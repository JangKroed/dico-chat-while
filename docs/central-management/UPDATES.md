# 업데이트 사용 방법 (0.4.9)

## 평소에는 중앙 페이지에서 한 번

1. 실행 중인 그룹을 중지하거나 일시정지합니다. 진행·미확인 결과와 중지 응답 대기를 먼저 처리합니다.
2. 설정·도움말 → **업데이트 실행**을 누릅니다.
3. 새 소스 다운로드 → 의존성 준비 → 빌드·검사 → 안전 상태 재확인 → 프로그램 적용 순서가 표시됩니다. 기존 탭은 재연결을 기다립니다.
4. 같은 주소의 기존 탭이 다시 연결되면 완료 상태와 브라우저 연결을 확인합니다. 설정 화면에서 실행한 업데이트는 같은 탭에서 화면을 갱신합니다. 다른 편집 화면은 초안을 보존하도록 갱신 안내를 표시할 수 있습니다. 그룹은 자동 재개되지 않습니다.

기존 개발 폴더에서 git pull·빌드·설치 명령을 반복할 필요가 없습니다. 고정 저장소 `JangKroed/dico-chat-while`의 main을 별도 작업 폴더에 받습니다. 기존 클론, DB, 설정과 실행 기록은 보존합니다. Git과 npm은 최초 소스 설치 때 준비된 것을 재사용합니다. 도구가 없으면 어떤 도구가 필요한지 표시합니다.

## 확장을 매번 새로고침하지 않는 방식

실행 중인 확장 빌드 ID와 설치 폴더의 실제 파일 해시를 비교합니다. 확장 파일이 같으면 재로드하지 않습니다. 바뀌었으면 모든 그룹과 로컬 실행기가 유휴 상태일 때 각 브라우저가 `chrome.runtime.reload()`로 자체 재시작합니다. Chrome·Brave 프로필이 닫혀 있으면 다음 실행·연결 때 확인합니다.

콘텐츠 스크립트도 안전한 전송용 탭에서 버전을 검사해 다시 연결합니다. 초안을 삭제하거나 Discord 탭을 강제로 새로고침하지 않습니다. 구버전 콘텐츠 스크립트는 최초 한 번 직접 탭을 새로고침해야 할 수 있습니다. 새 버전이 확인되지 않으면 같은 목표 빌드에 대한 재로드를 반복하지 않고 로드 폴더 확인을 안내합니다.

## 0.4.0·0.4.1에서 최초 한 번 전환

기존 버전에는 업데이트 버튼과 자동 재로드 코드가 없으므로 이번 0.4.2 전환만은 기존 설치 절차가 필요합니다.

1. 현재 그룹을 중지하고 미확인 결과·중지 응답을 확인합니다.
2. 관리 프로그램을 정상 종료합니다. 관리 페이지의 ‘전체 중지’는 프로세스 종료와 다릅니다.
3. 최신 소스를 받은 폴더의 `setup.command`(macOS) 또는 `setup.ps1`(Windows)을 실행합니다. 자세한 도구 준비와 실행은 [클론 설치 문서](CLONE-SETUP.md)를 참고하세요.
4. 각 브라우저의 관리 확장 경로가 아래 **설치된 app/extension**인지 한 번 확인하고 확장을 새로고침합니다.
5. 필요한 초안을 따로 보관하고 기존 Discord 탭을 한 번 새로고침한 뒤 연결을 확인합니다.

| OS | 관리되는 확장 폴더 |
| --- | --- |
| macOS | `~/Library/Application Support/DICO/app/extension` |
| Windows | `%LOCALAPPDATA%\DICO\app\extension` |

클론의 `central/extension`이나 옛 패키지 폴더를 로드했다면 앱 업데이트가 그 폴더를 바꾸지는 않습니다. 기존 확장을 무작정 삭제하지 말고 현재 로드 경로를 먼저 확인하세요. 관리 경로 이전은 최초 한 번 필요하며, 이후 그 경로를 유지합니다. 브라우저가 새 권한 승인을 요구하거나 확장을 비활성화한 경우에는 브라우저에서 처리해야 합니다.

## 실패했을 때

다운로드·의존성·빌드·검사 실패 시 기존 설치를 바꾸지 않습니다. 적용 직전에 실행 상태가 바뀌어도 중단합니다. 교체 오류에서는 이전 JavaScript 파일을 복원하고, 시작 확인 실패 시 이전 파일을 보존하여 복구 가능한 상태를 남깁니다. 실패 원인과 다음 조치는 중앙 화면에 표시됩니다.

Windows 파일 잠금을 피하기 위해 Node와 네이티브 런처 실행 파일은 일반 업데이트에서 교체하지 않습니다. 더 높은 Node 버전이나 런처 변경이 필요한 릴리스는 전체 설치 도구를 사용합니다. 새 버전의 DB를 임의로 과거 DB로 덮어쓰지 않습니다.

## 검증 범위

자동 테스트는 임시 설치 폴더에서 안전 상태·출처 고정·CSRF/작업 인증·중복 실행·교체 복구·확장 재로드 제한을 검사합니다. 실제 사용자 프로그램 설치, 실제 Chrome/Brave 확장 재로드, Windows 실기기 업데이트와 Discord 발송은 별도 인수 검사가 필요합니다.

## 주소와 탭 유지 (0.4.4부터)

설치별 포트를 기록해 프로그램 재시작·업데이트 때 재사용합니다. 신규 설치 기본은 `http://127.0.0.1:43127`이고 기존 설치는 사용할 수 있는 기존 포트를 유지합니다. 포트가 다른 프로그램에 점유되면 임의 주소로 바꾸지 않고 오류를 안내합니다.

일반 업데이트는 브라우저를 새로 열지 않습니다. 유효한 UI 세션은 개인 저장 파일에 기존12시간 정책 안에서 보존되며 같은주소·같은탭에서 재연결합니다. 만료된 인증을 자동으로 우회하지 않습니다. 세션 파일은 백업이나 확장으로 내보내지 않습니다.

기존0.4.3 이하 worker는 새창을 여는 코드와 메모리 전용 세션을 사용하므로,0.4.4 최초 전환은 새 화면이나 최초 인증이 한 번 필요할 수 있습니다.0.4.4가 시작하는 다음 업데이트부터 기존탭 유지가 적용됩니다. 확장0.4.2 코드는 바뀌지 않습니다.

## 0.4.4 표시·진단 보강

대시보드에서 채널별·계정별 간격 충족까지 남은 시간을 매초 표시합니다. 이는 중앙에서 계산한 실행 조건의 예상 시각이며 실제 게시 완료 시각은 아닙니다. 연결이 끊기거나 미확인 발송이 있으면 숫자 대신 확인할 상태를 표시합니다.

직접 지정한 계정 표시 이름을 실행 기록 목록·상세와 대시보드·그룹·문제 안내에 공통 적용합니다. 같은 계정 ID라도 브라우저별로 등록한 이름을 구분합니다.

이번 버전은 발송 결과 진단 보강 때문에 확장도 변경됩니다. 관리 프로그램 업데이트 후 각 브라우저의 확장 업데이트 안내를 확인하세요. 미확인 시도는 먼저 실제 Discord 게시 내역과 실행 차단을 확인해 결과를 확정해야 합니다. 상세 절차는 `DELIVERY-TROUBLESHOOTING.md`를 참고하세요.

### 실제 Discord 제한 상태 확인

`early-prepare-v1`을 지원하는 최신 확장은 다음 예정 시각의 약 5초 전부터 문구를 준비합니다. 현재 차례만 준비하며 다른 계정의 차례를 앞당기지 않습니다. 준비 후에는 같은 초안과 계정·채널을 유지한 채 실제 Discord의 남은 제한 시간을 반복 확인합니다. 예정 시각과 제한 해제 모두 충족해야 전송 허가가 발급됩니다. Enter 직전에도 다시 검사합니다.

제한 표시를 읽을 수 없으면 0초로 간주하지 않습니다. 연결·초안이 바뀌거나 준비 대기가 2분을 넘으면 중단해 확인하도록 합니다. 허가 후 새 제한이 감지된 경우에는 Enter를 누르지 않고 그룹을 일시정지해 차례를 유지합니다. 초기 실행처럼 5초의 준비 여유가 없는 경우는 입력 준비가 끝난 뒤 확인 절차를 수행합니다.

## 0.4.5 대시보드 진행 문구 수정

중지된 그룹에서는 남아 있는 쿨다운과 무관하게 계정 행에 `중지됨`을 표시합니다. 일시정지 상태는 `일시정지됨`으로 표시합니다. 실행 중인 그룹의 현재 차례 계정만 `입력 준비까지 약 N초`를 표시하고 다른 계정은 `차례 대기`를 표시합니다. 입력 준비 시간은 해당 그룹의 다음 허가 예정 시각에서 최신 확장의 사전 입력 5초를 뺀 시각입니다. 다음 계정의 개인 쿨다운을 실제 입력 예정 시각으로 표시하지 않습니다.

입력 후에는 `입력 준비 완료 · 발송 대기`, `Discord 제한 해제 대기`, `발송 확인 중`을 표시합니다. 기존 미확인 발송은 중지 여부와 별개로 실제 게시 여부 확인이 필요하다는 표시를 유지합니다. 이번 변경은 중앙 화면에만 적용되며 확장 빌드는 0.4.4를 유지합니다.

## 0.4.6 브라우저마다 전송 창 하나로 관리

- Brave에 채널 3개를 연결하면 최소화된 전송용 창 1개에 탭 3개를 둡니다. Chrome과 다른 브라우저 프로필은 각각 별도로 관리합니다.
- 이미 여러 창으로 나뉘어 있다면 해당 브라우저의 모든 그룹을 중지하고 미확인 결과를 확인한 뒤, 계정·브라우저 화면의 `전송 창 모으기`를 누르세요. 기존 탭을 이동하며 페이지를 새로고침하거나 초안을 지우지 않습니다. 일반 탐색 탭은 옮기지 않습니다.
- 대시보드·채널 설정·실행 기록·문제 알림의 `전송 창 보기`는 연결된 기존 채널 탭을 선택해 창을 앞으로 가져옵니다. `전송 창 숨기기`는 해당 브라우저의 전송용 창 전체를 최소화합니다. 보기 동작은 메시지를 발송하지 않습니다.
- 전송용 창이나 브라우저를 종료하면 자동 실행할 수 없습니다. 최소화 상태로 유지하세요. 백그라운드 절전이나 Discord 화면 변경으로 검증하지 못할 때는 발송을 차단합니다.
- 여러 관측 요청을 직렬화·병합하고 채널별 읽기는 병렬화해 오래된 결과가 새 결과를 덮는 문제를 줄였습니다. 로딩·화면 읽기 실패·닫힌 탭·실제 계정 불일치를 구분합니다.
- 장애 이후 현재 세션에서 정상 계정·채널을 다시 확인하면 관련 연결 알림을 해결합니다. 게시 여부 미확인 시도와 수동 재개가 필요한 그룹은 자동 재개하지 않습니다.

관리 프로그램과 각 브라우저 확장을 0.4.6으로 업데이트한 뒤 사용합니다. 운영 중인 창을 자동으로 이동시키지 않으며 창 모으기는 사용자가 요청한 경우에만 수행합니다.

## 0.4.7 대기·초안·설정 보존과 화면 테마

- 상세창이 데스크톱 화면보다 길어지면 창 내부를 스크롤합니다. 키보드와 터치 스크롤도 지원합니다.
- 발송 직전 실제 Discord 쿨다운이 남으면 같은 발송 시도·계정·초안·그룹 순서를 유지하며 기다립니다. 제한 해제 뒤 입력 안정 상태와 최신 중앙 승인을 다시 확인한 후 Enter를 한 번 시도합니다. 실제 게시가 확인돼야 다음 계정으로 넘어갑니다. 기다리는 동안 중지·계정·초안 변경이나 연결 유실이 있으면 차단합니다.
- 정상 관측 중인 긴 쿨다운은 30초 결과 타임아웃으로 종료하지 않습니다. 최대 지원 관측 대기는 6시간 30초이며, 관측 유실과 절전·시계 변화는 기존 안전 검사로 중단합니다. 이미 Enter를 시도한 미확인 시도에는 Enter를 다시 보내지 않습니다.
- 입력창 문구가 예정 문구와 같으면 붙여넣지 않고 그대로 사용합니다. 다른 일반 텍스트 초안은 브라우저에 먼저 보관하고, 원문이 바뀌지 않은 경우에만 예정 문구로 교체합니다. 보관 실패·첨부·답장·해석할 수 없는 입력은 교체하지 않습니다. 보관 원문은 확장 사이드패널의 ‘교체 전에 보관한 초안’에서 볼 수 있습니다. 같은 발송 ID와 미확인 시도의 중복 전송을 막으며, 사용자가 지정한 반복 메시지 자체를 과거 본문과 같다는 이유로 금지하지 않습니다.
- 설정 초기 렌더링에 저장값을 사용하고, 알림·기록 보존의 편집값을 별도로 유지합니다. 한 항목 저장이나 업데이트 재연결이 다른 항목의 미저장 편집을 덮어쓰지 않습니다. 미저장 설정이 있으면 자동 화면 새로고침 대신 업데이트 안내를 표시합니다. 저장된 SQLite 설정이 재시작으로 초기화되는 현상은 재현되지 않았습니다.
- 저장된 계정과 닫힌 전송용 채널 탭을 재연결 시 자동 복구합니다. 실제 계정 확인과 기존 실행기 중지 확인이 필요하며, 미확인 발송이 있거나 기존 탭이 다른 채널이면 자동 교체하지 않습니다. 대시보드의 ‘자동 연결 진행 상황’에서 브라우저 연결 → 계정 확인 → 채널 확인 → 설정 적용을 확인합니다. 발송 시작은 별도 실행 요청이 필요합니다.
- 설정·도움말에서 시스템·라이트·다크 테마를 선택합니다. 기본은 시스템이며 OS 테마 변경을 반영합니다. 직접 고른 테마는 같은 브라우저에서 업데이트 뒤에도 유지합니다.

검증 범위: 자동 시험과 UI 빌드. 격리된 Chrome 실행 실패로 실제 브라우저 스크롤·다크 화면·Discord 게시의 최종 확인은 완료하지 못했습니다. 이번 이미지의 Enter 시도 후 초안 잔류는 쿨다운이 원인이라고 확정할 증거가 없으므로, 신규 대기 경로 개선과 기존 미확인 결과 처리를 구분합니다.

## 0.4.8 UI/UX와 두 테마 정리

- 대시보드는 현재 운영 요약과 문제를 먼저 표시한다. 정상 연결의 세부 절차는 접고, 브라우저별 요약과 계정 별칭으로 구분한다. 단계는 완료·진행 중·대기를 구분하며, 실행 차단 사유는 별도로 표시한다.
- 연결이 끊긴 브라우저에 자동 생성 이름인 ‘연결된 Chrome’이 남아 현재 연결 상태처럼 읽히지 않도록 표시 이름을 정리한다. 사용자가 지정한 이름은 보존한다.
- 화면별 다크 색상 덧칠을 공통 색상 토큰으로 교체했다. 본문·보조 문자·진단 안내·입력·표·상태·포커스·비활성 버튼을 두 테마에서 함께 관리한다. 보조 문자는 최소 12px, 일반 본문과 입력은 13px 이상을 기준으로 조정했다.
- 마지막 갱신은 실제 수신 시각을 사용한다. 선택 기간의 분석 조회 실패를 0건이나 다른 기간의 집계로 대체하지 않는다.
- 편집 중 페이지 이동·선택 변경에서 초안 보호를 보강하고, 모달 Tab 순환·Escape 닫기·포커스 복귀와 모바일 메뉴의 기본 키보드 처리를 추가했다.
- 이번 변경은 중앙 화면에 적용되며 확장 버전은 0.4.7을 유지한다. 관리 프로그램 업데이트로 적용한다.

리뷰와 검증 범위는 `UIUX-REVIEW-2026-11-02.md`에 기록했다. 자동 시험·React 서버 렌더 검사·색상 조합 검증은 실행했으나, 격리된 Chrome 시작 실패로 실제 브라우저의 반응형·키보드·시각 검증은 완료하지 못했다.

## 0.4.9 네이티브 통신 연결 회귀 수정

0.4.7에서 추가한 `CONNECTION_PROGRESS`, `RECOVERY_STATUS`, `DELIVERY_WAIT`를 네이티브 호스트의 통신 허용 목록에 누락했다. 중앙 코어는 처리할 수 있었지만 네이티브 호스트가 먼저 거절해, 최초 연결 성공 뒤 자동 복구 보고 단계에서 끊기는 문제가 발생했다. 이 수정은 세 메시지를 명시적으로 허용하며 등록 확장 출처·비밀 필드·프레임 크기·미지원 메시지 차단은 유지한다.

기존 코어·실행기 통합 시험은 이 네이티브 경계를 생략해 누락을 잡지 못했다. 모든 실제 확장 요청 타입의 통과 계약 검사와, 실제 네이티브 프레임 → 로컬 HTTP → 중앙 상태를 연결한 자동 복구·쿨다운 회귀 검사를 추가했다. 대기 중 같은 시도와 메시지 순서를 유지하고, 허가 차단·해제, 알 수 없는 메시지 거절 후 정상 세션 유지까지 검사한다. 실제 Discord 메시지는 보내지 않는다.

관리 프로그램만 0.4.9로 업데이트하면 된다. 확장 버전은 0.4.7 유지가 정상이다. 업데이트 뒤 기존 호스트 연결이 닫히고 새 호스트로 자동 재연결될 때까지 약 30초 기다리거나, 각 확장의 `연결 도움말 · 다시 확인 → 관리 프로그램 다시 연결`을 누른다. 계정·채널을 삭제하거나 다시 만들 필요는 없다. 이번 수정은 기존 그룹을 자동 실행하지 않는다.

진단 시 실제 DB를 읽기 전용으로 확인한 결과 계정 3개·채널 8개가 남아 있었고 최근 이벤트 90개에서 연결/해제가 각각 44번 반복됐다. 설치된 0.4.8 호스트에도 세 타입이 없는 것을 확인했다. 운영 DB와 실행 상태는 수정하지 않았다.

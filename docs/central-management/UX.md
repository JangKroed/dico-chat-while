# 중앙관리 화면별 UI/UX 명세

## 1. 공통 화면 구성

PC 브라우저가 주 사용 환경이다. 1280px 이상에서는 왼쪽 메뉴, 위쪽 상태·전역 행동, 중앙 작업 영역을 사용한다. 768~1279px에서는 메뉴를 축약하고 상세는 서랍으로 연다. 767px 이하에서는 메뉴 버튼과 카드 목록으로 바꾸며 모바일 외부 접속 기능을 의미하지 않는다. PC에서 창을 좁혀도 사용할 수 있게 한다.

상단에는 `DICO`, 관리 프로그램 연결 상태, 최근 상태 수신 시각, 미해결 문제 수와 알림 센터, `전체 중지`를 유지한다. 전체 중지는 메뉴 깊숙이 숨기지 않는다. 중앙 페이지가 여러 개 열려도 같은 상태를 구독하고, 탭마다 별도 실행 엔진을 만들지 않는다.

색상만으로 상태를 구분하지 않는다. 텍스트·아이콘·설명을 병행하고 키보드 포커스, 레이블, 오류 연결, 대화상자 포커스 복원을 제공한다. 순서 변경에는 드래그와 함께 `위로`·`아래로` 버튼을 제공한다. 시간은 사용자 OS 시간대와 초 단위로 표시하고 기록 상세에는 시간대도 표시한다.

권장 메뉴 순서는 `대시보드 → 메시지 보관함 → 채널·브라우저 → 발송 그룹 → 실행 기록 → 로그·분석 → 설정·도움말`이다. 첫 설정 중에는 단계 안내가 메뉴보다 먼저 보인다.

## 2. 처음 시작과 튜토리얼

### 시작 화면

서비스가 실행 중이지만 데이터가 없으면 `첫 발송을 준비해 볼까요?`와 프로그램 준비 이후의 5개 설정 단계(브라우저 연결, 채널 연결, 메시지 준비, 채널 적용, 그룹 만들기)를 보여준다. 기본 행동은 `브라우저 연결하기`, 보조 행동은 `기존 설정 가져오기`다. 비어 있는 통계 차트를 먼저 보여주지 않는다.

각 단계에는 현재 상태, 해야 할 행동, 완료 판정, 뒤로 가기, 나중에 하기, 문제 해결이 있다. 입력된 내용은 단계 이동 전에 저장하고 오류 시 해당 필드에 표시한다.

| 단계 | 화면과 핵심 행동 | 완료 판정 |
| --- | --- | --- |
| 프로그램 준비 | 서비스 실행 여부와 자동 시작 선택 | 로컬 서비스가 응답하고 저장소 검사 통과 |
| 브라우저 연결 | Chrome·Brave 설치 안내, 확장에서 `연결` | 해당 확장의 인증된 연결 이벤트 수신 |
| 채널 연결 | Discord 채널 열기 → 확장에서 `이 채널 연결` | 계정·서버·채널 검증 후 중앙 등록 |
| 메시지 준비 | 이름·본문 작성 → `보관함에 저장` | 메시지 버전 저장 완료 |
| 채널 적용 | 대상 채널·문구·순서 선택 → `채널에 적용` | 연결 채널의 적용 버전 저장 완료 |
| 그룹 만들기 | 참여 계정·순서·간격 지정 → 요약 | 실행 전 검사 통과; 자동 시작하지 않음 |

브라우저 확장을 웹페이지에서 강제로 설치하거나 OS 권한을 자동 허용했다고 표시하지 않는다. 확장 미설치, 호스트 미설치, 권한 거절, 미지원 브라우저를 서로 다른 문제로 안내한다.

## 3. 대시보드 `/`

위에서 아래 순서는 다음과 같다.

1. **확인할 문제:** 미확인 발송, 연결 끊김, 저장 오류, 중지 확인 대기. 원인과 영향을 받는 그룹·계정을 함께 표시.
2. **요약:** 실행 중 그룹, 대기 그룹, 연결된 브라우저/전체, 오늘 게시 확인 수. 시도 수를 성공 수로 세지 않음.
3. **발송 그룹 목록:** 운영의 중심. 각 그룹에서 계정 순서, 현재 상태, 다음 행동을 바로 확인.
4. **최근 활동:** 게시 확인, 그룹 시작/중지, 메시지 적용, 연결 변경. 전체 기록으로 이동.

그룹 목록 아래에는 시간대별 게시 확인 막대와 계정별 발송 타임라인을 제공한다. 상태 분포·지연 추이·대기 원인·연결 상태는 분석 보기로 펼친다. 각 차트는 같은 필터의 원본 기록으로 연결한다. 상세 배치와 집계 기준은 [로그·그래프·알림 명세](OBSERVABILITY.md)를 따른다.

그룹 목록의 기본 열은 다음과 같다.

| 그룹·채널 | 상태 | 현재·다음 차례 | 메시지 | 다음 진행 | 행동 |
| --- | --- | --- | --- | --- | --- |
| 모집방 순환 / 서버1 #모집 | 간격 대기 | A 완료 → B → C | B: 거래 안내 v3 | 최소 12초 뒤 조건 확인 | 일시정지 · 상세 |
| 공지방 / 서버2 #공지 | 확인 필요 | A 결과 미확인 | 모집 안내 v2 | 게시 여부 확인 필요 | 결과 확인 |
| 안내방 / 서버3 #안내 | 중지됨 | 다음 C | 안내 v1 | — | 시작 · 상세 |

숫자와 계정명은 예시다. `최소 12초`는 실제 남은 중앙 간격이며 이후의 슬로우 모드·연결 검사로 더 늦어질 수 있음을 상세에 표시한다. 연결 상태가 오래되면 카운트다운을 멈추고 `상태 갱신 중`으로 바꾼다.

행 상세 서랍에는 참여 순서, 각 브라우저 연결, 현재 적용 목록, 마지막 게시, 미확인 시도, 최근 오류, 다음 가능한 행동을 표시한다. 시작/중지 버튼 옆에 영향 범위를 명확히 쓴다.

## 4. 메시지 보관함 `/messages`

좌측은 검색·태그·상태 필터와 메시지 목록, 우측은 선택 메시지의 편집·미리보기 영역이다. 폭이 좁으면 목록과 상세를 화면 이동으로 나눈다.

목록은 이름, 태그, 마지막 수정, 사용 중 채널 수, 보관 상태를 표시한다. 새 메시지와 복제를 주요 행동으로 제공한다. 편집기는 이름, 태그, 본문, 글자 수, 유효성 오류, `수정본 저장`을 제공한다. 미저장 상태에서 이동하면 저장·계속 편집·변경 버리기를 선택한다.

상세에는 `편집`·`미리보기`·`사용 중인 채널`·`버전 이력`을 둔다. 최신 수정본과 각 채널의 적용본이 다르면 어떤 버전을 사용하는지 표시한다. 메시지 수정으로 전체 채널이 자동 갱신된다는 인상을 주지 않는다.

### 채널에 적용 대화상자

1. 연결된 채널 검색 및 대상 선택. 기본은 선택 없음; 채널에서 진입한 경우 해당 채널만 미리 선택.
2. 메시지 버전과 채널별 목록·순서 확인. 추가/교체를 구분하고 조용히 덮어쓰지 않음.
3. 영향 요약: 대상 채널, 변경 전/후 목록, 새 목록 첫 문구부터 사용, 진행 중 시도 보존, 미확인 발송으로 막힌 채널.
4. `선택한 N개 채널에 적용`. 일부가 적용 불가하면 이유를 표시하고 가능한 채널에만 적용할지 명시적으로 선택.

적용 완료는 중앙 설정 저장, 확장 수신, 확장 실제 적용을 구분한다. 연결이 끊긴 경우 `중앙에 저장됨 · 브라우저 수신 대기`, 수신 ACK만 받은 경우 `수신됨 · 적용 대기`, 적용 ACK와 버전 일치를 확인한 뒤 `적용 완료`로 표시한다. 최신 구성을 적용하지 못한 확장에는 신규 발송을 허가하지 않는다.

### 삭제·보관

사용 중인 문구의 삭제 메뉴는 영향을 받는 채널 목록을 열고 `보관하기`·`채널 설정 변경`을 제공한다. 영구 삭제가 가능한 항목만 명시적 확인 후 삭제한다. 삭제 실패가 편집 중인 본문을 지우지 않도록 한다.

## 5. 채널·브라우저 `/connections`

상단은 브라우저 연결 카드다. 카드에는 표시 이름, 브라우저 종류(확인 가능한 경우), 연결/재연결/끊김, 확장 버전, 마지막 응답, 확인된 Discord 계정을 표시한다. 실제 프로필 이름을 읽지 못하면 사용자가 지정한 이름만 사용한다.

카드 아래 연결 채널 목록은 서버·채널, 계정, 메시지 목록 요약, 적용 버전, 소속 그룹, 검증 상태를 보여준다. 계정이 없는 연결을 정상 준비 상태로 표시하지 않는다.

채널 상세는 `연결 정보`·`메시지 선택`·`전송 제한`·`최근 결과`로 구성한다. 문구 선택 화면에서 보관함의 여러 메시지를 선택·정렬하고 각 버전을 미리 볼 수 있다. 새 메시지가 필요하면 편집을 잃지 않고 보관함 작성으로 이동한다.

`연결 해제`는 영향받는 채널과 그룹을 먼저 표시한다. 진행/미확인 발송이 있으면 단순 삭제 대신 중지·확인 절차로 이동한다. 브라우저가 종료됐다는 이유로 저장 메시지를 지우지 않는다.

## 6. 발송 그룹 `/groups`

생성 순서는 `대상 Discord 채널 → 참여 연결 계정 → 계정 순서 → 간격 → 실행 전 요약`이다. 해당 채널에 연결되지 않은 계정은 선택할 수 없고 `먼저 채널 연결` 안내를 제공한다.

순서 편집에는 계정명·브라우저명·적용 메시지 수·검증 상태를 표시한다. 최소 한 계정으로 만들 수 있다. 그룹 간격과 계정별 최소 주기는 이름을 달리하고 도움말 예시로 차이를 설명한다. `20초` 같은 설정을 확정적인 실제 발송 주기로 광고하지 않는다.

### 실행 전 요약

확인 항목은 대상 서버·채널, 계정 순서, 각 계정의 다음 문구와 버전, 그룹 간격, 계정별 대기, 연결 상태, 권한·계정 검증, 중복 실행 여부, 미확인 발송 유무다. 차단 사유가 있으면 시작 버튼을 비활성화하고 해당 설정으로 이동하는 행동을 제공한다. `설정 완료`와 `실행 시작`은 다른 버튼이다.

실행 중 구조 변경 시 `진행을 일시정지한 후 수정`을 제공한다. 일시정지 요청 중에는 완료된 것처럼 편집 가능 상태로 바꾸지 않는다. 그룹마다 현재 순서와 문구 위치를 명시하고 초기화는 정지 상태에서만 제공한다.

## 7. 실행 기록과 결과 확인 `/history`

필터는 기간, 그룹, 브라우저·계정, 채널, 상태다. 기본 표는 예정 시각, 실제 시도 시각, 게시 확인 시각, 계정·채널, 메시지 이름·버전, 결과를 보여준다. 게시 시각은 근거가 있을 때만 별도 표시하고 PC 관측 시각과 혼동하지 않는다.

상세에는 상태 전이와 근거(허가 ID, 구성 버전, 게시 확인 ID, 지연 사유)를 보여준다. 기본 화면에 토큰·파일 경로·내부 예외 스택을 노출하지 않고 진단 상세에서 필요한 범위만 보여준다.

미확인 발송에는 문구·계정·채널·시도 시각·관측 결과와 `다시 확인`을 제공한다. 게시가 확인되면 완료 보고를 재시도하며, 새 메시지를 보내는 버튼으로 연결하지 않는다.

수동 확인에는 `실제 게시됨`과 `실제 미발송`을 사용한다. 후자는 이전 전송이 더 이상 실행될 수 없다는 확인 절차가 선행돼야 하며, 증거가 불충분하면 활성화하지 않는다. 이미 확인한 결과와 반대 결과를 선택할 수 없다.

## 8. 설정·도움말 `/settings`

설정 구획은 프로그램 실행, 알림, 데이터·백업, 연결·버전, 업데이트, 문제 해결로 나눈다. IP·포트·토큰·확장 ID 입력은 일반 설정에서 제공하지 않는다. 개발용 수동 연결은 일반 튜토리얼과 분리한 진단 전용 경로다.

알림 설정에는 유형별 OS 알림, 내용 숨김, 반복 간격, 방해 금지, 회복 알림, 지연 경고 기준, 테스트 알림을 둔다. 권한을 거절해도 화면의 알림 센터와 미해결 문제 표시는 유지한다. 튜토리얼 마지막에 대시보드·로그 읽기와 테스트 알림을 안내한다.

튜토리얼에는 설치·추가 브라우저 연결·메시지 적용·순환 설정·중단 복구가 있다. 실제 연결 상태를 읽어 완료 여부를 계산하고 단순 스크린샷 따라 하기만으로 완료 표시하지 않는다.

백업 복원은 파일 검사 → 기존 작업 확인 → 가져올 항목과 중복 처리 미리보기 → 정지 상태로 복원 → 재연결 안내 순서다. 복원 파일로 연결 키나 활성 허가를 되살리지 않는다.

### 연결 상태 표시 기준 제안

평상시 5초 간격 상태 보고, 15초 미수신 시 갱신 지연, 30초 미수신 시 연결 끊김으로 표시한다. 이는 UI 진단 기준이며 허가 만료나 차례 넘김 기준이 아니다. 실제 주기는 절전·브라우저 부하 시험 후 조정한다. SSE 단절을 감지하면 즉시 화면에 알리고 지난 카운트다운을 최신 상태로 가장하지 않는다.

## 10. 화면 검증 체크리스트

- 새 사용자, 연결만 완료, 메시지만 작성, 미연결 채널, 작업 실행, 미확인 발송, 서비스 종료 등 각 상태를 재현한다.
- 창 크기 1440/1024/768/390px에서 버튼·문구·오류가 잘리지 않는다.
- 키보드만으로 메시지 작성, 채널 선택, 순서 변경, 일시정지, 대화상자 닫기를 완료한다.
- 여러 탭에서 편집 중 외부 변경이 와도 입력 내용을 조용히 덮어쓰지 않는다.
- 중지/적용 응답을 지연시켰을 때 요청 중 상태와 실제 완료를 구분한다.
- 한 계정은 대기, 한 계정은 끊김, 다른 그룹은 실행 중인 복합 상황을 대시보드에서 구분한다.
- 계정 A/B/C와 문구 A/B를 혼용하지 않고 문구는 이름으로 표시한다.
- 튜토리얼에서 실제 발송이 일어나는 최초 행동은 명시적인 시작 버튼뿐이다.

## 11. 로그·분석 및 알림 센터

`/logs`에 현재 문제·분석·전체 로그 보기를 둔다. 필터, 실시간 보기, 새 로그 수, 행 상세·내보내기를 제공한다. 읽는 중 새 이벤트가 스크롤을 밀지 않도록 하고, 차트는 표 보기로도 제공한다. 상단 알림 센터는 모든 화면에서 열리며 사건별 읽음·미해결·해결을 구분한다. OS 알림 클릭도 같은 사건 상세로 이동한다. 전체 동작과 문구는 [로그·그래프·알림 명세](OBSERVABILITY.md)를 따른다.

# 제출 중계 보안 조사 계획

목표: 공개 제출 값의 권한을 분류하고 자동 오류 제보를 유지하면서 재현 가능한 위험을 줄인다.

- [x] 알림·main·도입 커밋·클라이언트 및 중계의 신뢰 경계 조사.
- [x] 합성 키/보고서와 MailApp 대역으로 할당량 소진, ID 충돌, 개인정보 옵션 우회, 저장소 한계 재현.
- [x] Central.gs: 공개 경로 하루 5건, 전체 20건, 비공개 설치 키용 잔여 용량; 요청 검증, 개인정보 필터, 내용과 키에 결합된 영수증, 저장 용량 상한.
- [x] support-report.mjs: 자유 텍스트의 명시적인 인증정보 패턴 제거. 알려지지 않은 문자열의 완전 탐지는 보장하지 않음.
- [x] support-delivery.mjs: QUOTA 응답의 제한된 재시도 시각 반영; 기존 전송 동의, 큐, 응답 유실 재시도 유지.
- [x] 기존/신규 회귀 테스트, 전체 테스트 및 빌드 검증 후 조사 보고서와 PR 작성.

운영 서비스에 공격 요청/실메일을 보내지 않는다. 공개 키 원문은 출력하지 않는다. 실제 Apps Script 속성/운영 로그는 조사 범위에서 확인되지 않았으며 코드 재현과 구분한다. 공개 키만 사용하는 기존 설치는 공격자와 구분할 수 없으므로 비공개 키 배포 전 완전한 가용성을 보장하지 않는다. 배포와 키 발급은 PR 반영과 별개다.

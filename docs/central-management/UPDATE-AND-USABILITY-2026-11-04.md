# 0.4.34 업데이트 및 사용자 흐름 개선

## 확인한 원인

- 0.4.33 배포 커밋의 중앙 프로그램 버전은 0.4.33이나 확장 manifest는 0.4.27이었다. 빌드가 확장 manifest 버전을 그대로 콘텐츠 코드에도 복사했다. 따라서 코드 갱신 여부와 별개로 이전 버전 표시가 남았다.
- 확장 재시작 호출 전에 성공과 구별되지 않는 표식을 저장하여 재시작 호출이 실패하면 같은 빌드의 다음 자동 시도도 차단되었다.
- 전체 프로그램 교체 안전 조건을 확장 교체에도 적용하고, 중지/관찰/복구 이후에만 업데이트를 확인하여 안전하게 차단된 작업에서도 갱신이 지연되었다.
- 설정의 브라우저 행은 긴 설명과 브라우저 이름이 한 flex 행의 폭을 경쟁하여 이름이 한 글자씩 줄바꿈되었다.
- 계정 삭제는 이미 완료되었으나 오프라인 브라우저의 후속 탭 정리 기록을 일반 화면의 미완료 작업처럼 표시했다.

## 변경 내용

중앙 package 버전을 확장 manifest와 콘텐츠 코드에도 반영한다. 실제 실행 중인 발송은 교체하지 않고, 실행 차단이 확인된 미확인 작업은 결과·잠금을 보존하면서 유지보수를 허용한다. 재시작 실패는 30초 간격 최대 3회로 제한해 자동 복구한다. 일반 발송의 정상 미발송 재시도와 업데이트 오류 복구의 제한은 별개 정책이다.

일반 화면에서 삭제 완료 대상의 후속 정리 기록을 제거한다. 진단 화면에는 기록을 유지하고 내부 삭제 표식으로 뒤늦은 브라우저 연결이 계정을 되살리지 않도록 한다.

브라우저 이름·버전·상태를 grid로 배치하고 긴 안내는 다음 행에 둔다. 작은 화면에서는 한 열로 전환한다. 대시보드는 운영 지표, 그룹별 진행, 최근 결과, 연결 상태를 함께 보여주며 전체 누적 실적으로 오인할 수 있는 수치를 만들지 않는다.

발송 재시도 횟수 옵션은 제거한다. 미발송이 확인되고 재시도 조건이 충족되면 중단 또는 실제 오류까지 계속하며, 결과가 불확실하면 재전송하지 않는다. 상세 정책은 CONTINUOUS-DELIVERY-2026-11-04.md를 따른다.

DICO 전용 아이콘을 중앙 확장 관리 목록과 도구 모음에 적용한다. 생성 원본을 16/32/48/128px PNG로 패키징하며 브라우저 권한이나 확장 ID는 변경하지 않는다. 디스크의 아이콘도 기존 빌드 지문 계산 대상에 포함된다.

## 검증 및 제한

회귀 테스트는 버전 불일치, 재시작 실패 재시도, 차단된 미확인 작업의 유지보수, 실제 실행 중 교체 차단, 횟수 상한을 넘는 정상 재시도와 중단을 검증한다. 격리된 실제 Chrome에서 일반 사용자 흐름과 1440/1000/390px의 데이터가 채워진 화면을 검사한다.

실제 수신자의 컴퓨터나 Discord 계정으로 발송하지 않는다. 브라우저·운영체제의 외부 권한 승인을 자동 우회하지 않는다. 전체 통합 검증 결과는 릴리스 보고에 기록한다.

### 통합 검증 기록

- 전체 테스트 1,147개 통과, 실패·건너뜀 0개.
- 중앙 UI TypeScript·Vite 빌드, 중앙/루트 문법·manifest·CSP 검사, 실제 React SSR 검사 통과.
- 격리 Chrome에서 1440/1000/390px 대시보드·설정 및 브라우저 행을 검증: 가로 넘침 0px, 콘솔 오류 0건. 1440px 그룹 행 약 78px, 최근 결과 영역 시작 약 697px.
- 마지막 독립 리뷰에서 업데이트 상태 조회 대기 중 발송이 시작되는 경쟁 조건을 추가 재현했다. 비동기 조회가 끝난 뒤 최신 작업 상태를 읽어 판정하도록 수정했다. 해당 회귀는 수정 전 실패, 수정 후 통과를 확인했다.

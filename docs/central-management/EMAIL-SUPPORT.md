# 중앙 관리 자동 이메일 제보

사용자는 기존 관리 화면의 업데이트를 사용한다. ZIP 재설치로 전환하지 않는다. 업데이트는 GitHub main 소스를 가져오므로 중계의 배포·전송 검증 후 연결 정보와 함께 main에 반영해야 한다.

## 흐름

동의한 사용자의 오류 발생 → 기존 영속 제보 큐 → Google Apps Script HTTPS → didlsdydgh@gmail.com. 사용자가 JSON 파일을 내려받거나 메일 앱을 열 필요가 없다. 중계가 진단 JSON을 자동 첨부한다. 발송 계정 비밀번호나 OAuth 토큰은 프로그램에 포함하지 않는다.

`mail-relay/Central.gs`는 중앙 관리 보고서 전용이다. 구형 확장의 `Code.gs`와 같은 Apps Script 프로젝트에 함께 넣지 않는다. Google MailApp의 메일 발송 권한만 사용하며 받은편지함 읽기 권한을 요구하지 않는다.

관리자는 스크립트 속성 REPORT_KEY를 설정하고, 웹 앱을 본인으로 실행하도록 배포한다. 외부 설치에서 로그인 없이 접수하려면 웹 앱 접근을 허용해야 한다. 수신자는 코드에 고정되어 있으며 클라이언트의 수신자 지정은 무시한다. REPORT_KEY는 배포 앱이 제출에 사용하는 키이므로 앱을 가진 사람에게 숨겨진 비밀이 아니다. 메일 읽기나 임의 수신자 발송 권한을 주지 않는다. 하루 20회 한도와 보고서 ID 중복 방지를 적용한다.

Apps Script 응답의 Google 콘텐츠 호스트 리다이렉트만 허용한다. 리다이렉트 요청은 GET이며 보고서와 제출 키를 재전송하지 않는다. 다른 호스트로 향하는 리다이렉트는 실패 처리한다.

## 상태와 재시도

- 발송 성공 응답을 받은 뒤에만 앱에서 접수 확인으로 표시한다. 이는 Google 메일 발송 함수 성공을 뜻하며 받은편지함 도착 보장은 아니다.
- 응답이 유실되면 같은 보고서 ID로 재시도하고, 중계는 저장한 접수번호를 반환한다.
- 메일 서비스 호출 중 오류가 나면 중복 발송 방지를 위해 중계에 미확정 기록을 남긴다. 자동으로 같은 메일을 다시 보내지 않으며 앱도 성공으로 표시하지 않는다. 관리자가 실제 메일과 실행 기록을 확인해야 한다.
- 전송 동의 및 본문·이름 포함 옵션은 기존 선택을 유지한다. 기본은 꺼짐이다.
- Google 배포 권한 승인과 실메일 검증 전에는 자동 이메일 연결 완료로 안내하지 않는다.

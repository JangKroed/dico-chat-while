# 0.4.55 발송 지연과 연결 중단 진단

## 읽기 전용 운영 관찰

11월 9일 그룹 11은 Brave 50시도 중 39건, Chrome 50시도 중 48건이 DICO 완료로 기록됐다. Brave 최장 건은 첫 Enter부터 실제 요청까지 약 86초가 걸렸다. 30회 Enter에서 DOM 쿨다운은 0초였고, 관측된 POST는 마지막 Enter 직후 한 건이었다. Chrome과 Brave 모두 백그라운드였으며 대표 시도의 keydown 기본 동작이 취소됐다. 따라서 기본 동작 취소 자체는 발송 처리의 근거가 아니다.

최근 24시간의 Brave 지연 표본 93건에서 직전 성공 POST부터 첫 Enter까지 중앙값은 66.6초, 다음 POST까지는 119.0초였다. 빠른 Brave 표본 45건의 POST 간격은 68.1초였다. 약 120초 경계에 모이는 현상은 클라이언트나 계정 쪽 제출 조건을 조사할 근거이며, 운영 계정과 브라우저가 서로 달라 원인 확정에는 사용할 수 없다. Chrome의 연결 단절 21회는 별도 현상이다.

## 변경

- 자동 발송의 특정 Enter가 문서 캡처·버블 단계에 도달했는지 두 불리언으로 기록한다. 진단 이벤트 시각은 실제 keydown 호출 직전으로 고정한다. 사용자 키나 원문은 수집하지 않는다.
- 읽기 전용 비교 도구가 동일 계정·채널의 직전 성공 POST를 기준으로 첫 Enter와 다음 POST의 간격을 빠른 표본과 지연 표본으로 나눠 집계한다. 동일 조건의 브라우저 교차 표본을 별도로 요구한다.
- 중앙의 연결 중단 기록에 명시적 전송 종료와 응답 만료를 구분하는 코드, 응답 만료 시 마지막 유효 브리지 메시지 이후 시간을 남긴다.
- 발송 간격과 Enter 재시도 조건은 유지한다. 이 검증본에는 이전 작업의 준비 실패 후 계정 순환 수정도 포함된다.

## 검증 및 교차 시험

`npm test` 1,357건, 중앙 UI 컴파일, 확장 빌드·검사, React SSR, Apple Silicon 패키지 ZIP 무결성 및 임시 DB에서 0.4.55 실행·브리지 진단을 확인했다.

실환경에서는 같은 계정·채널·문구·빌드·탭 상태에서 Chrome과 Brave를 순차적으로 비교한다. 직전 POST와 첫 Enter 사이 간격이 비슷한 표본을 브라우저별 3건 이상 확보한다. 문서 전파가 같고 성공 POST만 특정 경계에 몰리면 클라이언트 또는 계정의 제출 제한을 우선 조사한다. 문서 전파가 브라우저에 따라 달라지면 이벤트 전달 경로를 좁힌다. 둘 다 간접 근거로 취급한다.

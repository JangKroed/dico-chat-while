# DICO 0.4.44 안정성 변경

## 배포 원칙

중앙 업데이트는 공식 저장소 main을 사용한다. 작업 폴더에서 수정·컴파일한 것과 실제 배포는 구분한다. 이번 변경은 0.4.42 이후 안정성 수정본을 기존 업데이트 경로에 제공한다. 중앙 패키지·lock·확장 manifest는 모두 0.4.44다. 구형 단독 확장의 버전은 별개이며 변경하지 않는다.

## 원인과 변경

- 계정 간격 보정과 사용자 간격을 중복 가산하던 계산을 긴 값 선택으로 통일했다. 그룹 간격과 5초 사전 입력은 별도 시각으로 유지한다.
- 일시적인 입력 준비 오류는 동일 차례를 유지하며 백오프로 재준비한다. 명시적 Enter 이전 근거가 있을 때만 자동 재시도하며, 불확실한 과거 결과를 미발송으로 바꾸지 않는다.
- 재연결 후에도 원래 제출 세션에 묶인 완료 영수증을 조회한다. 현재 복구 명령과 원래 세션·계정·채널·문구·설정·실행 식별자를 검증한다. 근거가 없으면 새 Enter를 만들지 않는다.
- 페이지 읽기는 취소와 제한 시간을 적용한다. 사용자 중지, 세션 변경, 연결 종료 후 늦은 조회 결과를 폐기한다.
- 완료 결과 보고와 정지 적용의 불필요한 결합을 줄였다. 현재 페이지 실행이 끝난 시도만 별도 제어 경로를 허용하고, 실행 중 입력은 기존 중지 게이트와 차단 확인을 따른다.
- 시스템 복구 의도는 재시작 시 보존하고 현재 관찰·설정·세션을 재확인한다. 사용자 중지는 자동 재개보다 우선한다.
- 삭제된 탭 정리와 확장 reload 호출의 일시 실패는 영속 백오프로 재시도한다. 삭제 표식을 보존하며 뒤늦은 관찰로 연결이 부활하지 않는다.
- 원래 입력 차단이 확인된 미확인 이력은 보존한 채 업데이트할 수 있다. 현재 실행 가능성과 과거 결과의 확실성을 구분한다.
- 자동 제보 수집을 읽기 전용 worker로 분리하고 수집 의도를 대기열 등록 전에 저장한다. 기존 동의 범위에서 전송 실패를 재시도한다.
- Native 진단 대기열이 중요 응답을 점유하지 않도록 순서를 조정한다. 세션 경계와 중복 방지 검사는 유지한다.
- 실제 중앙 버전, 연결 확장 보고 버전, 관측된 페이지 버전을 구분한다. 관측이 없거나 오래되면 미확인·오래된 관측으로 표시한다.

## 검증

원격 main 기반 격리 체크아웃의 실제 구현을 대상으로 전체 테스트 1,324개 통과, 실패·취소·제외 0. 여러 계정·채널 120회 반복, 20초 그룹 간격과 5초 준비, 61회 Enter 재시도, 중지·늦은 응답·세션 전환·삭제·자동 복구·대량 합성 이력을 포함한다. TypeScript·중앙 UI 컴파일·prebuilt 검증·확장 빌드·manifest/CSP·루트 검사·루트 ZIP 빌드·React SSR도 통과했다. 기존 updater의 UI 의존성 설치와 central:build, central:check 준비 절차도 통과했다.

실제 Discord 시험 발송 및 운영 프로그램 교체는 수행하지 않았다. 모의 검증 통과만으로 모든 브라우저 환경의 해결 완료를 주장하지 않는다. 브라우저 내부의 Enter 무시 원인은 추가 관측이 필요하며, 단계별 시간 및 버전 계측과 취소·재시도 경로로 관측 공백과 지연을 줄인다. 다른 확장의 실제 실행을 전부 관측·차단할 수 없으므로 구형 확장의 공존 안전을 보장하지 않는다.

# 다른 PC에서 중앙 관리 화면 열기

중앙 PC 한 대에서 실행 중인 DICO를 **같은 사용자의 다른 PC 브라우저로 조회·조작**할 수 있습니다. 관리 프로그램의 **설정 · 도움말 → 다른 PC에서 관리 화면 열기**에서 현재 포트에 맞는 터널 명령과 일회용 접속 링크를 제공합니다.

중앙 PC의 DICO와 Discord 브라우저는 계속 실행해야 합니다. 다른 PC의 Discord 계정을 이 중앙 PC의 실행기로 연결하는 기능은 아직 없습니다. 여러 PC 실행기·소유자별 권한 분리 계획은 [MULTI-DEVICE.md](MULTI-DEVICE.md)를 참고하세요. 원격 관리 세션은 현재 작업 공간의 메시지·계정·설정을 조회·변경하고 발송을 시작·중지하는 전체 관리 권한을 갖습니다.

## 1. 연결할 두 PC 준비

- **중앙 PC:** 기존 관리 프로그램과 Discord가 실행되는 PC입니다. SSH 서버에 로그인할 수 있는 OS 계정을 준비합니다.
- **다른 PC:** 관리 화면만 여는 PC입니다. macOS 터미널 또는 Windows PowerShell에서 OpenSSH 클라이언트를 사용합니다.
- **같은 내부망:** 중앙 PC의 사설 IP나 호스트 이름으로 SSH에 연결합니다.
- **서로 다른 내부망:** 먼저 신뢰하는 VPN으로 두 PC를 연결하고 중앙 PC의 VPN 주소를 사용합니다. 공유기에서 중앙 관리 포트나 SSH 포트를 공인 인터넷에 공개하는 절차는 사용하지 않습니다.

중앙 PC가 macOS라면 시스템 설정 → 일반 → 공유 → 원격 로그인에서 사용할 OS 계정만 허용합니다. 표시되는 사용자 이름·호스트 주소를 확인하세요. 이 터널에 전체 디스크 접근 권한은 필요하지 않습니다. [Apple 공식 원격 로그인 안내](https://support.apple.com/guide/mac-help/allow-a-remote-computer-to-access-your-mac-mchlp1066/mac)

중앙 PC가 Windows라면 선택적 기능에서 OpenSSH Server를 준비하고 OpenSSH SSH Server 서비스를 실행합니다. 다른 PC에는 OpenSSH Client가 필요합니다. SSH 허용 계정과 네트워크 범위는 사설망·VPN 용도에 맞게 직접 설정하세요. [Microsoft 공식 OpenSSH 안내](https://learn.microsoft.com/ko-kr/windows-server/administration/openssh/openssh_install_firstuse)

DICO는 SSH 설치, OS 원격 로그인, 방화벽, VPN 설정을 자동으로 변경하지 않습니다.

다른 PC의 macOS 터미널에서 `ssh -V`, Windows PowerShell에서 `Get-Command ssh`로 SSH 클라이언트가 있는지 먼저 확인하세요. Windows에서 명령을 찾지 못하면 선택적 기능에서 OpenSSH Client를 직접 설치한 뒤 PowerShell을 다시 엽니다. 중앙 PC의 OpenSSH Server와 접속하는 PC의 OpenSSH Client는 서로 다른 역할입니다.

## 2. 다른 PC에서 터널 실행

중앙 관리 화면의 포트를 확인합니다. 아래는 **예시 포트 43127**입니다. 실제 값은 프로그램 안의 안내에 표시됩니다.

```text
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:43127:127.0.0.1:43127 SSH_USER@CENTRAL_HOST
```

`SSH_USER`를 중앙 PC의 OS 사용자 이름으로, `CENTRAL_HOST`를 중앙 PC의 사설망·VPN 주소로 바꾸세요. Discord 계정 정보가 아닙니다. 예를 들어 OS 사용자 `hoya`, 중앙 PC의 사설 IP `192.168.0.20`이라면 마지막 부분은 `hoya@192.168.0.20`입니다.

처음 접속할 때 SSH 호스트 지문이 중앙 PC와 일치하는지 확인하고 해당 OS 계정으로 인증합니다. 명령은 터널을 유지하며 기다리므로 터미널을 열어 두세요. `-L`은 다른 PC의 로컬 포트를 중앙 PC의 로컬 서비스에 연결하고, `-N`은 원격 명령을 실행하지 않습니다. [OpenSSH 공식 설명](https://man.openbsd.org/ssh)

양쪽 포트는 **같아야** 합니다. 다른 PC에 같은 포트를 사용하는 DICO나 프로그램이 있다면 해당 프로그램을 확인한 뒤 충돌을 해소하세요. 로컬 포트만 임의로 바꾸면 DICO의 Host/Origin 검사에서 거부됩니다. 터널은 다른 PC의 `127.0.0.1`에만 열며 `0.0.0.0`이나 `-g`를 사용하지 않습니다.

## 3. 일회용 링크로 로그인

1. 터널이 연결된 상태에서, 이미 로그인된 중앙 관리 화면의 **설정 · 도움말 → 다른 PC에서 관리 화면 열기**를 펼칩니다.
2. **2분짜리 접속 링크 만들기**를 누르고 전체 관리 권한 안내를 확인합니다.
3. 링크를 복사해 **본인의 다른 PC 브라우저 주소창에 2분 안에** 붙여 넣습니다. 중앙 PC에서 먼저 열면 일회용 링크가 사용됩니다.
4. 로그인 후 인증 부분은 주소창에서 제거됩니다. 이후 같은 브라우저에서는 해당 로컬 주소로 관리 화면을 다시 열 수 있습니다. 세션은 최대 12시간 유지됩니다.

주소는 `http://127.0.0.1:실제포트/`를 유지합니다. `localhost`나 중앙 PC의 IP로 바꾸지 마세요. 기존 화면의 주소를 복사하는 것만으로는 새 브라우저가 로그인되지 않습니다. 일회용 링크는 권한을 주는 정보이므로 공개 채팅방·문서에 남기지 않습니다. DICO의 내부 브리지 인증 파일이나 자격증명을 복사할 필요가 없습니다.

## 4. 사용 종료와 문제 확인

관리 탭을 닫고 다른 PC의 터널 터미널에서 `Ctrl+C`를 누르면 터널이 끝납니다. **터널을 종료해도 중앙 PC의 발송은 계속됩니다.** 발송을 멈추려면 먼저 관리 화면에서 그룹 중지를 요청하고 적용을 확인하세요. 탭 종료나 터널 종료가 로그인 세션을 폐기하지는 않습니다. 공용 PC에서는 사용하지 마세요.

| 화면·오류 | 확인할 사항 |
| --- | --- |
| SSH 연결 거부·시간 초과 | 중앙 PC 실행 상태, SSH 서버, 사설망·VPN 경로와 허용 범위 |
| `Address already in use` | 다른 PC의 동일 포트를 점유한 프로그램 확인. 포트 숫자를 임의로 바꾸지 않기 |
| 허용되지 않은 요청 출처 | 두 포트가 중앙 포트와 같은지, 주소가 정확히 `127.0.0.1`인지 |
| 페이지 연결이 만료됨 | 터널 유지 후 새 일회용 링크 만들기. 링크는 2분 이내 한 번만 사용 |
| 링크 만료 시간이 맞지 않음 | 두 PC의 시스템 시간 확인 후 다시 발급 |
| 연결되지만 기대한 계정이 없음 | 관리 대상은 중앙 PC의 작업 공간. 다른 PC 실행기 등록은 미지원 |

중앙 서버는 계속 `127.0.0.1`에만 바인딩하며 기존 Host/Origin·세션·CSRF 검증을 유지합니다. 터널은 네트워크 경로만 연결하고 DICO의 로그인이나 접근 검사를 생략하지 않습니다.

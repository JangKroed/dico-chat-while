# 빠른 채팅 발송 관찰 개선 (0.4.26)

## 조사와 확인된 결함

사용자는 개인 테스트 서버에서는 정상이나 전달받은 사용자의 채널에서는 정지한다고 보고했고, 빠른 채팅을 의심했다. 실제 수신자의 해당 순간 DOM·로그는 확보하지 않았으므로 실제 장애 원인을 단정하지 않는다.

0.4.25에서 다음 회귀 테스트가 실패하는 것을 확인했다.

- 동일 문구의 타인 메시지에 전송 중 표시가 있는 합성 DOM: 작성자 확인 전 sending 상태를 기록하여 본인의 남은 초안 재시도가 관찰 대기로 이어졌다. 실제 Discord가 타인의 행에 이 표시를 사용하는지는 확인하지 못했다.
- 200개 연속 메시지의 작성자 상속: 앞선 행을 반복 탐색하여 DOM 작성자 조회 20,300회. 관찰이 잦을 때 비용이 커지는 구조다. 실제 사용자의 지연 시간은 측정하지 않았다.

## 수정

작성자를 먼저 판별하여 명시적으로 다른 작성자의 행은 sending/failed 및 로컬 발송 증거에 기록하지 않는다. 작성자를 모른다는 이유만으로 본인 또는 미발송으로 단정하지 않는다.

한 번의 관찰에서는 작성자 상속 탐색 결과를 공유하여 반복 탐색을 줄인다. 다음 관찰마다 캐시를 새로 생성하므로 행 재사용·작성자 변경을 새로 읽는다. 200개 재현의 조회가 401회 이하인지 검사한다.

빠른 채팅으로 게시가 사라져도 검증된 현재 계정·채널·입력창이 비워지면 1회 완료하는 기존 경로를 유지한다. 200개 메시지 유입 및 제거 재현에서 추가 Enter가 발생하지 않는지 검사한다. 화면에서 글이 없다는 사실만으로 재발송하지 않는다.

## 검증 및 배포

기존 코드에서는 신규 회귀 3개 중 2개 실패, 수정 후 관련 테스트 102개 통과. 전체 테스트·빌드 결과는 배포 커밋의 CI에서 확인한다. 실제 상대방 채널 연속 발송은 미실행이다.

기존 GitHub main 소스 업데이트 경로로 제공한다. 관리 화면에서 0.4.26 업데이트를 적용하며 자동 제보 연결과 동의 설정은 유지한다.

## 기술 참고

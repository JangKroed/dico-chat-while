# 자동 연결 복구 무결성 검증 — 2026-11-03

## 재현된 원인

0.4.32 작업 트리의 복구 스케줄러는 `repair()`가 예외 없이 반환하면 안전 조건으로 차단되어도 성공으로 간주하고 3회 예산을 소모했다. 간격은 항상 10초였다. 계정 관찰이 잠시 미확인이 되면 장애 키가 비어 다시 확인될 때 예산이 초기화됐다. 연결 복구 함수는 계정 확인 도중 세션이 바뀌어도 이전 계정 결과를 저장할 수 있었고, 진행 상태 보고 도중 중지되어도 계정 조회를 계속했다. 새 회귀 테스트 5개가 변경 전 모두 실패하여 각 원인을 재현했다.

## 변경 동작

- 동일 누락 대상·등록 계정·세션에서 실제 복구는 최대 3회다. 첫 시도 후 10초, 두 번째 후 20초를 기다린다. 일반화한 지수 대기는 최대 60초다.
- 계정 `verified`의 일시적인 변화는 예산을 초기화하지 않는다. 누락 대상 집합이나 등록 계정/세션이 바뀌거나 누락 상태가 사라진 뒤 다시 발생하면 새 장애로 처리한다.
- 결과는 `status`, `attempted`, `completed`, 필요한 경우 `reasonCode`로 반환한다. `blocked`와 `cancelled`를 성공으로 처리하지 않는다. 실제 탭 생성/이동 시도 전 안전 차단은 예산을 소모하지 않으며 확인 자체에는 최소 10초 간격을 둔다. 미확인 발송 해소 뒤 다음 확인에서 자동 복구가 가능하다.
- 스케줄러는 동시 복구를 하나로 제한하고, 이전 장애의 늦은 완료가 새 장애의 예산·예약 시간을 덮어쓰지 못하도록 세대를 비교한다.
- 연결 복구는 세션·resetEpoch·중지 상태와 호출자의 현재 연결 조건을 비동기 경계마다 확인한다. 다른 계정의 기록이 섞인 경우 계정 저장 전에 차단한다.
- background는 구조화된 복구 결과를 스케줄러에 반환한다. 하트비트의 이전 세션 응답을 폐기하고, 연결/복구 뒤 중지된 경우 타이머·업데이트 후속 작업을 시작하지 않는다.
- 채널 열기/창 모으기 대기열은 예약 시점 세션을 보존한다. 중지 또는 세션 교체 도중 Chrome 창 생성이 완료되면 새로 생성한 탭만 정리하고 등록을 저장하지 않는다. 기존 관리 창의 다른 탭은 보존한다. 준비 상태 조회 반복문도 매번 중지·세션을 확인한다.

## 검증

`tests/central-recovery-integrity.test.js`는 스케줄러/복구 함수 실행뿐 아니라 실제 `background.js`의 채널 열기와 하트비트 함수를 추출해 Chrome/transport를 모킹한다. 중지 중 창 생성 완료의 정리 및 무저장, 이전 세션 하트비트 응답의 무변경을 검증한다. 기존 중지 회귀 테스트는 중지 후 추가 progress 전송 대신 `cancelled` 반환과 마지막 사전 상태를 검증하도록 수정했다. 중지 전 미확인 발송의 `blocked` 보고 테스트는 유지했다.

실행 명령:

```sh
node --check central/extension/background.js
node --test tests/central-recovery-integrity.test.js tests/central-recovery-scheduler.test.js tests/central-connection-recovery.test.js tests/central-recovery-review.test.js tests/central-missing-tab-recovery.test.js
```

실제 Discord 발송이나 외부 계정 변경은 수행하지 않았다. Chrome에 이미 제출한 생성 API 호출은 취소할 수 없으므로 완료 후 새로 생성한 탭을 정리하는 보상 처리를 사용한다. 정리 API까지 실패하는 실제 브라우저 오류는 모킹 검증 범위 밖이다. 이미 제출된 창 이동/저장 API 자체의 취소를 보장하는 변경은 아니다.

## 추가 창 작업 가드 및 제어 경로

`managed-windows.js`의 생성/복구용 모으기 함수는 선택적 `assertCurrent`를 받는다. 저장 상태·탭 소유권을 조회한 뒤 생성/이동하기 직전과 저장 직전에 검사한다. 생성 대기 중 중지된 경우 생성 탭만 제거한다. 기존 호출자는 기본 인자로 동작을 유지한다.

중앙 제어의 일시 중지 상태에서도 하트비트는 결과 조정 및 재개 명령을 계속 수신한다. 중지 상태에서는 복구·관찰 갱신·업데이트 경로만 건너뛴다. 이전 세션 응답은 제어 경로에서도 폐기한다. 관련 모킹 회귀 테스트를 추가했다.

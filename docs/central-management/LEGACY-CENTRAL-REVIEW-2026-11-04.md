# 구형 확장 대비 중앙 관리 전반 검토 — 0.4.40

## 비교 기준과 범위

구형 단독 확장의 로컬 Git 기준 87d0368의 background.js/controller.js와 중앙 관리 0.4.39(31c2846)의 발송·Native·복구·UI 경로를 비교했다. 구형도 별도 준비, 예약 대기, 입력 검사, 확인 및 중복 방지 단계를 가진다. 구형은 브라우저 내부에서 허가를 판단하고 진단·알림을 발송 저장 경로와 분리하지만 중앙은 Native IPC, 로컬 HTTP, SQLite, UI 구독을 추가로 거친다. 중앙 순서 보장은 필요하지만 업데이트 파일 검사와 전체 화면 계산까지 발송 응답을 막을 이유는 없다.

수신자의 기존 녹화 및 0.4.29 보고서, 앞서 확보한 0.4.35 메일은 참고 자료다. 이번 결함은 최신 코드로 별도 재현했으며 과거 모든 실패를 같은 원인으로 단정하지 않는다. 구형 바이너리를 사용자 계정에서 실행하거나 실제 Discord에 시험 발송하지 않았다.

## 재현과 실제 변경

### Native 통신 대기열

확장 상태 조회는 파일 해시를 읽을 뿐 아니라 구형 설치 복사본을 교체할 수도 있다. 따라서 일반 읽기와 같은 병렬 실행·응답 시간제한을 적용하지 않는다. 관리 프로그램이 reloadSafe가 아니라고 응답하면 파일 검사 자체를 건너뛰고 이후 승인 요청으로 진행한다. 유휴 상태에서는 기존 자동 복사본 복구와 직렬 처리·종료 대기를 유지한다. 유휴 조회 직후 별도 UI에서 실행을 시작하는 전체 시스템의 경합까지 제거했다고 주장하지 않는다.

### 읽기 전용 검사와 중지

DICO_DRAFT_INSPECT와 DICO_INSPECT 응답을 각각 멈췄다. 기존에는 실행 lane이 해제되지 않았다. 수정 후 20초 내 제한되며 중지 요청이 오면 시간을 전진시키지 않아도 조회·중지 명령이 끝난다. 초안 본문은 유지되고 Enter는 실행하지 않는다. 허가 전 검사 시간 초과는 기존 5초 백오프·최대 3회 준비 복구 정책에 포함한다. 실제 중지는 재시도하지 않는다.

### 이벤트 폭주

동일 화면에 진단 이벤트 100개를 연속 전달한 HTTP/SSE 시험에서 기존 전체 상태 읽기는 초기 1회+추가 100회였다. 수정 후 초기 1회+추가 1회이며 최신 revision 100을 전달한다. 이벤트 100개는 모두 전달한다. 예약 뒤 인증이 만료되거나 화면이 닫히면 상태를 읽거나 전송하지 않는다. 알림 저장이 느릴 때 후속 최신 읽기를 하나만 예약하는 시험도 추가했다. 종료 시 새 발송을 먼저 차단하고 이미 진행 중인 알림 저장이 끝난 뒤 프로세스 잠금을 해제하여 새 런타임과 기록이 충돌하지 않게 한다.

### 채팅 목록 비용

200행이 있는 합성 채널에서 중앙 완료 콜백은 전체 메시지 목록을 다시 조회하지 않는다. 비교용 단독 발송 경로는 게시 근거를 위해 목록 조회를 유지한다. 모든 채팅 mutation의 스캔 비용을 제거한 것은 아니며 완료 시점의 불필요한 한 차례 순회를 줄였다. 뒤늦게 나타난 메시지 ID는 생략될 수 있으나 입력창 비움의 검증 근거와 이미 관찰한 ID는 보존한다.

## 왜 기존 테스트만으로 놓쳤는가

기존 승인 테스트는 주로 통신 결과와 상태 전이 자체를 검사했다. 파일 조회가 승인 앞에서 멈추는 패킷 순서, 읽기 전용 검사 응답 영구 대기, 서비스 복귀 시 브라우저 이벤트가 없는 경우, 포트 생성의 동기 예외, 이벤트 100개와 전체 상태 계산량의 조합은 별도 회귀가 없었다. 이번에는 각 실패 경로를 직접 만들고 실패를 확인한 뒤 수정했다. 타임아웃이나 승인 유효기간을 늘려 통과시키지 않았다.

## 남은 한계

- 실제 수신자 컴퓨터의 장시간 다중 브라우저 운영 및 Discord 서비스 지연 실측은 미완료다.
- 중앙의 SQLite 상태 전체 복사·저장 구조는 유지된다. 많은 누적 이력에서 처리 비용이 증가할 수 있으므로 이번 화면 갱신 병합만으로 전체 저장 성능 문제가 해결됐다고 주장하지 않는다.
- 정상 발송의 500ms 최종 입력 안정 검사와 계정·중앙 승인 통신은 남는다. 정확한 예약 시각에 항상 제출되는 보장은 없다.
- 인증 만료·권한 상실·사용자 초안 변경·외부 발송 여부 불명확은 자동으로 무시하지 않는다.
- 화면 재연결은 발송 그룹 자동 재개를 뜻하지 않는다. 사용자가 중지한 그룹은 그대로 유지한다.
- 자동 제보는 기존 동의·민감 정보 제외 정책을 유지하며, 새 메일을 시험 전송하지 않는다.

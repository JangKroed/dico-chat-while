아무것도 설치하지 않은 컴퓨터에서도 기존 설치 확인 → 필요한 프로그램 준비 → DICO 설치 → 브라우저별 연결 → 첫 실행 순서로 진행합니다.

관리 프로그램 버전은 0.4.14, 확장 버전은 0.4.13이 정상입니다. 이번 변경은 설치 안내·검사·패키징에 적용됩니다.

이 파일은 인터넷 없이도 읽을 수 있습니다. 다운로드·로그인·실제 사용에는 인터넷이 필요합니다.

2. 이미 설치되어 있는지 먼저 확인

2-1. 브라우저부터 확인

  1. Chrome이 있으면 주소창에 chrome://extensions, Brave가 있으면 brave://extensions를 입력합니다. 검색창이 아니라 맨 위 주소창입니다.
  2. DICO 중앙관리 실행기가 있으면 새 확장은 이미 등록된 것입니다. 표시된 버전과 켜짐 상태를 확인합니다. Chrome과 Brave, 그리고 각각의 프로필에서 따로 확인합니다.
  3. Dico While / 구형 자동 발송 확장이 있으면 기존 실행 화면에서 중지하고, 미확인 게시 여부를 정리한 뒤 확장 스위치를 끕니다. 새 확장과 같은 계정으로 동시에 실행하지 않습니다. 새 설치자는 ‘기존 실행기를 사용하지 않는 새 설정’을 선택하면 됩니다.

2-2. DICO 관리 프로그램 확인

Mac용 ZIP을 풀고 check-installation.command를 실행합니다. 이 파일은 설치·삭제·설정 초기화·메시지 발송을 하지 않습니다. 현재 사용자에 설치된 프로그램·연결 등록·브라우저와 실행 상태를 읽어서 보여줍니다.

응용 프로그램 폴더에 DICO가 보이지 않아도 정상일 수 있습니다. 현재 배포본은 일반 DICO.app이 아니라 사용자 폴더에 설치되는 프로그램입니다. 확장이 있는 것과 관리 프로그램이 설치된 것은 서로 다른 항목입니다.

3. Mac · Apple Silicon에 설치

필요한 것

Chrome 또는 Brave 한 개 이상, 인터넷, 받은 Mac용 ZIP. 처음 실행에는 Git·Node.js·VS Code·Xcode를 따로 설치할 필요가 없습니다. Node 런타임은 포함되어 있습니다.

  1. 브라우저 설치 여부 확인: Finder → 응용 프로그램에서 Google Chrome 또는 Brave Browser를 찾고, 실행되는지 확인합니다. 없다면 Chrome 공식 사이트 또는 Brave 공식 사이트에서 내려받아 설치합니다. Safari만으로는 이 확장을 사용할 수 없습니다.
  2. ZIP을 다운로드하고 더블클릭해 압축을 풉니다. 압축 파일 자체가 아니라 풀린 폴더를 엽니다. iCloud 동기화 중인 폴더 대신 다운로드 같은 로컬 폴더를 사용하면 파일 대기 문제를 줄일 수 있습니다.
  3. START-HERE.html을 열어 이 안내서를 읽고, check-installation.command를 먼저 실행합니다. 이미 설치되어 있다면 위 분기를 따릅니다.
  4. 설치가 없을 때 install.command를 더블클릭합니다. 터미널이라는 글자 창이 열리며 현재 OS 사용자에게 설치하고 중앙관리 화면을 엽니다.
  5. 설치 파일을 열 수 없다는 macOS 안내가 나오면 아래 ‘Mac 보안 안내’ 항목을 따릅니다. 본인이 전달받은 DICO 파일인지 확인한 뒤 해당 항목만 허용합니다.
  6. 설치가 끝나면 중앙 화면 또는 open-manager.command로 관리 화면을 엽니다. 브라우저 주소를 외워서 직접 입력할 필요는 없습니다. 아래 확장 등록까지 끝나야 실제 브라우저가 연결됩니다.
Mac에서 install.command를 열 수 없다고 나옵니다
  1. 경고에서 휴지통으로 이동하지 않고 창을 닫습니다.
  2. Apple 메뉴 → 시스템 설정 → 개인정보 보호 및 보안으로 이동합니다.
  3. 방금 차단된 파일 항목을 확인하고 그래도 열기를 선택합니다. 확인 창에서 열기를 누릅니다.
  4. 버튼이 없거나 조직 관리 정책으로 막혔다면 임의로 보안 설정을 전체 해제하지 않습니다. 파일명·경고 내용을 전달한 사람에게 보여주세요.

설치 도구와 포함 런타임은 서명되지 않은 개발판입니다. Mac 설정과 다운로드 상태에 따라 파일별 확인이 더 필요할 수 있습니다. Apple의 앱 열기 안내

4. 사용할 브라우저마다 확장 등록

순서: 관리 프로그램 설치를 먼저 끝낸 다음 확장 폴더를 선택합니다. ZIP 전체·central 폴더·응용 프로그램 목록에서 임의의 폴더를 선택하지 않습니다.

  1. Chrome은 chrome://extensions, Brave는 brave://extensions를 엽니다.
  2. 오른쪽 위 개발자 모드를 켭니다. 개발 작업을 하라는 뜻이 아니라, 스토어에 없는 받은 확장을 등록하는 메뉴입니다.
  3. 압축해제된 확장 프로그램을 로드합니다를 누릅니다. 브라우저에 따라 ‘압축 해제된 확장 프로그램 로드’처럼 문구가 조금 다를 수 있습니다.
  4. Mac: 폴더 선택 창에서 ⌘ Shift G를 누르고 아래 경로를 붙여넣어 이동한 뒤 선택을 누릅니다.
    ~/Library/Application Support/DICO/app/extension
    Windows: 폴더 선택 창 주소칸에 아래 경로를 입력하고 선택합니다.
    %LOCALAPPDATA%\DICO\app\extension
  5. DICO 중앙관리 실행기가 추가되고 켜져 있는지 확인합니다. 고정된 확장 ID는 ibkkihhaihlpjcahglnoiphcddcjipgh입니다.
  6. 브라우저 오른쪽 위 퍼즐 모양 → DICO 옆 고정 핀을 눌러 아이콘을 표시합니다. 아이콘을 누르면 옆 패널이 열립니다.
  7. 다른 브라우저나 다른 프로필도 사용할 때는 그 창에서 같은 과정을 반복합니다. Chrome에 설치했다고 Brave에도 설치되는 것은 아닙니다.

설치된 경로의 extension 폴더를 사용하면 다운로드한 폴더를 이동해서 연결이 끊기는 문제를 줄일 수 있습니다. 설치 위치의 폴더는 임의로 이름을 바꾸거나 삭제하지 않습니다.

5. 계정 → 채널 → 메시지 → 그룹 순서로 설정

  1. Discord 로그인: 사용할 브라우저에서 Discord 웹을 열고 자신의 계정으로 로그인합니다. 계정이 다르면 브라우저 또는 프로필도 구분합니다.
  2. 기존 실행기 확인: DICO 패널에서 처음 사용하는 사람은 ‘기존 실행기를 사용하지 않는 새 설정’을 선택해 확인 상태를 저장합니다. 기존 사용자라면 실제 중지·비활성화 후 해당 선택지를 사용합니다.
  3. 계정 등록: Discord 탭에서 패널의 현재 Discord 계정 등록을 누릅니다. ‘관리 프로그램과 연결이 끊겼습니다’라면 관리 프로그램 다시 연결을 먼저 누릅니다.
  4. 중앙 화면: 패널의 채널 설정 열기를 누릅니다. 계정·브라우저에서 자신이 구분할 계정 이름과 브라우저 이름을 정합니다.
  5. 메시지 보관함: 보낼 문구를 추가합니다. ‘메시지 이름’은 목록에서 알아볼 제목이며 실제 보낼 본문도 입력합니다.
  6. 채널 설정: Discord에서 원하는 서버의 텍스트 채널을 열고 URL을 복사해 추가합니다. 사용할 등록 계정을 고르고 연결을 요청합니다. 채널·계정 검증이 완료된 뒤 메시지를 골라 채널에 적용합니다. 또는 해당 Discord 채널 탭에서 패널의 현재 Discord 채널 연결을 사용합니다. 다른 사이트에서는 이 버튼이 비활성인 것이 정상입니다.
  7. 발송 그룹: 같은 채널에 연결된 계정들을 선택하고 순서를 정합니다. 채널이 다르면 그룹도 따로 만듭니다. 계정별 주기는 기본 자동(감지된 슬로우 모드 + 3초 및 실측 보정)이며 더 길게 설정할 수 있습니다.
  8. 첫 시험: 허용된 테스트 채널에서 짧은 문구로 그룹 하나만 시작합니다. ‘모두 실행’은 준비된 모든 그룹의 실행 요청입니다. 버튼을 누르면 실제 메시지가 나갈 수 있습니다.
  9. 확인: Discord 게시 내역과 실행 기록의 게시 확인을 함께 확인합니다. 첫 순환과 다음 순환까지 보고 계정·문구 순서가 맞는지 확인합니다.

6. 다음 날 실행 · 중지 · 업데이트

  • 다시 열기: 확장 패널의 ‘채널 설정 열기’ 또는 Mac 패키지의 open-manager.command를 사용합니다. PC 재시작 뒤에는 연결 상태를 확인하고 실행을 요청합니다.
  • 실행 유지: 브라우저와 관리 프로그램이 실행되어 있어야 합니다. 전송 창은 최소화할 수 있지만 종료하지 않습니다. PC 절전 중에는 정상 진행할 수 없습니다.
  • 터미널: 설치 직후 별도 실행된 서비스는 백그라운드로 동작할 수 있습니다. 직접 open-manager로 실행해서 터미널에 실행 주소가 표시되고 계속 대기한다면 그 창이 프로그램을 실행 중이므로 닫으면 프로그램도 종료될 수 있습니다.
  • 중지: 중앙 화면의 ‘전체 중지’를 요청하고 적용 상태를 확인합니다. 알림을 읽음으로 표시하는 것은 실행 문제 해결과 다릅니다.
  • 업데이트: 그룹 중지·미확인 결과 확인 후 설정·도움말의 업데이트를 사용합니다. 설치 폴더나 개인 데이터 폴더를 먼저 지우지 않습니다. 확장 파일이 변경되면 브라우저별 버전·연결 상태를 확인합니다.
  • 발송 재시도: 설정·도움말에서 0~5회, 기본 5회입니다. 게시 확인 전에는 다음 계정으로 넘어가지 않습니다. 입력 준비 카운트다운은 실제 발송 시각과 다릅니다.
처음 실행은 되는데 자동 업데이트에서 Git이 없다고 나옵니다

Mac 실행 ZIP에는 Node와 npm을 포함하지만 Git은 포함하지 않습니다. 자동 업데이트에는 Git이 별도로 필요합니다.

Mac: Spotlight(⌘ Space)에서 ‘터미널’을 열고 아래 한 줄을 입력합니다. Apple 설치 창이 뜨면 Command Line Tools 설치를 끝내고, 새 터미널에서 git --version을 확인합니다.

xcode-select --install

이미 설치되어 있다고 나오면 다시 설치할 필요가 없습니다. 전체 Xcode 앱 설치는 필요하지 않습니다.

Windows: 앱 목록에서 Git을 확인하고, 없다면 Git for Windows x64 설치 파일을 설치합니다. 기본 옵션을 사용하고 관리 프로그램을 다시 실행합니다. Node를 별도로 설치할 필요는 없습니다.

Windows x64: 소스 준비 ZIP으로 설치할 때

이번에 함께 제공하는 Windows용 파일은 완제품 EXE 패키지가 아닌 소스 준비 ZIP입니다. 이 경로는 C++ Build Tools 설치가 추가로 필요합니다. Windows 실행 파일은 Windows에서 만들어야 하며, 실제 Windows 설치 검증은 이번 Mac 작업에서 수행하지 않았습니다.

  1. 시작 → 설정 → 시스템 → 정보에서 x64인지 확인합니다. Chrome 또는 Brave가 설치되어 있고 실행되는지 확인합니다.
  2. 브라우저 확장 목록에서 기존 DICO/구형 확장 설치 여부를 확인합니다. 파일 탐색기 주소창에 %LOCALAPPDATA%\DICO\app을 입력했을 때 runtime\node.exe와 central\package.json 등이 있으면 기존 설치일 수 있습니다. 폴더가 있다는 사실만으로 완전한 설치라고 판단하지 않습니다.
  3. 기존 관리 화면이 열린다면 새 설치보다 기존 화면의 설치·연결 진단과 업데이트를 먼저 사용합니다. 기존 폴더를 삭제하지 마세요.
  4. 소스 ZIP을 우클릭 → 모두 압축 풀기로 C:\DICO-Setup 같은 고정 로컬 경로에 풉니다. 안쪽에 setup.ps1과 package.json이 보이는 폴더가 기준입니다.
  5. 시작 메뉴에서 Visual Studio Installer 또는 설치된 앱의 Build Tools를 확인합니다. 없다면 Microsoft C++ Build Tools를 설치하고 ‘C++를 사용한 데스크톱 개발’(MSVC x64/x86 및 Windows SDK 포함)을 선택합니다. 이미 있다면 수정 화면에서 해당 구성 요소가 있는지만 확인합니다. 관리자 확인과 재부팅 요청은 화면에 따라 진행합니다.
  6. 준비 폴더 안 빈 공간을 Shift+우클릭해 PowerShell/터미널을 엽니다. 아래를 입력합니다. 이 옵션은 이 프로세스에서만 적용하며 영구 실행 정책을 바꾸지 않습니다.
    powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
    Node 24.13.0이 없으면 공식 파일을 내려받고 SHA-256을 확인해 이 폴더 안에 준비합니다. 빌드·검사·패키징·현재 사용자 설치·중앙 화면 열기를 진행합니다.
  7. 완료 후 위 4. 사용할 브라우저마다 확장 등록부터 따라갑니다. 고정 확장 경로는 %LOCALAPPDATA%\DICO\app\extension입니다.

터미널에 서비스를 실행하는 주소가 표시되고 계속 대기하면 그 창을 유지합니다. 중간 실패 시 마지막 오류 문구를 확인하고 같은 명령을 다시 실행합니다. 소스 준비 폴더를 옮기거나 삭제하면 참조 중인 준비 도구 경로가 달라질 수 있으므로 설치·업데이트 확인 전에는 유지합니다.

Git은 소스 ZIP의 최초 준비에는 필수가 아니지만 앱 내 자동 업데이트에 필요합니다. 위 ‘Git이 없다고 나옵니다’ 안내를 참고합니다.

자주 막히는 지점

증상확인 순서
응용 프로그램에 DICO가 없음현재 설치본은 DICO.app이 아닙니다. 먼저 설치 상태 검사를 실행하고, 관리 프로그램을 설치한 뒤 고정 경로의 extension 폴더를 선택합니다.
확장 폴더를 찾을 수 없음관리 프로그램 설치가 끝났는지 확인합니다. Mac 선택 창의 ⌘ Shift G에 정확한 경로를 붙여넣고, extension 안에 manifest.json이 있는지 확인합니다.
Brave에 계정이 안 보임Brave에도 확장을 따로 로드하고, Brave의 Discord 로그인 탭에서 계정을 등록합니다. Chrome 등록만으로 Brave가 연결되지는 않습니다.
현재 Discord 채널 연결 버튼이 회색현재 탭을 Discord 서버 텍스트 채널로 바꿉니다. 중앙관리 탭이나 다른 사이트에서는 비활성화가 정상입니다.
관리 프로그램과 연결 끊김관리 화면 열기 → 해당 브라우저 확장 ‘관리 프로그램 다시 연결’ → 설치·연결 진단을 확인합니다. 주소나 포트를 임의로 바꿀 필요는 없습니다.
입력만 되고 게시가 안 보임대시보드의 제한 대기·재시도 상태와 실제 Discord 게시 내역을 확인합니다. 게시 확인이 안 된 문구를 별도 창에서 추가 전송하면 중복될 수 있으므로 현재 시도를 먼저 확인합니다.
문제가 이미 해결됐는데 알림이 남음로그·분석에서 해결 상태 재검사를 사용합니다. 미확인 게시 결과는 실제 게시 내역을 확인한 뒤 처리합니다.
다른 PC도 연결하고 싶음현재 배포본은 PC별 독립 실행입니다. 한 PC의 중앙 페이지가 다른 PC 브라우저까지 제어한다고 가정하지 않습니다.

전달하는 사람용 확인

  • 받는 사람의 OS·CPU를 먼저 확인하고 올바른 ZIP과 이 안내서를 함께 전달합니다.
  • 자신의 ~/Library/Application Support/DICO 또는 %LOCALAPPDATA%\DICO 폴더는 보내지 않습니다. 계정·채널·메시지·기록이 들어 있습니다.
  • 이번 ZIP은 코드·공개 확장 키·Node/npm 런타임 및 안내서만 포함합니다. 개인 운영 DB·세션 토큰·Discord 로그인 정보는 포함하지 않습니다.
  • 처음 받는 사람은 기존 확장·계정 정보가 없어도 됩니다. 계정과 메시지는 자기 컴퓨터에서 새로 설정합니다.

검증 범위: macOS Apple Silicon 패키지 생성·압축 무결성·파일 구성 검사·가상 설치 상태 테스트. 실제 새 Mac의 Gatekeeper 통과, Windows 실행과 실제 Discord 게시 시험은 별도입니다.

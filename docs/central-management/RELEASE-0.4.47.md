# DICO 0.4.47 Discord 제출 조건 비교

## 확인 범위

Enter 직전 보이는 쿨다운, 화면에 숨은 카운트다운 요소의 유무, 편집기의 접근성 비활성·읽기 전용 상태, 폼의 명시적인 제출 버튼 비활성 상태를 기록한다. 값은 불리언이며 입력·HTML·본문은 보내지 않는다. 숨은 요소나 비활성 표시는 진단 근거이며, 발송을 막거나 대기 시간을 바꾸는 규칙으로 사용하지 않는다. 카운트다운 요소가 보이지 않아도 Discord 내부의 제출 제한이 없다는 의미는 아니다.

## 비교 방법

개발 환경에서 `node central/runtime/diagnose-discord-submit.mjs`를 실행하면 최근 24시간의 로컬 DB를 읽기 전용으로 조회한다. 다른 DB의 경로를 첫 인수로 지정할 수 있다. 보고서는 원문 계정·채널·문구·요청 식별자를 출력하지 않는다. `gateSamples`는 새로운 화면 신호를 갖춘 표본 수다.

- 브라우저별로 첫 Enter 직전부터 실제 POST까지 걸린 시간을 비교한다. 관찰기가 활성 상태이고 POST 한 건과 2xx 응답을 짝지을 수 있는 자동 완료 건을 사용한다.
- 교차 비교는 동일 계정·채널·문구 버전, 비슷한 직전 완료→Enter 간격(5초 구간), 같은 탭 가시성·포커스·쿨다운 관찰 조건에서 브라우저별 세 건 이상을 요구한다. 5초 이상을 지연으로 집계한다.
- 기존처럼 계정마다 브라우저가 하나씩 고정되어 있으면 `needs_same_account_channel_samples`로 표시한다. 같은 계정이 두 브라우저에서 동일한 조건으로 사용된 기록이 있어야 교차 결과를 출력한다.
- 동일 조건의 지연이 Brave에서만 재현되면 프로필·브라우저 경로를 우선 조사한다. 같은 계정에서 두 브라우저 모두 재현되면 계정·채널·공통 클라이언트 조건을 조사한다. 다른 계정도 같은 조건으로 비교해야 계정 효과를 분리할 수 있다.

운영 설정이나 로그인은 이 도구가 변경하지 않는다. 실제 비교에서는 같은 계정·채널을 동시에 실행하지 않으며, 관측 기준을 확보하기 위한 별도 강제 발송도 하지 않는다. 실제 지연 원인은 교차 표본과 제출 직전 상태를 함께 확인해 판단한다.

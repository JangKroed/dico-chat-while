# 발송 미확인과 초안 잔류 점검

## 2026-11-02 조사에서 확인한 사실

- Brave의 첫 순환은 게시 확인됐지만 다음 순환의 두 채널에서는 작성한 문구가 입력창에 남고 결과가 미확인으로 끝났다.
- 중앙 기록에는 준비와 허가 발급이 남았지만 상세 응답 사유가 `result_unknown`으로 대체돼 있었다. 이 기록만으로 Enter 미실행과 Enter 이후 게시 확인 실패를 구분할 수 없다.
- 기존 content 진단 이벤트를 중앙 실행기가 수신만 하고 버리고 있었다. 과거 대화·프로젝트 자료에도 이번 실제 Brave DOM 문제의 확정 원인은 없었다. 모의 DOM 회귀 검증을 실제 브라우저 검증으로 해석하지 않는다.

## 미확인 기록 처리

1. 해당 그룹 또는 전체 중지를 요청하고 확장의 실행 차단 확인을 기다린다.
2. 해당 계정·채널의 Discord 게시 내역을 확인한다. 입력창에 문구가 남았다는 이유만으로 미발송으로 확정하지 않는다.
3. 실제 게시됐다면 실행 기록 상세에 게시된 Discord 메시지 ID를 넣고 결과를 확정한다. 실제 미발송을 확인했고 실행 차단도 확인된 경우에만 미발송으로 확정한다.
4. 결과 확정으로 알림이 해결되는지 확인하고 초안을 보관·정리한 뒤 준비 상태를 점검한다. 미확인 시도를 다시 보내는 방식으로 확인하지 않는다.

## 회귀 점검 범위

- 같은 전용 탭과 계정에서 두 번 이상 순환, 긴 Markdown·줄바꿈·이모지 문구.
- 입력 준비와 실제 Enter, DOM 이벤트 전달과 게시 확인의 구분.
- React의 optimistic 메시지 노드 교체와 동일 본문 과거 게시물 구분.
- 탭 지연·포커스·selection·입력창 교체·중지·계정/채널 변경 시 전송 차단.
- 응답 유실·재연결·명령 중복 전달 시 Enter 중복 실행 금지.
- 민감한 메시지 본문 없이 실패 단계·증거를 기록하고 읽기 전용 재검사로 최초 원인을 덮지 않기.

자동 시험은 Discord의 실제 입력 모델을 완전히 재현하지 못한다. 실제 환경에서 재발하면 해당 시도의 새 진단 단계와 실제 게시 내역을 함께 확인한다.

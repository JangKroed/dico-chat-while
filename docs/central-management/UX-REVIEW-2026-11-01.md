# 계정·채널 등록 분리 UX 검토

검토 기준: 2026-11-01 작업 중 소스. 기존 화면과 이번 수정의 목표를 구분합니다.
이 문서는 코드·명세 검토 결과이며 실제 브라우저 GUI·모바일·Discord 발송을 검증했다는 뜻이 아닙니다.
계정·채널 분리 변경은 병행 구현 중이므로 아래 수용 기준 통과 전 완료로 안내하지 않습니다.

## 범위와 유지할 제약

- 현재 0.4는 PC 한 대의 로컬 중앙관리입니다. 좁은 화면 지원은 Android LAN 접속 지원을 의미하지 않습니다.
- Android 컨트롤러와 여러 PC의 조정은 [별도 설계](MULTI-DEVICE.md) 범위입니다.
- 등록·연결·저장과 발송 시작은 별도 행동입니다. 튜토리얼도 시험 메시지를 자동 전송하지 않습니다.
- 계정 증거는 Discord 화면에서 확인합니다. 토큰 입력·비밀 저장소 읽기·확인 불가한 계정의 우회 등록은 제공하지 않습니다.
- 미확인 발송을 실패로 취급하거나 자동 재전송하지 않습니다. 중지 요청과 중지 적용 완료를 구분합니다.
- 기존 [화면 명세](UX.md), [제품 정책](PRODUCT.md), [현재 설치 범위](../../central/README.md)를 함께 적용합니다.

## 확인한 문제와 개선 방향

| 기존 소스 근거 | 사용자에게 생기는 문제 | 개선 및 담당 |
| --- | --- | --- |
| `App.tsx` Connections가 브라우저와 연결 채널 중심이며 계정은 채널 속성으로 표시 | 먼저 어떤 계정을 등록했고 어느 채널에 사용할지 분리해서 이해하기 어려움 | UI: 계정 목록 → 채널 목록 → 계정·채널 연결을 구분 |
| 기존 팝업에 `현재 Discord 채널 연결`만 존재 | 계정 등록을 위해 먼저 서버 채널까지 찾아야 함 | 확장: Discord 홈에서도 계정 등록, 서버 채널 연결은 별도 행동 |
| Dashboard `fresh`가 어떤 데이터든 하나 있으면 참 | 브라우저만 연결한 미완료 사용자도 첫 설정 안내를 잃음 | UI: 객체 개수가 아닌 실제 단계 완료 상태로 안내 유지 |
| Settings 단계에서 `instances.length`, `channels.length` 등을 사용 | 끊긴 브라우저·미검증 채널도 완료처럼 보일 수 있음 | Core/UI: 현재 세션 검증·비어 있지 않은 목록·적용 버전을 조합 |
| 기존 팝업 공통 완료 문구가 `요청을 처리했습니다` | 계정 등록, 창 열기, 긴급 중지의 결과와 다음 행동을 알 수 없음 | 확장: 행동별 결과 및 후속 안내, 요청과 완료를 구분 |
| 전역 `모두 실행` 활성 조건이 busy와 그룹 존재 여부 중심 | 어떤 그룹이 막혔는지 실행 버튼을 누른 뒤에야 알게 됨 | UI: 실행 전 대상·차단 이유 요약. Core의 전체 원자적 검증 유지 |
| 계정 표시가 짧은 ID 중심 | Chrome·Brave의 여러 프로필과 여러 계정을 혼동하기 쉬움 | UI/Core: 계정 별칭, 브라우저 별칭, 계정 ID를 함께 표시 |
| 일반 요청 성공이 실제 적용 완료를 뜻하지 않음 | OPEN_CHANNEL ACK만 보고 연결 성공으로 오인할 수 있음 | Core/확장/UI: 명령 상태와 실제 관찰된 연결 상태를 분리 |

근거 파일: [중앙 화면](../../central/ui/src/App.tsx), [팝업](../../central/extension/popup.html),
[팝업 동작](../../central/extension/popup.js), [도메인 상태·명령](../../central/core/index.js).
표는 검토 시작 시 확인한 기존 구현을 기준으로 하며 병행 수정 이후 재확인이 필요합니다.

## 이번 변경에서 맡을 역할

| 구분 | 책임 | 완료로 판단할 증거 |
| --- | --- | --- |
| Core | accounts·targets 저장, 계정 검증 상태, `channel.connect`, `OPEN_CHANNEL` 명령 | 권한·세션·대상 검증을 통과한 요청 및 실제 채널 관찰 |
| 확장 | 현재 브라우저 계정 확인, 홈에서 계정 등록, 요청된 채널 창 연결 | 화면 계정 ID와 요청 계정 일치, 정확한 서버·채널 확인 |
| 중앙 UI | 계정·채널을 별도 목록으로 관리하고 두 항목을 선택해 연결 | 저장·대기·검증·적용 상태 및 다음 행동이 일관됨 |
| 팝업 | 브라우저 연결과 계정 등록의 시작점, 로컬 긴급 중지 | 행동별 결과, 현재 계정, 오류 해결 방법 표시 |
| 검증 | 기존 연결 데이터 이전, 실패·재연결·중복 클릭 검사 | 자동 테스트와 별도 GUI 검사 결과를 각각 기록 |

Core 작업본에서 `accounts`, `targets`, `channel.connect`와 `OPEN_CHANNEL` 추가를 확인했습니다.
이는 전체 사용자 흐름이나 배포본에서의 동작 완료를 뜻하지 않습니다.
계정은 브라우저 연결에 속하고, 채널 목록은 대상 서버·채널 정보이며, 실행 연결은 둘의 조합입니다.
같은 계정이 여러 브라우저에 등록됐다고 실행 담당을 자동으로 바꾸지 않습니다.

## 권장 사용자 흐름

1. 프로그램과 브라우저 연결을 확인하고 기존 실행기 중지 확인을 저장합니다.
2. 해당 브라우저의 Discord에서 계정을 등록합니다. 홈 화면의 계정 등록은 DM 발송 지원을 의미하지 않습니다.
3. 중앙에서 계정 별칭과 브라우저를 확인하고 서버 채널 URL을 별도로 등록합니다.
4. 계정과 채널을 선택해 연결을 요청합니다. 전용 창이 열리고 검증될 때까지 대기 상태를 보여줍니다.
5. 연결된 계정·채널에 문구와 버전을 적용하고 실제 적용 완료를 확인합니다.
6. 그룹의 참여 순서·간격·차단 사유를 확인한 뒤 사용자가 시작합니다.

단계별 대표 행동은 하나로 두고 이미 완료한 단계를 다시 강제하지 않습니다.
추가 Brave 프로필은 기존 메시지·채널 목록을 보존한 채 계정 등록부터 진행할 수 있어야 합니다.

## 반드시 지킬 세 가지 조건

### 1. 요청 성공을 연결 완료로 표시하지 않기

`채널 저장됨` → `연결 요청 보냄` → `전용 창 확인 중` → `계정·채널 검증됨`을 구분합니다.
브라우저의 명령 수신이나 창 생성만으로 채널을 그룹 실행 대상으로 활성화하지 않습니다.
대기 중에는 같은 연결 요청을 중복 생성하지 않고 오류 시 원인과 재시도 행동을 제공합니다.
연결 끊김·시간 초과·권한 없음에는 완료 표시 대신 확인 가능한 다음 행동을 보여줍니다.

### 2. 계정 변경을 기존 실행 연결에 자동 반영하지 않기

브라우저에서 로그인 계정이 바뀌면 이전 계정 카드는 재검증 필요로 표시합니다.
이전 그룹·문구·발송 기록을 새 계정에 조용히 연결하지 않습니다.
동일 계정의 여러 브라우저 등록을 구별하고 담당 브라우저와 검증 시각을 보여줍니다.
확인할 수 없는 계정은 등록 실패 이유를 안내하며 임의 ID 입력으로 검증을 대신하지 않습니다.

### 3. 준비 완료와 실제 발송을 구분하기

전체 실행 전 대상 그룹 수, 서버·채널, 계정 순서와 차단 사유를 표시합니다.
실행 중 그룹의 차례를 유지하며 하나라도 시작 불가하면 기존 원자적 취소 정책을 설명합니다.
오래된 상태나 연결 대기 상태를 준비 완료로 표시하지 않습니다.
전체 중지는 항상 찾기 쉬워야 하며, 누른 직후에는 중지 요청됨으로 표시합니다.

## 후속 개선 후보

- 첫 설정 안내를 완료 전까지 대시보드에 유지하고 각 차단 사유에서 관련 설정으로 바로 이동합니다.
- 긴 ID는 목록에서 줄이되 상세·복사로 원문을 확인하고 계정·브라우저 별칭을 우선 표시합니다.
- 성공 알림에 결과와 다음 행동을 함께 씁니다. 예: `계정 등록됨 · 중앙에서 채널을 선택하세요`.
- 상태 배지는 색뿐 아니라 텍스트를 사용하고 요청 중 표시를 스크린리더에 전달합니다.
- 모달의 최초 포커스·Escape·닫은 뒤 포커스 복원과 미저장 편집 보존을 점검합니다.
- 현재 범위 밖인 LAN, Android 원격 접속, 자동 계정 로그인은 안내에서 구현 완료처럼 표현하지 않습니다.

## 검증 체크리스트

아래는 전체 인수 검사 기준입니다. 구현 후 수행한 웹 UI 검사는 마지막 검증 메모에 기록했습니다. 실제 Discord·확장 연동 및 실기기 검사는 별도로 남아 있습니다.

| 환경·상황 | 통과 기준 |
| --- | --- |
| 새 PC 프로필·빈 데이터 | 계정 등록과 채널 등록이 별도 행동이며 다음 단계가 분명함 |
| Discord 홈·기본 아바타·로그아웃 | 홈에서 확인 가능한 계정만 등록; 증거 없으면 구체적 오류; 우회 없음 |
| 계정만 등록·채널만 저장 | 등록 개수는 표시하되 실행 준비 완료로 표시하지 않음 |
| Chrome 이후 Brave 추가 | 기존 데이터 유지, 브라우저별 계정·별칭·세션을 혼동하지 않음 |
| 연결 요청 연속 클릭·중복 ACK | 중복 창·중복 연결 없음; 검증 전 완료 표시 없음 |
| 권한 없는 채널·다른 계정·탭 이동 | 연결 실패 이유 표시, 잘못된 계정·채널 실행 금지 |
| 명령 대기 중 재접속·계정 전환 | 이전 세션 요청 무효화, 기존 그룹의 자동 재개·승계 없음 |
| 문구 저장·수신·적용 지연 | 세 상태 구분, 최신 적용 전 신규 발송 차단 |
| 전체 실행·전체 중지·미확인 | 영향 범위 명시, 일부 실패 원자적 취소, 요청·완료 구분, 자동 재발송 없음 |
| 1280px·1024px 데스크톱 | 목록·상세·오류·전역 중지 접근 가능, 긴 이름으로 버튼 가림 없음 |
| 390px 좁은 화면·200% 확대 | 메뉴·등록·연결·확인·중지 조작 가능, 표 가로 스크롤 범위 명확 |
| 키보드·스크린리더 | 입력 레이블·오류·대기 알림 전달, 포커스 순서와 복원 정상 |
| 기존 DB·백업 복원·초기화 | 계정·채널 목록 이전 중 중복 없음, 미확인·발송 증거 보존 |

모바일 화면 검사는 우선 PC 브라우저의 좁은 뷰포트로 수행합니다.
Android 실기기 원격 검사는 LAN 기능이 구현된 이후 별도 보안·연결 인수 검사로 기록합니다.

## 최종 검증 메모

0.4.1 구현 후 별도 임시 서비스와 합성 계정으로 실제 브라우저 UI를 확인했다. 계정 화면과 채널 화면 분리, 채널만 저장, 등록 계정 선택과 연결 요청 대기, 명령 거절의 한국어 원인·해결 순서와 관련 화면, 읽음 후 미해결 유지가 확인됐다. 375px에서 문서 폭과 화면 폭이 같아 가로 넘침이 없었다. 이 검증은 실제 Discord 발송·운영 데이터 변경·확장 설치를 포함하지 않는다. 계정이 등록된 뒤에는 반복적인 등록 안내를 접어 목록 접근을 줄였다.

추가 알림 검토: 작업 결과 문자열을 유지할 뿐 만료 처리가 없어 알림이 계속 남았고, 같은 문자열은 새 상태로 구분되지 않았다. 알림별 식별자와 취소 가능한 타이머를 도입해 성공 6초·오류 9초로 닫고 마우스·키보드 읽기 중에는 일시정지한다. API 오류의 영문 원문 대신 원인 코드별 한국어 조치 안내를 표시한다. 이 변경은 채널 검증을 우회하거나 미해결 문제를 자동 해결하지 않는다.

실제 임시 웹 UI에서 저장 알림의 표시·자동 소멸을 확인하고 같은 계정 표시 이름을 다시 저장해 동일 문구 알림이 다시 나타나는 것을 확인했다. 타이머 교체·중첩 일시정지·이전 콜백 무효화는 가상 시계 테스트로 검증했다.

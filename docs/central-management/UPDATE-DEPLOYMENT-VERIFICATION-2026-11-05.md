# 0.4.42 배포 경로 검증과 0.4.43 수정

검증일: 2026-11-05 KST. 기준 main: `cf18098`(PR #1 병합, 중앙관리/확장 0.4.42).

실제 Discord 메시지를 발송하지 않았다. 브라우저 프로필이나 운영 DB를 변경하지 않았고, 시험은 임시 디렉터리·합성 설정·가상 Chrome API만 사용했다.

## 기존 자동화 경로

1. 중앙관리의 기존 업데이트 요청은 설치된 버전의 `updater.mjs`와 Node를 별도 작업 폴더로 복사해 worker를 실행한다. GitHub main을 받아 사전 빌드 UI 검증, 확장 빌드, 배포 검사를 한다. 중앙관리의 새 릴리스를 무조건 무인 설치하는 주기 작업은 아니다.
2. 현재 안전 상태를 다시 확인하고 중앙 프로세스가 종료된 뒤 `app/central`과 `app/extension`을 교체한다. 런타임·실행기·사용자 DB는 교체 대상이 아니다. 새 프로세스의 HTTP 응답을 확인하고 이전 코드를 보관한다.
3. 각 확장의 기존 연결/heartbeat가 네이티브 `EXTENSION_STATUS`를 호출한다. Chrome·Brave 등록 경로에서 신원과 구조를 확인할 수 있는 배포 폴더만 동기화한다. 개발 저장소·다른 확장·심볼릭 링크는 덮어쓰지 않는다.
4. 파일 교체 뒤 `chrome.runtime.reload()`로 실행 중 워커를 갱신한다. 이어 기존 채널 탭의 콘텐츠 빌드를 확인하고, 유휴 상태의 이전 리스너를 해제한 뒤 새 콘텐츠를 주입한다. 탭 새로고침이나 메시지 입력을 이 과정의 기본 작업으로 사용하지 않는다.
5. 중앙·로컬의 실행/중지 확인/미확인 발송 보호 조건을 유지한다. 파일 교체, 워커 로드, 콘텐츠 로드는 각각 별도 단계이며 중앙 업데이트 완료만으로 모든 브라우저의 동기화를 주장하지 않는다.

## 재현한 결함과 수정

| 재현 조건 | 0.4.42 동작 | 0.4.43 동작 |
|---|---|---|
| 일시적인 runtime.reload 실패가 누적 | 3회 이후 영구 중단 | 기존 heartbeat에서 30·60·120·240·300초, 이후 최대 300초 간격으로 계속 재시도 |
| 워커 재생성/강제 확인 중 실패 대기 | 실패 간격이 워커 재생성에 보존되지 않음 | `nextAttemptAt`을 저장해 강제 확인도 대기를 우회하지 않음 |
| 배포 폴더 복구 순간 로컬 실행기가 바쁨 | 일회성 `repairedCopies`를 잃어 과거 reload 표식에 막힘 | 복구 신호를 저장해 다음 안전 시점에 재시작 |
| 콘텐츠 갱신용 상태 조회가 폴더를 먼저 복구 | updater 밖에서 복구 신호를 버림 | 모든 해당 상태 조회가 같은 복구 신호 저장 함수를 사용 |
| 같은 빌드의 추가 프로필 복구 | 신규 구현 리뷰에서 실패 대기를 초기화하는 결함 검출 | 기존 실패 횟수·시각을 보존하며 복구 신호만 병합 |
| 콘텐츠의 생성 빌드 표식이 잘못됨 | 해시 계산에서 제외한 표식을 검증하지 않아 설치 정상으로 판정 | manifest/콘텐츠 버전, 생성 build-info, 실제 파일 해시와 콘텐츠 빌드 표식을 함께 검증 |
| 새 앱 시작 실패 후 이전 코드가 현재 DB를 변경함 | 종료 증거만으로 이전 코드를 재시작 | 복제 DB에서 기존 호환 검사를 먼저 수행. 손실 가능 시 실제 DB와 두 코드 사본을 보존하고 복귀 보류 |

같은 빌드를 정상 reload했다고 기록했지만 여전히 구버전인 경우에는 복구 근거 없이 무한 reload하지 않는다. 정상 빌드가 실제 워커에 로드된 뒤 이전 표식을 정리한다. 등록된 복사본의 콘텐츠 표식만 손상된 경우도 단순 해시 일치로 건너뛰지 않고 정상 설치본으로 복구한다.

## 설정 보존과 실패 복귀

- 기존 확장 키·ID·권한과 chrome.storage 설정은 유지한다. 변경하는 저장 키는 업데이트 메타데이터인 `dicoUpdateReload`뿐이다.
- 계정·채널·문구·그룹·순서·간격과 실행 이력은 현재 DB에 보존한다. 과거 DB 백업으로 덮어쓰지 않는다.
- 실제 중앙 프로세스 시험에서 중지 그룹, 주소, 기존 UI 세션 쿠키를 유지하고 자동 발송이 시작되지 않았음을 확인했다.
- 부분 교체 예외, 빌드 실패, 최종 승인 거절, 살아 있을 가능성이 있는 프로세스, 훼손된 롤백 슬롯, 비호환 데이터에 대한 기존 보호 회귀를 포함한다.
- **초기 이행 한계:** 0.4.42에서 시작한 첫 업데이트는 0.4.42 worker가 실행한다. 신규 자동 롤백 호환성 검사는 새 버전이 설치된 뒤 시작하는 작업부터 적용된다. 새 코드가 과거 worker의 실행 흐름을 소급 변경할 수는 없다.
- 운영체제의 접근 거부, 검증할 수 없는 개발 폴더, 시작 실패 뒤 데이터 비호환 상태까지 성공으로 꾸미거나 안전 조건을 무시하지 않는다. 이번 시험은 전원 차단 중간 시점이나 Windows의 실제 파일 잠금 동작을 검증한 것이 아니다.

## 회귀 검증과 재실행

필수 환경: Node >=24.13. 빌드 개발 의존성은 `central`, UI 호환 패키지는 `central/ui`에 설치한다.

```sh
npm --prefix central ci
npm --prefix central/ui ci
npm run central:compile
npm test
npm run central:check
npm run check
```

추가 격리 설치 시험:

```sh
node --test tests/central-update-installed-runtime.test.js
legacy_dir=$(mktemp -d /tmp/dico-legacy-042.XXXXXX)
git archive cf18098 | tar -x -C "$legacy_dir"
DICO_TEST_LEGACY_ROOT="$legacy_dir" node --test tests/central-update-installed-runtime.test.js
```

기본 격리 시험은 같은 데이터 형식을 쓰는 합성 이전 설치를 사용한다. 두 번째 명령은 **cf18098의 실제 중앙 코드와 updater**를 사용해 0.4.42 → 후보 → 0.4.42 롤백 및 후보 시작 실패 후 0.4.42 복귀를 확인한다. 원격 소스 다운로드와 최종 승인 HTTP는 시험 대역이며, 실제 파일 교체·프로세스 종료 확인·재시작·HTTP health·UI 세션·설정 검사는 실제 코드로 실행한다. 기본 실제 프로세스 시험은 Linux와 macOS에서, cf18098 이행 시험은 macOS에서 통과했다.

macOS `/var` 별칭의 경로와 Node의 실제 파일 URL 차이로 초기 시험 fixture가 진입점을 실행하지 못하는 문제를 발견했다. fixture의 임시 경로를 realpath로 정규화한 뒤 macOS에서도 통과했다. 운영 설치를 수정해 통과시킨 것이 아니다.

핵심 회귀 파일:

- `central-extension-update-reliability.test.js`: 재시도·저장된 대기·두 상태 조회의 복구 신호.
- `central-extension-location.test.js`: Chrome/Brave에 해당하는 다중 프로필·배포 복사본 동기화, 실패 복원, 설정 파일 불변.
- `central-extension-version-build.test.js`: 버전/빌드 표식 훼손 거절과 실제 빌드 동기화.
- `central-content-lifecycle.test.js`: 실제 콘텐츠 코드를 VM에서 교체, 리스너 1개·초안 보존·발송 호출 없음.
- `central-updater.test.js`, `central-rollback*.test.js`: 잠금·승인·부분 교체·현재 DB 호환성·원본 보존.
- `central-update-installed-runtime.test.js`: 실제 중앙 프로세스의 업데이트·롤백·실패 복귀.

독립 리뷰에서 발견한 2건은 각각 실패 회귀를 확인한 후 수정했다. 최종 검증 수치는 PR과 아래 실행 결과에 기록한다.

최종 결과(macOS / Node 24.14.1): 전체 **1,282/1,282 통과**, 실패·스킵 0. `central:compile`의 TypeScript/프로덕션 UI/확장 빌드, `central:check`, `check`, `git diff --check` 모두 exit 0. cf18098 실코드 이행 시험 2/2 통과. 이 수치는 실제 Discord 게시 성공률 측정이 아니다.

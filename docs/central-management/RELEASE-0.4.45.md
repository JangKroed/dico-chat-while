# DICO 0.4.45 발송 지연 사전 진단

발송 지연은 허가 대기, 첫 Enter, 동일 초안의 재시도, 입력창 비움 관찰, 결과 저장으로 나누어 본다. 남은 쿨다운 0과 쿨다운 표시를 찾지 못한 경우는 서로 다른 관찰이다. Enter 이벤트의 기본 동작 취소 여부 역시 Discord가 서버에 제출했다는 근거와 구분한다.

| 단계 | 관찰 기준 | 대응 |
| --- | --- | --- |
| 첫 Enter 직전 | 같은 페이지·계정에서 최근 10분 내 입력창 비움으로 완료한 마지막 발송에 재시도가 3회 이상 있었고 현재 카운트다운 표시가 없음 | 위험 징후와 이전 횟수를 기록한다. 과거 이력으로 첫 Enter를 늦추거나 추정 쿨다운을 설정하지 않는다. |
| 각 Enter | 판독 가능 여부, 표시 유무, 남은 시간, 승인 결과, 이벤트 기본 동작 취소 여부 | 페이지 시각과 함께 중앙 기록에 보존한다. |
| 같은 초안 반복 | 세 번 이상 초안이 남았고 현재 판독이 가능한 0초임 | 다음 Enter 승인 전에 500ms 더 관찰한다. 실제 카운트다운이 있으면 기존 쿨다운 대기만 적용한다. |
| 늦은 완료·중지·초안 변경 | 관찰 또는 취소 신호 | 완료 근거를 재확인하고 다음 Enter를 차단한다. |

추가 대기는 기존 취소 가능한 확장 타이머를 사용한다. 정상 첫 발송에는 추가 대기가 없다. 같은 초안을 재입력하지 않으며 재시도 상한은 추가하지 않는다. 500ms 간격 조정은 반복 Enter 빈도를 낮추는 완화책이다. 원인이 서버 쿨다운인지, Discord 입력 이벤트 경로인지에 대한 판정은 실제 페이지 관찰을 대조해야 한다.

회귀 검증에서는 진단 전달 단계에서 값이 유실되는 경로, 동일 초안 반복 후 완료, 같은 페이지의 다음 차례에서 위험 징후 기록, 기존 중지·결과 확정·발송 순서 조건을 검사한다. 실제 Discord 실발송 검증은 별도다.

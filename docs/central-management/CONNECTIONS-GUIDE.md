# 계정과 채널을 나눠 설정하는 방법 · 0.4.3

계정은 브라우저별 로그인 신원이고, 채널은 메시지를 보낼 목적지입니다. 먼저 각각 등록한 뒤 ‘어떤 계정이 어떤 채널을 사용할지’를 연결합니다. 등록·연결·문구 저장만으로 발송하지 않습니다.

## 준비

중앙 프로그램은 0.4.3 이상, 브라우저의 전용 확장은 0.4.2 이상을 사용합니다. 0.4.3은 중앙 프로그램과 화면만 변경하며 확장 재로드를 요구하지 않습니다. 확장 팝업의 버전과 중앙 ‘설정 · 도움말 → 설치 · 연결 진단’의 프로그램 버전을 확인하세요. 기존 실행기는 중지·비활성화합니다. 브라우저 확장을 새로고침한 뒤 Discord 탭도 새로고침합니다.

기존 채널 연결은 유지하며 계정 목록과 채널 목록에 자동 반영합니다. 계정과 채널이 별도 화면으로 보이더라도 기존 그룹을 자동 재시작하지 않습니다. 현재 실행기는 계정 확인에 프로필 이미지가 필요하며 기본 아바타는 아직 지원하지 않습니다.

## 1. 계정 등록 · 각 브라우저에서 한 번씩

1. Chrome 또는 Brave에서 원하는 Discord 계정으로 로그인합니다. 친구 목록 화면에서도 등록할 수 있습니다.
2. DICO 확장 팝업을 열고 처음 한 번 기존 실행기 상태를 확인합니다.
3. **현재 Discord 계정 등록**을 누릅니다. 이 단계는 채널 창을 만들지 않습니다.
4. 중앙의 **계정 · 브라우저**에서 브라우저 종류, 계정 ID와 검증 상태를 확인하고 기억하기 쉬운 별칭을 정합니다.
5. 다른 브라우저나 프로필에서도 반복합니다. 같은 브라우저의 프로필 이름은 자동으로 읽지 않으므로 별칭을 사용합니다.

계정을 바꾸거나 로그인 상태가 사라지면 이전 계정이 새 계정으로 바뀌지 않습니다. 이전 계정은 재검증 필요로 남으며 새 계정은 다시 등록합니다.

## 2. 채널 추가 · 중앙에서 한 번

1. **채널 설정**에서 Discord 서버의 텍스트 채널 URL을 붙여넣습니다.
2. 표시 이름을 입력하고 **채널 추가**를 누릅니다.
3. 채널은 계정이 연결되지 않아도 목록에 저장됩니다. 같은 서버·채널을 여러 계정마다 중복 등록할 필요가 없습니다.

일반 URL: `https://discord.com/channels/서버숫자ID/채널숫자ID`. 친구 목록·DM·스레드 주소를 목적지로 사용하지 않습니다.

## 3. 사용할 계정 연결

1. 저장한 채널을 선택합니다.
2. 현재 검증된 등록 계정 중 사용할 계정을 선택하고 **선택 계정 연결**을 누릅니다.
3. 각 브라우저에 전송용 창이 열립니다. 해당 계정에 서버 접근 및 발송 권한이 있어야 합니다.
4. **채널 열기·검증 대기 → 연결 검증됨** 상태를 확인합니다. 요청 접수는 검증 완료가 아닙니다.

동일 연결을 반복 클릭해 창을 여러 개 만들지 않도록 대기 중에는 중복 요청을 막습니다. 실패하면 안내된 브라우저의 창·로그인·접근 권한을 확인하고 다시 요청합니다. 확장 버전이 기능을 지원하지 않으면 업데이트 안내를 표시합니다.

## 4. 메시지 적용과 실행

1. 메시지 보관함에서 문구를 저장합니다.
2. 채널 설정의 **계정별 메시지 · 주기**에서 연결된 계정을 선택합니다.
3. 문구와 순서를 적용하고 **확장 적용 완료**를 확인합니다. 계정·같은 채널의 주기는 기본 **슬로우 모드 기준 자동**이며 감지된 제한+3초를 사용합니다. 더 길게 직접 설정할 수 있지만 현재 최소값보다 짧은 새 값은 저장할 수 없습니다.
4. 발송 그룹에서 같은 목적 채널의 계정 순서와 그룹 간격을 저장합니다.
5. 준비 상태와 차단 이유를 확인하고 직접 시작합니다. 미확인 결과가 있으면 실행 기록에서 먼저 해소합니다.

‘모두 실행’은 준비되지 않은 그룹이나 같은 채널을 두 그룹이 소유하는 충돌이 있으면 실행하지 않습니다. 중지 확인 대기와 미확인 발송을 재개 버튼으로 건너뛰지 않습니다.

## 문제·알림 읽는 방법

알림에는 **무슨 작업인지 → 영향받은 브라우저·그룹·채널 → 확인된 원인 → 해결 순서 → 관련 화면 이동**을 표시합니다.

| 표시 | 해야 할 일 |
| --- | --- |
| 다른 초안이 있음 | 전송용 창의 초안을 확인하고 필요한 내용을 보관한 뒤 정리, 문구 적용 상태 확인 |
| 입력창 미준비·여러 입력창 | Discord 로딩·쓰기 권한 확인, 스레드·편집 창 정리 |
| 계정 확인 필요 | 해당 브라우저의 로그인 계정 확인 후 확장에서 재등록 |
| 설정 불일치 | 채널·계정·수정본 선택을 확인하고 다시 적용, 확장 적용 완료 대기 |
| 탭의 확장 응답 없음 | 확장과 Discord 탭 새로고침, 계정·연결 재확인 |
| 중지 명령 거절 | 전체 중지와 모든 확장 ACK 확인, 계속 막히면 버전 일치·재연결 후 중지 재요청 |
| 상세 거절 사유 미기록 | 과거 로그에 원인이 없는 상태. 원인을 추정하지 않고 안내 순서대로 연결과 결과를 확인 |

**읽음은 해결이 아닙니다.** 실제 조건이 해소돼야 해결됨으로 바뀝니다. 현재 문제는 미해결만 기본 표시하고 ‘해결된 기록 포함’으로 지난 기록을 볼 수 있습니다. 미확인은 실패·미발송을 의미하지 않으며 실제 게시 결과를 확인해야 합니다.

## 잠깐 표시되는 화면 알림

오른쪽 아래 작업 결과 알림은 성공 6초, 오류 9초 후 자동으로 닫힙니다. 같은 내용이 다시 발생해도 새 알림으로 표시되고 시간이 다시 시작됩니다. 마우스를 올리거나 닫기 버튼에 키보드 초점을 두면 읽는 동안 시간이 멈춥니다. ×로 직접 닫을 수도 있습니다.

화면 알림이 사라져도 로그의 문제를 읽음·해결됨으로 바꾸지 않습니다. 미해결 문제는 알림 센터와 로그에서 계속 확인하세요. 계정·채널 검증 오류가 뜨면 브라우저 연결 표시만 보지 말고, 확장에서 계정을 등록한 뒤 ‘채널 설정’의 해당 계정·채널 연결이 검증됐는지 확인하세요. 브라우저 연결과 채널 검증은 별도 상태입니다.

## 미해결 알림을 실제로 정리하기 (0.4.2)

로그·분석 → 현재 문제 → **미해결 알림 한 번에 재검사**를 누릅니다. 하나만 검사하려면 해당 알림의 **해결 상태 재검사**를 누릅니다.

발송 결과가 이미 확정됐거나 안전하게 삭제된 지난 그룹의 요청이면 해결됨으로 이동합니다. ‘해결된 기록 포함’을 켜면 사유와 기록을 다시 볼 수 있습니다. 진행·미확인 발송, 중지 확인 대기, 판단 근거 부족은 남겨 두고 관련 화면과 이유를 표시합니다. 검사 자체는 그룹을 실행하거나 미발송으로 확정하지 않습니다.

브라우저 연결·채널 검증·메시지 적용·그룹 상태가 실행 조건입니다. 미해결 알림 개수 자체는 실행 차단 조건이 아닙니다. 삭제된 예전 그룹의 알림이 남았더라도 현재 그룹을 별도로 점검합니다.

## 사이드 패널에서 현재 채널 연결

확장 아이콘을 누르면 브라우저 옆에 연결 패널이 열립니다. **현재 Discord 채널 연결**이 첫 버튼이며, 현재 활성 탭이 Discord 서버 채널이어야 사용할 수 있습니다. 친구 목록·DM·다른 사이트·로딩 중에는 비활성화 사유를 표시합니다. **채널 설정 열기**는 중앙 관리의 채널 페이지를 여는 별도 버튼입니다. 사이드 패널 API가 없는 브라우저에서는 작은 팝업으로 동작합니다.

## 연결 복구 후에도 알림이 남는 경우 (0.4.3)

OPEN_CHANNEL 요청 실패·대상 채널 불일치가 기록됐더라도 이후 같은 브라우저·계정·서버·채널의 최신 연결이 검증됐다면 **해결 상태 재검사**로 해결됩니다. 계정 등록만 완료했거나 다른 채널이 연결된 것으로는 해결하지 않습니다. 이 검사는 과거 발송 여부와 그룹 차례를 바꾸지 않습니다.

## 자동 주기와 직접 설정

감지된 슬로우 모드 60초는 최소63초,120초는 최소123초, 확인된0초는 최소3초입니다. 미감지는 감지 대기로 표시하고 알려진 제한 또는 기본 여유3초를 기준으로 합니다. 직접 설정은 현재 최소값 이상만 저장합니다. 기존 설정이 최소값 이하이면 자동으로 이전하고, 더 길면 직접 설정 의도를 보존합니다.

제한이 늘면 실제 주기는 그 이상으로 늘고, 줄면 자동 기준 또는 보존한 직접 설정값 이상으로 돌아갑니다. 진행·미확인 발송 중에는 구성 버전을 덮어쓰지 않고 결과 확정 후 동기화합니다. 주기만 바뀌어도 메시지 순서는 초기화하지 않습니다.

그룹 간격은 다른 계정에게 차례를 넘기기 전 대기이며 새 그룹 기본값은1초입니다. 기존 그룹의 저장값은 그대로입니다. 계정별 최소 주기와 그룹 간격을 모두 만족해야 다음 차례를 준비합니다.

이미 잡힌 이번 회차의 대기는 주기를 낮춰도 보수적으로 유지할 수 있습니다. 다음 게시 이후부터 낮아진 주기를 사용하며 화면의 다음 진행 시각으로 실제 남은 대기를 확인합니다. 준비 도중 제한이 증가하면 전송 직전 다시 검사하고 필요하면 일시정지합니다.

# 0.4.33 안정성·사용자 흐름 개선

## 조사 범위와 판단
중앙 SQLite 상태/사건 트랜잭션, 확장 세션·명령 대기열·하트비트, 탭 복구, 자동 제보 저장/전송, UI 상태와 이전 0.4.26~0.4.32 수정 이력을 검토했다. 발송 엔진을 사용자용/진단용으로 복제하지 않고 동일 명령과 결과를 사용한다. 테스트 개수만으로 실제 수신자 환경의 해결을 주장하지 않는다.

## 재현한 원인과 수정
| 원인 | 수정/검증 |
| --- | --- |
| 중지 재시도 소진 후 재접속에서 과거 rejected CONTROL이 현재 완료 판정에 포함 | 이전 세션 명령을 superseded로 보존하고 현재 적용 ACK로 판단. unknown 결과/잠금은 유지 |
| 안전 조건 때문에 탭 복구를 보류해도 횟수를 소비 | 실제 복구 시도와 보류를 분리, 3회 한도·지수 대기·단일 실행 적용 |
| 이전 세션 응답·탭 생성 완료가 중지 후 상태를 변경 | 세션/초기화/중지 경계를 재확인하고 새로 생성한 탭만 보상 정리 |
| 자동 제보가 본문 포함 선호를 상속 | 자동 제보 저장/재전송 모두 본문·이름·자유 텍스트를 제외 |
| 전송 대상이 abort에 협조하지 않으면 전체 제보 큐가 멈춤 | 독립 타임아웃과 늦은 응답 무효화. 기본 8회 후 종료 상태 보존 |
| 보고서와 색인 저장 사이 종료 시 제보가 누락될 수 있음 | 저널을 먼저 fsync하고 시작 시 같은 ID로 큐 복원 |
| 로그·과거 오류를 사용자 현재 작업 상태와 혼합 | 일반 사용자 대시보드와 개발자 진단 모드 분리. 과거 사건만으로 현재 실행을 실패로 표시하지 않음 |

## 사용자 경험
기본 메뉴에서 실행 기록·로그 분석을 제외한다. 설정의 개발자 진단 모드에서 다시 볼 수 있다. 이것은 화면 선호이며 인증/권한 체계가 아니다. 일반 사용자도 현재 그룹, 시작·중지, 다음 발송 조건과 최근 확인된 발송 결과를 볼 수 있다. 자동 제보는 동의·저장·전송 상태 중심으로 제공하며 수신 주소/키·수신함·수동 내보내기는 진단 화면으로 옮긴다.

중단 접수와 적용 완료를 구분한다. 읽기 전용 대조 명령이 실제 대기/처리 중일 때만 자동 확인 중으로 표시한다. 근거가 부족하면 성공/미발송을 만들지 않고 안전하게 보존한다. 같은 원인의 새 사건은 이전 사건 ID와 발생 순번으로 추적하되 각 사건의 해결 근거는 독립적으로 유지한다.

## 복구 정책
- 발송/준비 재시도: 기본 추가 3회, 설정 범위 0~10회. 구형 무제한 설정과 활성 시도는 유한 한도로 이행하되 누적 횟수·미확인 상태는 유지한다.
- 연결 탭: 안전 차단은 시도 예산을 소모하지 않으며 주기적으로 조건을 재확인한다. 실제 실패는 최대 3회이고 동일 장애의 무한 재무장은 금지한다.
- 중단: 새 발송 차단과 진행 작업 취소를 유지한다. 긴급 중지 중에도 제어 하트비트는 계속 수신한다.
- 미확인 발송: 기존 증거 확인만 자동으로 수행하며 불명확한 메시지를 재전송하지 않는다.
- 제보: 동의 범위 내에서 로컬 보관·백오프 재전송·수신 영수증 확인. 기본 8회 종료 후 파일은 보존 정책에 따라 관리한다. 접수 확인은 실제 받은편지함 도착과 구분한다.

## 검증과 한계
단위/통합 회귀, 실제 로컬 HTTP 송신→수신함, 상태 저장 후 재시작, 독립 Chrome 프로필의 일반/진단 모드·중지 경합·모바일 화면을 검증 대상으로 삼는다. 최종 실행 결과는 이 문서 아래에 추가한다.

실제 전달받은 사용자의 빠른 Discord 채팅, 로그인·권한 UI, 실제 macOS/Windows 설치 사용자의 장시간 운용은 이번 환경에서 직접 재현하지 못했다. 기존 합성 DOM 빠른 메시지 유입/제거 테스트는 회귀 검사이며 실서비스 재현과 다르다. 이미 OS/브라우저에 제출한 API를 취소할 수 없어 완료 후 보상 처리하는 경우가 있다. 읽기 전용 증거가 끝내 부족한 발송, 실제 로그인/권한 문제, 복구 예산 소진까지 모두 자동 해결됐다고 주장하지 않는다. 실패는 사용자에게 디버깅을 요구하는 대신 현재 작업 영향과 제보 상태로 전달한다.

## 최종 실행 결과
- 전체 Node 테스트: 1,130개 통과, 실패/제외 0개.
- TypeScript/Vite 컴파일, 사전 빌드 검증, 확장 44개 JavaScript/manifest/CSP 및 루트 검사 통과.
- 독립 Chrome: 일반 화면 기본값, 직접 진단 URL 접근 처리, 진단 모드 저장/새로고침, 저장 응답 대기 중 중지, 메시지 저장/수정, 모든 메뉴, 긴 상세창, 390px 모바일 화면/메뉴, 콘솔 오류 없음 확인.
- 실제 로컬 HTTP 제보 수신함/영수증 통합 테스트 통과. 실제 이메일이나 Discord 메시지는 발송하지 않음.
- 자동 제보 동의 철회 시 대기/진행 중 자동 전송 중단, 늦은 응답 무효화, 수동 전송 동의 분리 검증.
- 테스트 변경: 이전 무제한 정책은 이번 유한 재시도 요구로 대체했다. 기존 안전성 검사는 유지했으며 중지 후 진단 전송도 금지하는 정책으로 해당 기대값을 바꿨다.

# 실행기의 정상 미발송 재시도 — 최종 요청 반영

사용자의 최종 요청에 따라 정상 미발송 재시도 횟수 옵션을 제거한다. 과거 설정의 0·3·10·null은 모두 내부의 계속 시도 정책으로 이행한다. 이는 오류가 난 작업이나 결과가 불확실한 작업을 무한히 다시 실행한다는 뜻이 아니다.

## 실행 경계

- 실행기에서 content로 전달하는 내부 `maxSendRetries`는 공유 정책 함수로 정규화한다. PREPARE 저장, 재시작 후 저장된 시도 로드, 명령 일치 비교에도 동일 규칙을 사용한다.
- 횟수 자체를 이유로 정상 미발송의 다음 재시도 또는 Enter를 거절하지 않는다. 각 재시도는 직전 승인 횟수와 연속되어야 하며 누적 횟수를 초기화하지 않는다.
- 재시도 대기와 실제 Enter 승인은 각각 중앙에 요청한다. 동일 탭·계정 설정·세션·실행 상태·중지 상태가 유효해야 한다.
- `unknown`, `confirmed`, `not_sent`, `cancelled` 상태는 실행 중 입력 권한이 없다. 미확인 결과를 정상 미발송으로 간주하여 재실행하지 않는다.
- 중지, 연결 해제, 세션 교체 및 실제 오류의 기존 차단은 유지한다. ACK 통신 재요청과 자동 연결 복구의 제한된 재시도는 이번 정책 변경 대상이 아니다.

## 검증

`tests/central-executor.test.js`는 과거 설정 0·3·10·null 각각에서 정상 재시도 대기와 입력 승인이 12회까지 이어지는지 확인한다. 이어 같은 시도를 `unknown`으로 바꾸거나 긴급 중지하면 추가 입력과 재시도가 모두 차단되는지 검증한다. 구형 설정이 content로 전달되기 전에 정규화되는지, 재시작 로드가 미확인 상태와 누적 횟수를 보존하는지도 검사한다.

`tests/central-retry-executor.test.js`는 실제 중앙 코어와 실행기를 연결하여 동일 시도의 재시도 12회가 승인되고, 최종 완료 전까지 재생 목록과 그룹 순서가 진행하지 않는지 검증한다. 완료 후 재생 목록은 한 번만 진행한다. 모든 Discord 호출은 모킹되어 실제 메시지를 발송하지 않는다.

# 중앙 관리 UI/UX 독립 리뷰 — 2026-11-02

## 검토 범위와 증거

- 대시보드, 계정·브라우저, 채널, 메시지, 그룹, 실행 기록, 로그·분석, 설정의 React/CSS 및 상태 계산 코드를 읽었다.
- 사용자가 제공한 화면에 대한 상위 작업자의 설명: 자동 연결 영역이 큰 풀폭 카드 3개를 반복하고, 단계 번호가 좁으며, 브라우저 이름과 연결 상태가 중복되고, 네 단계의 시각적 구분이 약하다. 이 리뷰 작성자는 원본 이미지를 직접 열지 않았다. 아래의 **화면 보고**는 이 설명을 뜻한다.
- **코드 확인**은 코드에서 해당 구조나 처리 방식을 확인했다는 뜻이며, 실제 사용자 DB의 상태나 브라우저의 렌더링을 검증했다는 뜻은 아니다.
- 실제 Discord 전송, 운영 DB, 브라우저 자동 조작을 사용하지 않았다. 대비비는 아래에 명시한 색 쌍의 계산값이며, 전체 화면의 접근성 인증이 아니다.
- 우선순위 P0는 이번 UI 개선의 선행 수정, P1은 후속 개선이다. 데이터 손실·잘못된 실행 같은 보안 심각도 분류와는 다르다. 이 문서는 승인 기록이 아니다.

## P1 — 주요 흐름별 개선

| 화면·주제 | 코드에서 확인한 문제 | 통과 조건 |
| --- | --- | --- |
| 공통 편집 이동 | `go()`가 편집 상태를 확인하지 않고 화면을 교체한다. 화면 내 일부 dirty 확인과 달리 사이드바 이동에는 보호가 없다. 그룹 목록 선택과 편집 닫기도 dirty 확인을 우회한다. 메시지의 내부 dirty 비교에는 태그가 빠져 있다. | 메시지·채널·그룹·설정 편집 후 화면 이동, 뒤로 가기, 선택 변경 시 일관된 보호 또는 초안 복원이 있다. 태그만 바꾼 경우도 동일하다. |
| 계정·브라우저 | 이름, 브라우저 종류, 계정 ID, 연결 상태가 여러 카드와 안내에 반복된다. 계정 준비 여부와 브라우저 연결은 별도 개념이나 첫 실행 안내가 같은 비중으로 계속 노출된다. | 계정 이름/검증 상태/연결 브라우저/필요 행동을 한 번씩 명확하게 읽는다. 브라우저 연결만으로 계정 검증 완료로 표시하지 않는다. 상세 ID와 버전은 필요시 펼친다. |
| 채널 설정 | 계정 연결 안내와 전송 창 설명이 길고 메시지 목록·주기·적용이 아래에 이어진다. 읽어야 할 영역에 비해 현재 선택과 완료 상태의 시각적 구분이 약하다. | 채널 선택 → 계정 연결 → 메시지 적용을 분리해 현재 작업이 보인다. 성공한 단계는 짧게 요약하고 문제에만 설명을 확장한다. 중앙 저장과 확장 적용 완료는 계속 구별한다. |
| 그룹 | 5단계 안내가 운영 화면에도 반복된다. 그룹 상태, 현재 시도, 다음 차례, 실행 차단 이유가 여러 패널에 분산된다. ‘실행 전 확인 · 시작’의 마지막 확인은 일반 브라우저 confirm이다. | 선택 그룹의 상태 → 다음 차례/대기 이유 → 실행/중지 조치 순으로 읽힌다. 실제 발송 전 대상 채널·계정 순서·적용 문구·간격이 같은 맥락에서 확인된다. 설정 저장을 실행 완료로 표현하지 않는다. |
| 실행 기록 | 검색 결과가 없을 때에도 ‘실행 기록이 없습니다’로 안내한다. 최대 100건만 표시하며 이전 기록 탐색은 검색에 의존한다. 선택은 필터 변경 후 유지되지만 선택된 비표시 항목 수가 즉시 드러나지 않는다. | 0건 저장 상태와 검색 0건을 구별한다. 결과 제한과 이전 기록 접근 경로가 명확하다. 일괄 확정 전 보이지 않는 선택 건수와 대상 범위를 확인한다. 미확인 결과를 임의로 확정하지 않는다. |
| 로그·문제 | 현재 문제에 원인·영향 대상·확인 순서가 있는 점은 유지할 가치가 있다. 다만 관련 화면 이동은 페이지 단위라 해당 그룹/시도에 바로 도달하지 못한다. 분석은 내부 영문 key와 원시 숫자를 그대로 나열한다. | 관련 문제에서 같은 대상의 상세/필터로 이동한다. 분석값은 이름·단위·기간을 명시하고 알 수 없는 필드는 숨기거나 기술 상세로 분리한다. 읽음과 해결을 계속 구별한다. |
| 설정 | 업데이트·진단·시작 가이드가 메인 열, 실제 환경 설정과 데이터 작업이 다른 긴 열에 있다. 한 화면에 설치·운영·파괴적 작업이 모두 쌓인다. | ‘화면·알림’, ‘설치·업데이트’, ‘데이터 관리’처럼 목적별 구획을 탐색할 수 있다. 백업/초기화는 독립 영역이며 기존 확인과 실행 중 차단을 보존한다. |

## 키보드·모바일·동작

- **코드 확인:** 실행 기록/로그 모달에 dialog 표시는 있지만 Escape 처리, 포커스 가두기, 닫은 뒤 원래 버튼으로의 복귀가 없다. 실제 키보드 동작은 별도 확인해야 한다.
- **코드 확인:** 모바일 사이드바는 transform으로만 숨긴다. 닫힌 메뉴가 Tab 순서에서 제외되는지 검증하고, 열 때 포커스 이동·Escape 닫기·포커스 복귀를 추가한다.
- **코드 확인:** 탐색 버튼에 현재 페이지의 `aria-current`가 없다. 로그 탭은 tab 역할이 있으나 연결 tabpanel, 방향키 이동, roving tab index 구현이 없다.
- **코드 확인:** 모바일에서 서비스 연결 문구는 `font-size:0`으로 숨기고 점만 남긴다. 연결 실패 이유와 재시도 동작은 모바일에서도 읽을 수 있어야 한다.
- **코드 확인:** 사이드바 transition은 있으나 `prefers-reduced-motion` 대응은 없다. 상시 애니메이션으로 상태를 대신하지 말고, 감소 설정에서는 불필요한 이동을 제거한다.
- **검증 필요:** 390px, 768px, 1440px에서 양 테마를 캡처한다. 긴 한국어 이름·큰 ID·여러 계정·오류 메시지로 줄바꿈을 검사한다. 표 내부 스크롤은 허용하되 전체 페이지 가로 스크롤과 조치 버튼 잘림은 없어야 한다.
- **검증 필요:** 키보드만으로 메뉴 → 검색 → 편집 → 저장/취소 → 모달 열기/닫기를 완료한다. 필수 조치는 최소 24px 포인터 영역을 확보하고 모바일 주요 조치는 더 넓힌다. 1초 단위 카운트다운은 보조 기술에 반복적으로 낭독되지 않아야 한다.

이 리뷰 작성자는 제품 코드를 변경하지 않았다. 기존 테스트 통과나 릴리스 사실은 이번 시각·키보드·운영 상태 검증을 대신하지 않는다.

| P0-01 정보 우선순위 | 실행/확인 필요 통계와 문제 배너가 연결보다 앞에 온다. 정상 연결은 접히는 요약으로 바뀌었고 브라우저별로도 상세를 접는다. 대시보드는 계정·대상 채널·메시지 목록·그룹 구조가 이미 있으면 첫 실행 안내를 숨긴다. 브라우저가 끊겨도 초기 안내가 다시 나타나지 않는다. 다른 화면의 모든 단계 완료 안내는 5칸 대신 짧은 요약과 그룹 보기로 축약됐다. |
| P0-02 단계 의미 | 완료 관측값과 전체 차단 여부를 분리했다. 첫 미완료 단계만 진행/확인 필요이며 뒤는 대기다. 알 수 없는 blocked 사유도 ‘연결·설정 완료’로 표시하지 않는다. 실제 설정 적용이 끝났으면 차단 때문에 해당 관측값을 false로 바꾸지 않는다. 관련 화면 행동이 추가됐고 상태 수신 지연/기존 실행기 문제는 계정·브라우저로, 미확인 발송은 실행 기록으로 이동한다. |
| P0-03 테마·가독성 | 별도 의미 기반 토큰으로 양 테마를 구성하고 기존 하드코딩 대비 문제를 제거했다. 본문/메타 크기, 포커스와 reduced-motion 처리, 긴 브라우저 이름 줄바꿈이 개선됐다. 토큰 대비 테스트는 계산한 색 조합의 근거이며 실제 렌더링 전체의 대비 검증은 남는다. |
| P0-04 수신 시각 | 대시보드가 `lastSeen`을 받아 ‘마지막 수신’을 표시한다. 일반 재연결을 업데이트 때문으로 단정하는 상단 문구도 수정됐다. |
| P0-05 대시보드 분석 | 로딩/실패/정상 상태, 이전 같은 기간 결과와 수신 시각, 재시도 버튼이 추가됐다. 당일 snapshot 값 대체는 제거됐다. 이전 요청을 active 플래그로 폐기한다. 재검토에서 발견한 ‘기간 변경 후 실패가 무한 로딩으로 보이는 문제’도 요청 시작에 period를 바꾸고 다른 기간 데이터를 비워 수정했다. 로그 분석 탭에도 같은 로딩/실패/선택 기간 처리와 재시도 경로가 반영됐다. |
| 편집 보호 | 메시지(태그 포함), 채널, 그룹, 설정에 화면 이동 guard가 추가됐고 뒤로 가기도 검사한다. 실제 이동/취소/복귀 시나리오와 브라우저 탭 종료 보호는 아직 검증하지 않았다. |
| 모달 접근성 | 공통 helper에 Tab 경계 순환, Escape 닫기, 열기 트리거 추적/포커스 복귀, 배경 inert 저장/복원, body overflow 저장/복원이 추가됐다. summary와 상속 disabled 및 tabIndex=-1을 필터링한다. Escape는 기존 닫기 경로를 사용하며 실행 결과나 저장 데이터를 변경하는 코드는 없다. 순수 포커스 인덱스 테스트만으로 DOM/보조 기술 동작을 보증하지 않는다. |
| 모바일·탐색 | 닫힌 모바일 사이드바를 visibility로 숨겨 포커스 대상에서 제외하도록 수정했다. summary에도 명시적인 포커스 링이 있고 현재 페이지에 aria-current가 추가됐다. 메뉴 열기/닫기의 포커스 관리와 탭 방향키 이동은 여전히 별도 확인 대상이다. |

실제 브라우저 검증은 환경에서 실행되지 못했다는 상위 작업자의 보고를 받았다(격리 브라우저 실행 SIGABRT, 원격 명시 경로 ENOENT). 따라서 모바일 캡처, 200% 확대, 실제 모달 키보드 순서, 스크린리더와 운영 데이터 상태를 통과했다고 기록하지 않는다. 개선 후에도 P1의 추가 대상 바로가기, 미등록 진단 코드의 명칭, 검색 0건·선택 범위, 설정 정보 구조 등은 이 표에서 명시적으로 해결한 항목 외에는 남아 있다.

## 공통 색상 조합 검증

측정 대상은 `design-tokens.css`의 실제 선언과 컴포넌트에서 사용하는 색상 역할 조합이다. WCAG 전체 적합성이나 실제 픽셀·모든 상호작용의 통과를 의미하지 않는다.

생산용 React 컴포넌트의 서버 렌더 검사로 운영 요약 순서, 정상 연결 상세의 기본 접힘, 계정 별칭, 의미 있는 단계 구조, 분석 로딩·실패와 0건의 구분을 검사한다. 이 검사는 실제 브라우저의 레이아웃·터치·스크린리더 검사를 대체하지 않는다.

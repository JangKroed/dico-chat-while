# 0.4.32 사용성 검토 및 개선

## 판단 기준
사용자가 직접 로그를 해석하고 반복 조작하는 부담을 줄인다. 프로그램이 관찰·복원·검증하고 처리 상태를 알려야 한다. 초안 삭제, 불명확한 발송의 재전송, 사용자 중단 후 자동 실행은 복구로 간주하지 않는다.

## 발견과 반영
| 마찰 | 개선 |
| --- | --- |
| 저장/조회 중 중지 버튼까지 비활성화 | 중지·일시정지를 공용 busy에서 분리하고 명령별 중복 요청 관리 |
| 전체/그룹 중지에 확인창 | 확인창 없이 바로 요청. 실제 발송을 시작하는 시작/재개 확인은 유지 |
| 명령 성공 뒤 상태 조회 실패를 작업 실패로 표시 | 접수 성공과 화면 갱신 실패를 분리해 재입력을 유도하지 않음 |
| POST 전 시작한 GET을 저장 결과로 표시 | 변경 뒤 갱신은 이전 요청 종료 후 새 조회 수행 |
| 전체 실행 불가 이유가 hover 안내에 머묾 | 대시보드 본문에서 준비 사유와 그룹별 이동 제공 |
| 문제마다 긴 수동 해결 목록이 펼쳐짐 | 원인·대상·행동은 유지하고 수동 확인 절차는 접힌 보조 설명으로 제공 |
| 로그 탭을 바꿔도 이전 검색어가 숨겨진 필터로 남음 | 탭 전환 시 검색/레벨 필터 초기화 |
| 정상 연결 중 관리 탭 소실은 복구가 호출되지 않음 | 관찰 결과에서 tab_missing을 감지해 저장 연결 복구 예약 |
| 없는 탭도 새로고침하라고 안내 | TAB_MISSING을 콘텐츠 교체 실패와 분리하고 자동 복원에 맡김 |

## 자동 복구 조건
계정 확인이 유지된 등록 탭만 대상으로, 동일 장애에 10초 간격 최대 3회 복원을 시도한다. 정상 관찰 후 다시 발생한 장애는 새로 예약한다. 실행 중·미확인 시도 또는 긴급 중지가 있으면 횟수를 소비하지 않고 대기한다. 복구 함수는 중앙의 RECOVERY_STATUS와 등록 상태도 다시 검사한다. 사용자가 다른 URL로 이동한 탭이나 초안은 강제로 새로고침하지 않는다. 계정 로그인 등 프로그램이 수행할 수 없는 동작은 자동 해결로 가장하지 않는다.

## 검증 범위
요청 접수/갱신 실패 분리, 중단과 저장의 동시 진행, 중복 클릭, 탭 복구 간격/상한/금지 조건, 실제 recoverConnections 연결을 테스트한다. 전체 회귀 테스트 및 독립 브라우저 프로필의 화면 검증을 수행한다. 실제 Discord 발송은 검증 중 실행하지 않는다.

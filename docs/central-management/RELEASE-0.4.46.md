# DICO 0.4.46 Discord 제출 구간 진단

Enter 이벤트 처리와 Discord 서버 요청은 별개다. 이 버전은 중앙 실행기의 관리 탭에서 진행 중인 발송과 탭·세션·채널이 일치하는 Discord 메시지 POST의 시작과 결과를 기록한다. 기존 Discord 호스트 범위에서 읽기 전용 webRequest 이벤트를 구독한다. 본문·헤더·쿠키·응답 본문·URL·요청 ID는 로그에 보내지 않는다. 요청 ID는 메모리에서 시작과 응답을 짝짓는 데만 사용한다.

| 로그 | 확인할 수 있는 범위 |
| --- | --- |
| 첫 Enter의 networkObserverReady | 실행기에 관찰 이벤트가 등록됐는지 여부 |
| network-start | 실행 중 동일 탭·채널에서 관찰한 요청 시각과 시도 내 관찰 순번 |
| network-result 429 | 요청에 HTTP 속도 제한 응답이 돌아옴. 서버의 구체적인 제한 정책이나 원인은 응답 코드만으로 구분할 수 없음 |
| network-result 2xx / 4xx / networkError | 각각 HTTP 성공 응답 / 클라이언트 오류 응답 / 브라우저 네트워크 오류. 게시·입력창 비움과는 별도로 비교 |
| Enter만 관찰 | 해당 구간에 일치하는 요청을 관찰하지 못함. 관찰기 상태, 샘플 한도, 요청 방식과 탭 문맥을 함께 확인 |

시도당 최초 12개 요청을 관찰하며 입력 재시도 로그 한도와 구분한다. 진단은 발송 권한, 시간, 성공 판정이나 중지 경로를 바꾸지 않는다. 사용자가 같은 관리 탭에서 직접 제출하면 관찰만으로 자동 Enter와 구별할 수 없으므로 진단 중 직접 제출과 겹친 표본은 제외한다. 관찰로 브라우저 효과와 계정 효과가 분리되지 않으면 동일 계정·채널을 한 브라우저씩 사용하는 교차 비교가 필요하다.

# DICO 0.4.60 — 연결 지연과 작업 진행 표시

## 영상에서 확인한 현상

2026-11-09 13.52.24 화면 기록(76.45초)의 채널 설정에서 계정별 상태가 연결 검증, 브라우저 연결 끊김, 계정 재등록 필요 사이에서 바뀐다. 이미 연결된 계정도 선택 대상에서 제외되므로 “연결 가능한 계정 0개”가 전체 연결 실패처럼 보인다. 영상만으로 해당 PC의 Native 연결 실패 원인을 확정할 수는 없다.

## 원인과 수정

- 주기 heartbeat가 탭 검사와 자동 복구까지 기다리는 single-flight 작업이었다. 느린 탭 검사 중에는 다음 heartbeat와 명령 조회가 시작되지 않았다. 검사·복구를 별도 single-flight로 분리하고, 최초 복구 전에 heartbeat 타이머를 시작한다. 탭 검사 실패로 정상 Native 연결을 해제하지 않는다. 실제 통신 실패의 재연결 처리는 유지한다.
- 계정 선택과 전송 창 제어 일부는 중앙 heartbeat를 화면 PC 시각과 비교했다. snapshot의 중앙 시각을 기준으로 통일한다. 15초 신선도 제한은 완화하지 않는다.
- 모든 공용 변경 요청에 작업명, 스피너, 경과 시간, 접수/화면 갱신 단계를 표시한다. 10초 이상 지연되면 성공·실패 미확인임을 명시하며 재전송하지 않는다. 다른 저장 작업 중에도 전체 중지는 가능하다.
- 전송 창 요청은 HTTP 응답 후에도 queued/received 브라우저 명령이 남아 있으면 처리 상태를 표시한다.
- 연결 완료, 일시적 대기, 구체적 검증 오류를 분리한다. 실제 오류는 무기한 로딩 안내로 숨기지 않는다. 이미 연결된 계정의 재선택이 불필요함을 안내하고 “추가 연결 가능” 수로 표현한다.

## 검증

- 수정 전 재현: 느린 관찰 중 두 번째 heartbeat가 진행되지 않음; 중앙과 화면 PC 시간이 다르면 계정/창 제어가 비활성화됨; 접수/갱신 단계 통지 없음.
- 전체 Node 테스트: 1,374 통과, 실패/건너뜀 0.
- TypeScript, Vite 프로덕션 빌드, 사전 빌드 무결성, 확장 빌드, 중앙 JS/manifest/CSP 검사 통과.
- SSR: 6개 명시적 오류와 미검증 계정이 동시에 존재해도 오류 문구를 보존하고 스피너를 표시하지 않는 검사 포함.
- `node scripts/central-progress-browser-check.mjs`: 격리 Chrome에서 지연 POST, 중복 클릭 방지, 동시 중지, 접수 후 갱신, 종료 시 표시 제거, 스크롤 중 진행 표시, 1440px/390px 채널 상태·가로 넘침 검사 통과. 실제 Discord 계정 연결 및 발송 없음.
- 독립 코드 리뷰에서 발견한 오류 사유 은폐를 수정하고 재검토 완료.

기존 `central-ui-browser-check.mjs`는 현재 제품에서 제거된 “개발자 진단 모드”를 기다리다 실패한다. 이번 변경의 브라우저 검증은 위 별도 스크립트로 완료했으며 기존 전체 브라우저 스크립트 통과로 보고하지 않는다. 실제 제보 PC에서 재발하지 않는지에 대한 운영 검증은 업데이트 적용 후 로그로 확인해야 한다.

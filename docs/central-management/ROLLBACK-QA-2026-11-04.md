# 코드 롤백 독립 QA

검토 범위는 로컬에 보관된 직전 정상 코드 한 벌을 사용하는 되돌리기다. 실제 사용자 설치나 Discord 발송은 실행하지 않았으며, 임시 디렉터리와 SQLite 복제본만 사용했다.

## 확인한 결함과 보완

최초 호환 검사 구현은 현재 DB를 복제해 구버전 코어로 열고 `schemaVersion === 1`인지 확인했다. 같은 스키마 번호를 반환해도 구버전의 시작 마이그레이션이 메시지, 사용자 설정, 과거 이벤트를 삭제하거나 변경할 수 있었다. 세 경우 모두 거절을 기대하는 회귀가 실제로 실패했다.

`verifyRollbackCompatibility`에 복제본 실행 전후 비교를 추가했다.

- 원본은 SQLite 읽기 전용 연결과 backup API로만 접근한다.
- 기존 사용자 필드의 삭제·값 변경, 배열 길이·순서 변경을 거절한다. 기존 값을 유지하며 기본 필드를 추가하는 것은 허용한다.
- 실제 발송 결과·자원 잠금·문구·계정/그룹 설정은 비교 대상이다.
- 이전 이벤트 ID 구간의 ID·시간·유형·내용 전체 해시가 같아야 한다. 새 시작 이벤트 추가는 허용한다.
- 기존 종료 구간 이력은 유지되어야 한다. 열린 구간의 정상 종료와 새 구간 추가는 허용한다.
- 시작 때 바뀌는 서비스 메타데이터·세션·연결 검증·계산된 deadline만 명시적으로 제외한다.
- 대기 명령을 `superseded`로 차단하는 시작 동작은 허용하며 그 외 명령 데이터는 보존한다.
- 구버전 시작 후에도 전체 코드 교체의 중지 조건을 만족해야 한다.
- 실패한 복제 DB와 WAL/SHM은 제거한다. 실제 DB를 과거 백업으로 덮어쓰지 않는다.

이는 보수적인 검사다. 기존 데이터의 변경이 무해하다는 근거를 확인하지 못하면 되돌리기를 거절할 수 있다. 단순 스키마 번호가 같다는 이유로 통과시키지 않는다.

## 검증 행렬

| 경계 | 기대 결과 | 독립 검증 |
| --- | --- | --- |
| 정상 복제 검사 | 원본 DB 바이트 불변, 임시 DB 정리 | 통과 |
| 메시지 삭제 | 호환 불가 | 통과 |
| 현재 보존기간 변경 | 호환 불가 | 통과 |
| 과거 이벤트 삭제 | 호환 불가 | 통과 |
| 확정 결과를 미발송으로 변경 | 호환 불가 | 통과 |
| 자원 잠금 삭제 | 호환 불가 | 통과 |
| 종료된 구간 이력 삭제 | 호환 불가 | 통과 |
| 실제 현 코어 시작의 세션/연결 초기화·대기 명령 차단 | 호환 가능, 원본 불변 | 통과 |
| 활성·허가됨·차단된 unknown·중지 의도 | 전체 코드 롤백 금지 | 통과 |

명령: `node --test tests/central-rollback-review.test.js`

**독립 회귀 9개 통과.** 파일 무결성·경로·확장 ID, 오프라인 작업자, 단일 잠금, 부분 교체/재시작 실패 복원, 신규 설치의 이전 코드 보관은 담당 구현의 `central-rollback.test.js` 및 `central-updater.test.js`와 함께 최종 통합 검증한다.

확장만 갱신하는 경로에서는 실행 차단된 unknown을 유지한 채 갱신할 수 있으나, 관리 프로그램 전체 코드 롤백에서는 해당 시도도 차단 대상이다. 두 정책을 서로 대체하지 않는다.

# 보관함 문구 수정 자동 반영

## 변경 동작

보관함의 문구를 저장하면 연결된 모든 채널이 그 문구의 최신 버전을 자동으로 사용한다. 채널마다 버전을 다시 적용할 필요가 없다. 구버전 UI가 과거 `revisionId`를 보내도 해당 버전의 존재를 검증한 뒤 현재 보관함 버전으로 정규화한다.

- 실행 중인 시도가 없는 채널은 설정 버전을 갱신하고 확장에 동기화한다. 실제 적용 ACK 전에는 새 발송을 시작하지 않는다.
- 현재 입력 준비·허가·발송·미확인 시도가 있으면 그 시도의 본문, revision, configVersion을 변경하지 않는다. `pendingPlaylist`에 다음 목록만 저장한다.
- 현재 시도가 종료된 뒤 다음 차례부터 새 문구를 적용한다. 보관함 저장 때문에 그룹을 일시정지하거나 추가 발송을 만들지 않는다.
- 연속 수정은 가장 최근 저장본만 다음 목록에 남긴다.
- 자동 갱신은 문구 순서, playlistIndex, 그룹 cursor와 사용자 목록 편집 version을 초기화하지 않는다. 확장의 실제 적용 버전인 configVersion은 갱신한다.
- 사용자가 이미 수동 편집한 대기 목록은 그대로 존중한다. 그 목록에서 빠진 문구를 되살리지 않고 남아 있는 문구의 버전만 최신화한다.
- 오프라인 채널도 최신본을 저장하며 재연결 관찰 때 해당 설정을 전달한다.
- 미확인 결과는 그대로 보존하고 잠금·재개 제한도 유지한다.

## 과거 데이터

기존 DB의 채널에 남은 이전 버전 고정은 시작 시 최신 보관함 버전으로 이행한다. 활성 시도가 있으면 현재 설정을 건드리지 않고 다음 목록에 예약한다. 재시작의 기존 미확인 처리·실행 차단은 바꾸지 않는다.

백업은 문구 revision 이력을 검증한 뒤 현재 보관함 버전으로 연결을 복원한다. 선택한 문구 순서와 다음 위치는 유지하며 그룹은 중지 상태로 복원한다. 실제 과거 발송의 revision과 기록 본문은 수정하지 않는다.

## 검증

수정 전에 신규 5개 회귀가 모두 실패했다. 다중 채널 동기화, 활성 시도의 최신본 예약, 미확인 상태 보존, 기존 수동 대기 목록 존중, 구버전 UI의 과거 revision 입력이 재현 대상이었다.

추가 회귀에서는 오프라인 재연결, 사용자 편집 버전 보존, 백업 이행, 저장된 대기/활성 연결 이행을 검증했다. 기존 ‘보관함 수정 후에도 이전 문구 발송’ 테스트는 새 요구와 직접 충돌하므로 ‘자동 동기화 ACK 전에는 발송 금지, ACK 후 새 문구 발송’으로 변경했다. 과거 revision 삭제 보호 검증은 유지했다.

```sh
node --test tests/central-message-propagation.test.js \
  tests/central-domain.test.js tests/central-control-completion.test.js \
  tests/central-slowmode-schedule.test.js tests/central-resume-deadlines.test.js \
  tests/central-rollback-review.test.js
```

관련 **163개 통과, 실패 0개**. 모든 검증은 임시 데이터와 가상 프로토콜을 사용했으며 실제 Discord 메시지는 발송하지 않았다.

## 0.4.36 통합 검증

전체 1,183개 테스트 통과(실패·건너뜀 0), TypeScript/Vite 빌드·구문/manifest/CSP 검사 통과. 실제 코어와 세 확장 실행기의 36회 순환 중 여섯 번째 준비에서 보관함 수정을 주입해 현재 여섯 번째는 기존 문구, 이후 30회는 최신 문구를 발송하며 계정 순서와 실행 상태가 유지됨을 검증했다. 수정 이력·발송 증거용 내부 식별자는 보존하지만 사용자가 선택하거나 재적용하는 UI는 제거했다.

# 자동 오류 제보와 관리자 수신함 (0.4.24)

문제가 발생하면 DICO가 진단을 수집해 관리자 수신 주소로 전송한다. 사용자가 JSON을 다운로드해 메신저로 전달할 필요가 없다. 파일 내보내기·가져오기는 백업용으로 계속 제공한다.

## 관리자 최초 설정

1. 관리자 기기의 중앙관리기에서 `설정 · 도움말 → 자동 오류 제보`를 연다.
2. `이 관리 프로그램에서 제보 수신`을 켜고 설정을 저장한다.
3. `수신 인증 키 표시`를 눌러 제보 전용 연결 키를 확인한다. 이 키는 중앙관리기 로그인·확장 연결 키와 별개다. 공개 게시하지 않는다.
4. 사용자가 접근할 수 있는 수신 주소를 전달한다. 주소 끝은 `/api/support/receive`다.
   - 같은 내부망: 관리자의 `다른 기기 접속`에서 내부망 접속을 활성화하고, 표시된 접속 주소 뒤에 `/api/support/receive`를 붙인다.
   - 다른 인터넷 망: 관리자 DICO 수신 경로로 전달되는 HTTPS 주소가 필요하다. `127.0.0.1`·`192.168.x.x`는 다른 인터넷 망의 사용자에게 전달할 수 있는 공용 주소가 아니다. 기존 HTTPS 프록시나 VPN의 접근 주소를 사용한다. HTTPS 프록시는 이 제보 경로를 내부 DICO 주소로 전달하고 `Host`를 해당 내부 주소·포트로 설정해야 한다. DICO의 Host·Origin 검증을 끄지 않는다.
5. 받은 보고서는 같은 설정 화면의 `관리자 수신함`에 나타난다. 제보를 열면 환경·버전·시도 당시 메시지·단계별 로그·설정·재시도·진단 결과를 볼 수 있다.

프로그램은 공용 서버나 도메인을 자동 구매하거나 외부에 관리 화면을 공개하지 않는다. 현재 배포에 공용 수신 주소가 없다면 수신 기능 구현만으로 다른 인터넷 망에서 도착할 수는 없다. 수신 주소 연결은 최초 한 번 필요하다.

## 사용자 최초 설정

1. `설정 · 도움말 → 자동 오류 제보`를 연다.
2. `관리자에게 진단 전송 허용`과 `문제 발생 시 자동 제보`를 켠다.
3. 관리자가 전달한 수신 주소와 연결 키를 입력한다.
4. 메시지 본문과 표시 이름의 포함 여부를 선택한다. 자동 전송에서는 기본적으로 제외한다. 메시지 내용을 분석하려면 본문 포함을 켠다. 토큰·쿠키·확장 세션·연결 비밀 키는 보고서에서 제외한다.
5. 설정을 저장한다. 이후 새 오류는 자동으로 대기열에 등록되고 전송된다. 상태는 전송 대기·전송 중·접수 완료·실패를 구분한다.

`관리자에게 바로 전송`은 선택한 시도의 보고서를 직접 대기열에 등록한다. 이 경우에도 전송 동의와 수신 주소가 필요하다. 개별 전송의 본문·이름 옵션은 저장된 동의보다 더 많이 포함할 수 없다.

## 재시도·보관·표시

- 수신처 미설정, 네트워크 장애, 접수 응답 유실 시 보고서를 디스크에 보관하고 자동 재시도한다.
- 수신 서버의 접수번호를 받아야 전송 완료로 표시한다. 응답 유실 뒤 같은 보고서가 도착해도 관리자 수신함에는 중복 등록하지 않는다.
- 프로그램 재시작·업데이트 뒤 대기열과 제보 설정을 이어 사용한다.
- 제보 전송 실패는 발송 그룹을 중지하지 않는다. 진단 저장소 오류도 발송 서비스 시작을 막지 않는다.
- 자동 제보는 기능을 켠 뒤 새로 열린 문제를 대상으로 한다. 과거 기록은 `관리자에게 바로 전송`으로 보낼 수 있다.
- 내부망 HTTP는 암호화되지 않는다. 화면에 이를 표시하며, 다른 인터넷 망의 수신 주소는 HTTPS를 요구한다.
- 이 화면의 전송 보관 기간은 제보 대기열·수신함에 적용된다. 기존 발송 로그의 보관 기간은 별도다.

# 여러 PC 실행기와 Android 컨트롤러 설계

상태: **여러 PC의 실행기를 통합하는 기능은 향후 구현 설계입니다.** 같은 소유자가 다른 PC에서 기존 중앙 화면만 여는 기능은 [주소로 내부망 접속 안내](REMOTE-ACCESS.md)를 사용합니다. 다른 PC의 Discord 실행기를 중앙에 연결하는 기능과 구분합니다.

확정한 사용 방식은 같은 LAN의 여러 PC·브라우저를 한 PC에서 조정하고, Android는 브라우저로 제어·조회하는 것입니다.
Android를 서버나 Discord 메시지 실행기로 사용하지 않습니다.

## 1. 현재 기능과 목표

| 항목 | 현재 0.4 | 계획 |
| --- | --- | --- |
| 중앙 서버 | 로컬 주소 + 선택한 사설 IP의 관리 화면 | 선택한 중앙 PC의 인증된 HTTPS LAN 주소 |
| 실행기 | 같은 PC의 Chrome·Brave 확장 | 여러 PC의 로컬 서비스와 Chrome·Brave 확장 |
| Android | 주소·연결 코드로 관리 화면 접속 | 로그인한 컨트롤러·대시보드 |
| 발송 순서 | 한 로컬 관리 프로그램 안에서 조정 | 중앙 PC가 모든 등록 실행기의 전역 순서를 조정 |
| 접근 권한 | 현재 OS 사용자 중심 | 소유자·장치·역할별 인증과 권한 |
| 연결 설정 | 네이티브 호스트의 로컬 연결 | 장치 페어링과 명시적 승인 |

현재 서버 주소를 `0.0.0.0`으로 바꾸거나 포트만 열어서는 이 목표를 달성할 수 없습니다.
현재 브리지 자격증명을 다른 PC나 Android에 복사하지 않습니다.
현재 사용법은 [클론 설치 안내](CLONE-SETUP.md)를 따릅니다.

## 2. 장치 역할과 설치

| 역할 | 필요한 구성 | 담당 |
| --- | --- | --- |
| 중앙 PC | 중앙 서비스·영속 DB·관리 UI | 유일한 스케줄러, 명령 승인, 순서 및 결과 기록 |
| 실행 PC | 실행기 로컬 서비스·네이티브 호스트·브라우저 확장 | 자기 브라우저의 계정·채널 검증과 승인된 발송 |
| Android | 지원 브라우저·신뢰할 수 있는 HTTPS 연결 | 메시지 편집, 상태 조회, 시작·중지 등 허용된 제어 |

중앙 PC가 실행 PC 역할을 함께 맡을 수 있습니다. 실행 전용 PC에는 별도 중앙 스케줄러를 만들지 않습니다.
실행 PC의 로컬 서비스는 기존 네이티브 메시징 연결을 유지하고 중앙 PC에 인증된 연결을 엽니다.
Android에는 Node, Git, MSVC, 확장 프로그램 설치가 필요 없습니다.
소스 빌드 PC에만 Git·지원 Node/npm 및 Windows C++ 빌드 도구가 필요합니다.
배포 패키지에는 역할에 필요한 런타임을 포함하는 방향으로 설계합니다.

로그인 자동 시작은 PC별 명시적 선택 사항입니다. 모바일 상시 실행이나 화면 유지 의무는 없습니다.
Android 화면이 꺼져도 중앙 PC와 실행 PC가 정상인 동안 작업은 중앙 정책에 따라 계속됩니다.
Android가 연결되지 않은 상태에서는 원격 중지 요청이 전달됐다고 표시하면 안 됩니다.

## 3. 중앙 조정과 소유자별 데이터

중앙 PC의 영속 DB를 구성·발송 차례·시도 상태의 단일 기준으로 사용합니다.
메모리 타이머나 Android 세션을 전역 순서의 기준으로 사용하지 않습니다.
장치 ID, 실행기 ID, 소유자 ID, Discord 계정 ID는 서로 다른 식별자입니다.

- 소유자별로 메시지와 구성의 소유권을 기록하고 서버에서 조회·수정 권한을 검사합니다.
- 실행기는 자신에게 배정된 계정·채널·명령과 필요한 메시지 내용만 받습니다.
- 공유 그룹에 참여할 권한과 다른 소유자의 메시지 원문을 볼 권한을 구분합니다.
- 관리자에게 필요한 전역 조정 정보와 민감한 메시지 내용의 접근 범위를 별도로 정의합니다.
- 백업·로그·검색·실시간 이벤트에도 같은 소유자 경계를 적용합니다.

전역 그룹의 순서가 A → B → C라면 실행 PC 위치와 관계없이 이 순서를 지킵니다.
A 성공을 확정한 뒤 B, B 성공을 확정한 뒤 C를 승인합니다.
실행 불가능한 차례를 자동으로 건너뛰거나 다른 실행기가 대신 발송하지 않습니다.
동일 Discord 계정은 한 시점에 하나의 실행기만 소유하도록 중앙에서 제한합니다.
다른 PC의 기존 확장이나 독립 중앙 서비스가 동시에 발송하지 않도록 사용자 확인도 필요합니다.

## 4. 네트워크와 HTTPS

LAN도 신뢰된 인증 경계로 취급하지 않습니다. IP 주소만으로 장치를 인증하지 않습니다.
무인증 LAN 바인딩, 인증 없는 제어 API, 임의 Origin 허용을 도입하지 않습니다.
로컬 네이티브 브리지와 원격 장치 API는 서로 다른 자격증명·권한 경계를 가집니다.

원격 UI와 실행기 연결은 신뢰 검증을 통과하는 HTTPS를 사용합니다.
Android에서 일반 LAN HTTP 주소는 loopback과 같은 예외를 기대할 수 없습니다.
보안 컨텍스트가 필요한 브라우저 기능도 고려하여 실제 모바일 브라우저에서 검증해야 합니다.
자체 서명 인증서는 QR을 읽는 것만으로 신뢰되지 않습니다.
주소의 호스트명과 인증서 이름이 일치해야 하며 인증서 발급·갱신·신뢰 설치 방식을 출시 전에 확정합니다.

인증서 오류 무시, 브라우저 보안 해제, 사용자 몰래 루트 인증서 설치를 연결 절차로 삼지 않습니다.
수동 인증서 신뢰가 필요한 배포 방식이면 영향과 제거 방법을 안내하고 사용자가 직접 선택합니다.
HTTPS와 모바일 신뢰 검증이 준비되지 않으면 LAN 제어를 활성화하지 않습니다.
방화벽 허용은 사용할 PC·네트워크 범위와 포트를 설명한 명시적 단계로 둡니다.
공유기 포트 포워딩이나 공용 인터넷 공개는 초기 범위에 포함하지 않습니다.

## 5. 발견과 페어링

1. 중앙 PC에서 역할·접속 주소·HTTPS 상태를 확인하고 장치 추가를 시작합니다.
2. 중앙은 짧게 만료되는 일회용 nonce와 접속 정보를 QR 또는 수동 입력 형태로 제공합니다.
3. 실행 PC 또는 Android가 해당 주소에 접속하고 장치 이름·요청 역할을 제출합니다.
4. 중앙 화면에서 대조 코드를 확인하고 소유자 및 권한을 선택해 승인합니다.
5. 승인 후 장치별 자격증명을 발급하고 nonce는 폐기합니다. 만료·재사용 요청은 거부합니다.
6. 중앙의 장치 목록에서 연결 상태를 확인하고 필요하면 권한을 변경하거나 연결을 취소합니다.

QR에는 장기 브리지 비밀이나 관리자 자격증명을 담지 않습니다.
페어링 시도에는 횟수·시간 제한을 적용하고 승인 없이 장기 자격증명을 발급하지 않습니다.
장치별 자격증명은 역할·소유자·대상 범위로 제한하며 개별 폐기와 갱신을 지원합니다.
모바일 세션에는 HTTPS용 보안 쿠키, CSRF 및 Origin 검증을 적용합니다.
장치 폐기 시 기존 세션·실시간 연결도 종료하고 보류 명령의 권한을 다시 확인합니다.

호스트명, QR, 수동 주소를 기본 발견 경로로 제공합니다.
mDNS 자동 발견은 선택적 편의 기능이며 Android·공유기·게스트 Wi-Fi에서 항상 된다고 가정하지 않습니다.
게스트 네트워크 격리, VPN, 방화벽, 주소 변경은 별도 진단으로 안내합니다.
주소가 바뀌어도 IP만 보고 다른 서버를 기존 중앙으로 자동 신뢰하지 않습니다.

## 6. 발송 명령과 연결 단절

각 발송 시도에는 전역 고유 attempt ID, 명령 ID, 대상 실행기, 구성 버전, 순서 정보가 있습니다.
중앙은 허가 전에 시도를 영속 기록하고 실행기는 실행 전 수신·중복 처리 상태를 영속 기록합니다.
중복 명령은 새 발송으로 바꾸지 않고 저장된 동일 시도의 상태를 반환합니다.
오래된 세션·만료 허가·이전 중앙 실행 세대의 명령을 실행하지 않는 규칙이 필요합니다.

허가 이후 통신이 끊어지면 실제 게시 여부를 모를 수 있습니다.
이 시도는 `UNKNOWN`으로 보존하고 해당 전역 순서의 후속 발송을 막습니다.
단절을 실패 또는 미발송으로 추정해 자동 재전송하지 않습니다.
재연결 시 확정된 게시 증거와 저장된 시도 기록으로 조정하며 모호하면 사용자 확인을 요구합니다.
외부 Discord 게시까지 포함하는 절대적인 exactly-once 보장을 표시하지 않습니다.

중앙 장애 시 실행기는 새로운 독립 스케줄을 시작하지 않습니다.
이미 받은 허가가 실행됐을 가능성은 중앙 복구 시 `UNKNOWN` 대상으로 보존합니다.
자동 중앙 승격·자동 failover·다른 실행기의 대체 발송은 초기 구현 범위 밖입니다.
중앙 재시작과 실행 PC 절전 복귀 후에는 명령 세대와 미확인 시도를 조정한 뒤 수동 재개합니다.
백업 복원으로 오래된 허가가 살아나지 않도록 복원 시 새 실행 세대를 발급해야 합니다.

## 7. 자동 설정의 경계

자동화 대상은 역할 선택 후 필요한 파일 준비, 버전 진단, 로컬 호스트 등록, 연결 검사와 안내입니다.
OS 설치 권한, 방화벽 승인, 인증서 신뢰, 중앙의 장치 승인, 브라우저 확장 로드는 수동 단계가 남습니다.
Discord 로그인·계정 검증·기존 실행기 중지 확인을 설치 성공으로 대신하지 않습니다.
메시지 이전과 소유자 배정은 미리보기를 제공하고 권한 있는 사용자가 확정합니다.
재검사는 설정·발송 상태를 바꾸지 않으며 연결됨과 실행 준비 완료를 구분합니다.

## 8. 구현 단계

1. **권한 모델:** 소유자·장치·역할 스키마와 데이터 접근 테스트, 기존 로컬 데이터의 소유자 이전.
2. **보안 연결:** HTTPS 배포 방식, 모바일 신뢰 검증, 페어링·폐기·세션 및 LAN 진단.
3. **원격 실행기:** 로컬 브리지 유지, 중앙 연결, 영속 중복 방지와 세대·허가 검증.
4. **전역 조정:** 여러 PC의 고정 순서, 계정 독점, `UNKNOWN` 조정과 장애 후 수동 재개.
5. **Android UI와 배포:** 반응형 대시보드, 재접속·충돌 처리, 역할별 설치·제거 및 복구 안내.

각 단계의 테스트가 통과하기 전 문서와 화면에서 해당 기능을 사용 가능으로 표시하지 않습니다.

## 9. 인수 검증

| 상황 | 통과 기준 |
| --- | --- |
| 여러 PC의 A → B → C | 지연과 재연결에도 성공 확인 전 다음 차례를 승인하지 않으며 순서를 건너뛰지 않음 |
| 허가 전·후 네트워크 단절 | 새 무단 발송 없음. 결과 불명 시 `UNKNOWN` 유지, 자동 재전송·후속 진행 없음 |
| 실행기 절전·재부팅 | 오래된 명령 거부, 영속 시도 복구, 실제 결과 조정 후 수동 재개 |
| 명령 중복·역순 전달 | 동일 시도를 다시 발송하지 않으며 버전·세대 불일치 명령 거부 |
| Android 화면 종료·재연결 | 중앙 작업 유지, 최신 상태 재조회, 중복 제어 방지, 오프라인 명령 자동 재생 없음 |
| 소유자 분리 | 다른 소유자의 메시지·백업·로그·이벤트와 변경 API에 직접 접근해도 거부 |
| 중앙 PC 장애·복구 | 실행기의 독자 진행·자동 승격 없음. 불명 시도 및 전역 차례 보존 |
| 같은 계정의 두 PC 등록 | 경쟁 소유와 동시 허가 거부, 명시적 이전 과정에서 기존 허가 무효화 |
| 페어링·장치 폐기 | 만료·재사용 nonce 거부, 미승인 장치 차단, 폐기된 세션·명령 접근 차단 |
| 모바일 HTTPS·발견 실패 | 실제 Android에서 신뢰 확인, 인증서 오류 차단, mDNS 없이 수동 연결 가능 |

실제 Discord 발송 검증은 별도 승인된 시험 계정·채널에서 실시합니다.
그 전에는 모의 전송 계층으로 장애 지점별 테스트를 반복하고 자동 재전송이 없음을 확인합니다.

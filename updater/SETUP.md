# DICO 자동 업데이트 최초 설치

지원: macOS 12 이상(Apple Silicon/Intel), Windows 10/11, Chrome·Brave.
별도 Python·Node.js 설치나 관리자 권한은 필요 없습니다.

## 최초 한 번

1. DICO 확장을 **0.2.41 이상**으로 한 번 설치하고 확장 관리 화면에서 새로고침합니다. 구버전에는 보조 프로그램 연결 기능이 없어 이 최초 적용은 필요합니다.
2. 설정을 백업하고 모든 채널을 중지합니다.
3. OS에 맞는 보조 ZIP을 풀고 Mac은 `DICO Updater.app`, Windows는 `DICO-Updater.exe`를 실행합니다.
4. 사이드패널 ‘자동 업데이트 최초 연결’에 있는 32자리 확장 ID를 복사합니다.
5. 설치 앱에 ID를 붙여넣고 **현재 브라우저에 등록한 manifest.json이 있는 폴더**를 선택합니다.
6. 사이드패널에서 **보조 프로그램 연결 / 자동 적용 켜기**를 누르고 연결 권한을 허용합니다.

설치 앱은 닫아도 됩니다. 매번 실행하거나 ZIP을 다시 풀 필요 없습니다.
개발자 코드 서명/Apple 공증은 아직 없습니다. OS가 실행을 차단하면 출처를 확인하고 OS의 실행 허용 절차를 직접 진행해야 합니다. 보조 프로그램은 Gatekeeper·SmartScreen을 해제하지 않습니다.

## 이후 동작

- 브라우저가 실행 중일 때 매시간 정식 GitHub 릴리즈를 확인합니다. 즉시 확인하려면 ‘지금 업데이트 확인·적용’을 누릅니다.
- 실행 중인 채널, 준비 중인 입력, 미확인 전송, 전용 창의 초안이 있으면 대기합니다. 모두 중지하고 초안을 정리하면 1분 이내 재확인합니다.
- 지정 저장소의 ZIP을 받고 SHA-256·버전·경로·필수 권한을 검증합니다. 이전 설치 폴더를 백업한 뒤 같은 경로에 교체합니다.
- 확장과 비어 있던 전용 Discord 탭을 새로고침합니다. Chrome 저장소의 설정·A/B 차례·진단은 유지합니다. 채널을 자동 재시작하지 않습니다.
- 일반 `main` 빌드 파일이 아닌 **정식 릴리즈**만 적용합니다. 파일 교체 없이 최신 버전이면 그대로 둡니다.

## 폴더와 복구

Git 저장소, 심볼릭 링크/정션 폴더는 대상이 아닙니다. 개발 PC는 배포본을 별도 폴더에 설치하세요. **여러 브라우저·프로필에서 한 폴더를 공유하는 설치는 지원하지 않습니다.** 다른 브라우저의 발송 상태까지 확인할 수 없으므로 별도 폴더와 ID로 연결하세요.

이전 파일은 설치 폴더 옆 `.dico-previous-*` 폴더에 보관합니다. 정상 작동을 확인한 뒤 필요 없는 백업을 직접 지울 수 있습니다. 자동 삭제하지 않습니다.
Mac은 파일시스템의 원자적 폴더 교환을 사용합니다. Windows는 교체 실패 시 기존 폴더를 복원하며, 교체 중 강제 종료·전원 손실 시 보조 설치 EXE를 다시 실행하면 저장된 복구 기록을 처리합니다. 실패 상태에서 채널을 다시 시작하지 말고 복구 완료를 확인하세요.

## 해제

사이드패널에서 자동 적용 체크를 끄면 자동 파일 교체가 중지됩니다. 보조 프로그램은 별도 상주 서비스가 아닙니다.
완전히 제거하려면 브라우저를 종료한 뒤 다음 전용 파일만 제거합니다. 확장 설치 폴더나 Chrome 설정 저장소는 지우지 마세요.

- Mac: `~/Library/Application Support/DicoUpdater` 및 Chrome/Brave의 `NativeMessagingHosts/com.dico.updater.json`.
- Windows: `%LOCALAPPDATA%\DicoUpdater` 및 HKCU의 `Software\Google\Chrome\NativeMessagingHosts\com.dico.updater`, `Software\BraveSoftware\Brave-Browser\NativeMessagingHosts\com.dico.updater` 등록.

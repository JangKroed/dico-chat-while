# 브라우저 간 순환 발송 설정

각 브라우저에서 같은 Discord 채팅방에 A 계정 → B 계정 → C 계정 순으로 공지를 보내는 선택 기능입니다. 기존 문구 A/B 교대와 별개로 계정 차례를 관리합니다. Node.js 20 이상이 필요하며 npm 패키지 설치는 필요 없습니다.

## 1. 조정기 준비

확장 배포 ZIP을 풀면 `coordinator` 폴더도 포함되어 있습니다. 터미널에서 해당 폴더의 상위 경로로 이동합니다. 개발 저장소에서도 같은 명령을 사용할 수 있습니다.

```sh
mkdir -p "$HOME/.dico-coordinator"
cp coordinator/config.example.json "$HOME/.dico-coordinator/config.json"
```

홈 폴더의 `.dico-coordinator/config.json`에서 다음 값을 실제 값으로 수정합니다. 설정·상태는 자동 업데이트로 교체되는 확장 설치 폴더 밖에 보관합니다.

- `notice`: 사이드패널에 입력할 그룹 이름입니다.
- `members`: 원하는 발송 순서대로 Discord 계정의 사용자 ID를 넣습니다. 계정 별명이 아닙니다.
- `channelId`: 세 계정이 공지를 게시할 동일한 Discord 채팅방의 ID입니다.
- `gapSeconds`: 이전 계정의 게시 확인을 조정기가 받은 뒤 다음 계정을 허용하기까지의 최소 간격입니다.

아래 명령으로 토큰을 만들고 실행합니다. 토큰 출력값을 각 브라우저의 연결 토큰에 입력합니다. 이 토큰은 Discord 토큰이 아닙니다.

```sh
export DICO_COORDINATOR_TOKEN="$(node -e 'process.stdout.write(require("node:crypto").randomBytes(32).toString("hex"))')"
printf '%s\n' "$DICO_COORDINATOR_TOKEN"
node coordinator/server.js "$HOME/.dico-coordinator/config.json"
```

같은 컴퓨터의 서로 다른 브라우저는 모두 `http://127.0.0.1:43127`로 연결합니다. 상태는 홈 폴더의 `.dico-coordinator`에 저장됩니다. 재실행할 때 같은 설정 파일과 상태 폴더를 사용하세요. 별도 경로는 세 번째 실행 인자나 `DICO_COORDINATOR_STATE_DIR` 환경 변수로 지정할 수 있습니다. 토큰을 새로 만들었다면 모든 브라우저의 토큰도 갱신해야 합니다. 자동 시작 서비스 설치는 포함되지 않으며 터미널을 닫으면 조정기도 종료됩니다.

Mac mini 등 다른 컴퓨터를 조정기로 쓰려면 그 컴퓨터에서 위 명령을 실행하고 `DICO_COORDINATOR_HOST`를 내부망 IP로 지정합니다. 브라우저에서는 해당 IP를 입력합니다. HTTP는 신뢰하는 내부망에서만 사용하고 외부로 포트포워딩하지 마세요. 외부망 연결에는 HTTPS 프록시를 사용해야 합니다.

```sh
export DICO_COORDINATOR_HOST=192.168.0.10
node coordinator/server.js "$HOME/.dico-coordinator/config.json"
```

## 2. 브라우저별 설정

1. 모든 계정의 기존 자동 전송을 중지하고 미확인 전송이 있다면 실제 게시 여부를 확인합니다.
2. 버전 0.3.0 이상 확장 프로그램을 새로고침하고 기존 Discord 전송용 탭도 새로고침합니다.
3. 각 브라우저에서 해당 계정으로 로그인하고 같은 채팅방을 연결합니다.
4. 채널 설정의 **내 Discord 사용자 ID**에 해당 계정 ID를 입력하고 **전송 결과 확인 생략**을 끕니다.
5. **여러 브라우저 순환 발송**을 열어 기능을 켭니다. 같은 조정기 주소·토큰·그룹 이름을 입력합니다.
6. 저장 시 선택한 조정기 주소에 접근하는 브라우저 권한을 허용합니다. 그 주소에만 권한을 요청합니다.
7. 세 브라우저 모두 시작합니다. 시작 버튼을 누른 순서와 무관하게 서버 `members`의 첫 계정부터 차례를 따릅니다.

예: 계정별 주기 60초, 그룹 간격 20초이면 A 게시 확인 → 최소 20초 뒤 B → 최소 20초 뒤 C → A 순서로 진행합니다. 예약 폴링은 최소 30초 간격이므로 정확히 20초마다 보내지는 않습니다. 브라우저 지연, 각 계정의 전송 주기, 슬로우 모드가 있으면 실제 간격은 더 길어집니다. 순서를 유지하는 기능이며 정확한 초 단위 동시 예약 기능은 아닙니다.

로그인 계정은 화면의 사용자 패널 아바타 ID로도 대조합니다. 기본 아바타 또는 Discord UI 변경 등으로 ID가 보이지 않으면 발송을 차단합니다. 사용자 ID만 수동 입력해서 이 검사를 우회하지 않습니다. 일반 계정별 발송 모드는 기존과 같습니다.

토큰과 브라우저 연결 ID는 Discord 탭, 진단 파일, 설정 백업에 전달하지 않습니다. 백업 복원 후에는 조정기를 다시 연결해야 하며, 연결 없이 자동으로 단독 모드로 시작하지 않습니다.

## 3. 그룹이 기다리거나 멈춘 경우

- 다른 계정의 차례라면 정상 대기입니다. 다음 계정이 시작되지 않았거나 슬로우 모드 대기 중이면 전체 순환이 기다립니다.
- 조정기 연결/허가 응답 유실 또는 발송 결과 미확인 시 해당 브라우저가 중지됩니다. 허가는 자동 만료되지 않고 다음 계정도 추월하지 않습니다.
- 이미 게시된 발송의 완료 보고만 실패했다면 **발송 완료**를 선택합니다. 같은 완료 보고를 여러 번 보내도 차례는 한 번만 넘어갑니다.
- **미발송**은 이전 요청이 실행 중이지 않고 메시지가 실제 게시되지 않은 것을 확인한 후 선택하세요. 필요하면 해당 전송용 탭을 닫아 지연된 Enter를 막은 뒤 게시 기록을 확인하세요. 같은 계정 차례가 유지됩니다.
- 한 번 발송 완료로 기록한 결과를 미발송으로 바꿀 수 없습니다.
- 같은 멤버를 다른 브라우저나 다른 채널 설정에서 시작하면 연결 충돌로 차단합니다. 브라우저 프로필 전체를 복제하지 마세요.

중앙 상태 조회는 인증이 필요합니다.

```sh
curl --fail -H "Authorization: Bearer $DICO_COORDINATOR_TOKEN" http://127.0.0.1:43127/status
```

상태 파일은 임의로 지우거나 편집하지 마세요. 삭제하면 발송 중인 허가와 사용 이력이 사라져 중복/순서 역전 위험이 생깁니다. 그룹의 멤버/순서/간격을 바꿔도 기존 상태와 다르면 실행을 거부합니다. 변경하려면 모든 브라우저를 중지하고 미확인 전송을 해소한 뒤 조정기를 종료하고 기존 상태 폴더를 백업하여 새 상태 폴더로 명시적으로 시작하세요. 모든 브라우저를 다시 시작할 때 새 순환의 첫 계정부터 진행합니다.

강제 종료 후 `coordinator.lock`이 남으면 조정기가 이미 실행 중인지 먼저 확인하세요. 모든 조정기 프로세스가 종료된 것을 확인한 뒤 잠금 파일만 제거하고 같은 `state.json`으로 실행합니다. 잠금 파일이 있을 때 자동으로 빼앗지 않습니다.

실제 Discord 발송과 브라우저 권한 UI는 사용 환경에서 최종 확인해야 합니다. 테스트는 가상 발송과 저장/복구, HTTP 처리, DOM 재현을 사용하며 실제 계정에 메시지를 보내지 않습니다.
